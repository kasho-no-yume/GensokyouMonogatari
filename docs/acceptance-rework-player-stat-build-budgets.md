# 验收步骤：rework-player-stat-build-budgets

> 变更：弹幕核核阶重做（design D7）+ 属性/预算重做。本文只覆盖**游戏内实机项**；
> 代码侧佐证（公式单测、`core-tier-ladder.md`、全量 build、`openspec validate`）见 change 的 HANDOFF §9。
> **所有命令都需要 `permission 2`（作弊/OP）。建议用独立存档。**
>
> 每测一项**先记录再改设置**；任何一项对不上，绝不要先调数值——把现象记下来再问。
> `/gs_test player N` 每次都会发一把新的千机核心（武器+三个核），背包满了旧的会掉地上——注意。

| 检查 | 通过标准 |

| 强度 | spirit_power 生效值 = 6523 |
| 护壁 | danmaku_reduce 生效值对应护壁 ≈ log2(56×10⁴/60) ≈ **13.19** |

## 1. 弹幕核核阶（本 change 的核心，逐项过）

**建议用一阶 BOSS 做**——五阶每弹即死，无法稳定测量。用 `infinite` 排除灵力干扰。

**准备**：

```
/gs_test reset
/gs_test player 1 infinite          # 标准一阶：spirit_power=1、满池 1000（无限补满）
/gs_test boss 1 min                # 一阶测试 BOSS（若血条掉得太快看不清，换 max 版：HP 更厚）
```

**1.1 等级核不再增伤**（同一颗核，只换武器等级核）
- 武器等级槽里装 `/give @p gensokyou:weapon_core_lv1`、`weapon_core_lv2`、`weapon_core_lv3` 后
  玩家属性不体现任何差别；打同一 BOSS、看击杀时间/血条下降速度：
  | 配置（球核不变） | 预期 |
  |---|---|
  | Lv1 / Lv2 / Lv3 | **击杀时间一致**（核阶 ×1，等级核不再提供 ×2/×4） |

**1.2 等级闸门仍然生效**
- Lv1 武器尝试装 T2 核（灵符/激光机枪）→ **装不上**，灰显提示需要 Lv2。
- Lv2 武器尝试装 T3 核（激光炮）→ **装不上**，提示需要 Lv3。
- Lv1 武器装 T1 核 → 正常装入、可射击。

**1.3 同武器换核步进 = ×2/阶**（核心验收）
- 固定用同一 BOSS，依次三次配置（每次 `/gs_test boss 1 min` 重新召唤），记录 `t1 / t2 / t3`：
  1. **球核（T1×1）** → 基准 DPS 5.0×强度 → 击杀时间 t1
  2. **换 Lv2 武器等级核**，装入 **灵符（T2×2）** → 击杀时间应约 **0.45 × t1**（灵符 DPS 11.0）
  3. **换 Lv3 武器等级核**，装入 **激光炮（T3×4）** → 击杀时间应约 **0.16 × t1**（激光炮 DPS 32.0；站桩射，拉好距离保证命中）

| 配置 | 弹核倍率 | DPS（含核阶） | 预期击杀时间 | 判定 |
|---|---|---|---|---|
| 球核 T1（Lv1 武器） | ×1 | 5.0 | t1 | 基准 |
| 灵符 T2（换 Lv2） | ×2 | 11.0 | ≈ 0.45 t1 | 与 t1 比约 2.2× 快 |
| 激光炮 T3（换 Lv3） | ×4 | 32.0 | ≈ 0.16 t1 | 与 t1 比约 6.4× 快 |

> 允许 Aiming/命中损失，偏差 > 30% 才算异常；要点是 **T3 显著强于 T2 显著强于 T1** 且大约符合 ×2 梯度。

**1.4 低核在高阶武器 ≠ 满配**
- Lv3 武器 + 球核（T1）：单发伤害 ≈ 激光炮的 **1/6.4**。使用低核在五阶打不动 BOSS 是设计目标，不是 bug。

**1.5 tooltip 核验（客户端、肉眼）**
- 悬浮每颗弹核：应看到 **「伤害倍率」** 一行（**已含核阶步进的单一数值**，蓝色）：麟弹 ×0.40、单发玉 ×2.00、灵符 ×8.80、激光炮 ×8（每脉冲）；其下仍是「攻击间隔 / 单发耗灵 / 有效 DPS（亦为合计值，如灵符 11.00、激光炮 32.00）」等。
- 悬浮武器：第一行仍为弹核名，不变。
- 全场不应出现任何「武器等级倍率 +X%」字样，也不应出现独立的「核阶倍率」行。

**1.6 指导书核验（客户端、肉眼）**
- 指导书 → 「武器系统」→ 第三页：有一阶 ×1 / 二阶 ×2 / 三阶 ×4 与「武器等级核只是装配闸门、不放大低阶核」的说明。

## 2. 存档/死亡兼容（2.4 验收）

**准备**：`/gs_test player 3`（**非 infinite**；标准三阶满血满池）。

1. 记录 `/gs_probe spirit player=<自己>`（max=100000、tier=3、pool 份额存证）。
2. 记下 `/gs_attributes show` 的贡献与生效值。
3. **死亡一次**（让测试 BOSS 打死你，或直接 `/kill @s`；死亡掉线同理）。
4. 重登进游戏后：
   - `/gs_probe spirit player=<自己>` → 预期 **current=0、tier=3、max=100000**、灵力强度/台账份额均在；
   - `/gs_attributes show` → 贡献组保留，仅当前灵力与进位清零。
5. 退出存档再进 → 同上（幂等，不补条、不增额）。
6. `/gs_test reset` → `/gs_probe spirit` → 回凡人态（0/0/0）。

| 检查 | 预期 |
|---|---|
| 死亡后 current | 0（max 不变） |
| 死亡后 tier / 台账 / 强度 | 全部保留 |
| 重登再进 | 幂等 |
| `/gs_test reset` | 完全回凡人 |

## 3. 一/三/五阶生存实测（5.4 验收，需实机）

> 全命中理论口径的校准窗口：1 阶 2~5 分；3 阶 5~12 分；5 阶 15~20 分。极端流派可例外，但必须记录幅度与原因。
> 3 阶 / 5 阶的弹伤按「参考 EHP / 挨弹数」标定——**3、5 阶每弹都是重伤害，几乎等于弹幕地狱**，请按弹幕规避打法预期；
> 允许很多次死亡重来（BOSS 不随玩家复活而消失）；**记录死亡次数**，不在此判失败。

每阶执行：

```
/gs_test reset
/gs_test player N          # 非 infinite，标准配装（球核 + 对应 Lv + 对应 T 增幅核）
/gs_test boss N min        # HP = 参考 DPS × 120s；弹伤 = 参考 EHP / 10
```

| 记录项 | 1 阶 | 3 阶 | 5 阶 |
|---|---|---|---|
| 召唤时聊天输出 HP / 弹伤 | | | |
| 击杀用时 | | | |
| 死亡次数 | | | |
| 无补给挨弹次数 | | | |
| 与校准窗口差距（短/超） | | | |

判定：

| 情形 | 结论 |
|---|---|
| 一阶 2~5 分钟内击杀 | 通过 |
| 一阶灵力/装备不足以完成击杀 | **不通过** |
| 3 或 5 阶远超校准窗口（如三倍） | 记录，需与校准审核一起裁量 |

## 4. 回灵/汲取（3.3 验收）

打 `/gs_test boss 1 min` 或 5 min，把灵力池打见底：

- **回灵**：池按 0.12%/s 恢复（1 阶 ≈ 1.2/s、3 阶 ≈ 120/s、5 阶 ≈ 12000/s）；每整格才入账，不出现超额跳变。
- **汲取**：**主武器弹幕**命中才回灵（符卡弹幕——冰锥/环绕玉/狐、任何符卡——不汲取）；速度上限 0.03%/s（1 阶 ≤ 0.3/s、5 阶 ≤ 3000/s）；多打不会加倍。满池汲取/回灵都是 0 增量。
- 停手 60 秒后 `/gs_probe spirit player=<自己>` 对比停手前：城乡增长 ≈ 0.12% × 60 = 7.2%（1 阶 ≈ 72）。

| 检查 | 通过标准 |
|---|---|
| 回灵速率 | ≈ 池 ×0.12%/s，不乱跳、不出现整格外增额 |
| 汲取来源 | 仅主武器；符卡不加 |
| 汲取上限 | ≤ 池 ×0.03%/s |

## 5. 旧核兼容（迁移验收）

- 用改动前存档进游戏（若有）：旧弹幕核还能装、还能用，**按新规则结算**（低核惩罚对旧核生效；等级核不再拉高低核伤害）。
- 旧核无版本字段，不自动重掷/重roll，词条保持原样。
- 旧增幅核 legacy 语义不变：只读 `spell_amp`（老治疗/召唤消费者），与分类增幅平加后各自封顶；武器/防御侧不因此多拿收益。
- 灵力成本按**阶级标准**收，不随池涨价；低阶核在高阶也纳入收支（打五阶不会永远满池）。

## 6. 攻速真实交付（3.1 验收）

校准目标：长按输出的实际频率 = 基准 × (1 + 攻速)；+300% 攻速 = 4 倍频率，且高攻速下**不少发、不免费发**。
**麟弹**（10 发/秒）是检验高频的最佳对象；无限灵力排除资源干扰。

**准备**：

```
/gs_test player 5 infinite
/gs_attributes add attack_rate_pct 0        # 同命令可复位为 0
/gs_test boss 5 min                         # 聊天输出 HP / 弹伤
```

分别把 `attack_rate_pct` 设为 `0` / `0.6` / `1.6` / `3.0`，每种各打同一 BOSS 一次，记击杀时间：

| 攻速 | 预期相对 DPS | 预期击杀时间 | 实测 t |
|---|---|---|---|
| 0%（基准） | ×1.0 | 100% | |
| +60%（一阶上限） | ×1.6 | ≈ 0.63 × t(0) | |
| +160%（三阶上限） | ×2.6 | ≈ 0.38 × t(0) | |
| +300%（五阶上限） | ×4.0 | ≈ 0.25 × t(0) | |

判定：

| 检查 | 通过标准 |
|---|---|
| 高攻速结算 | t(+300%) ≈ 0.25 × t(0)，允许命中波动 ±20%；>±30% 算失败 |
| 不漏发 | 击杀所需"弹数"不异常偏少（击杀时间与频率成比例，而不是持平） |
| 不白嫖 | 连续射击下不产生无灵力仍成弹的情况（infinite 下本条不构成阻塞，记录即可） |
| 高载 | +300% 下帧率/卡顿/断连是否明显；记录现象，不判失败但记账 |
| 点射一致 | 右键点火与长按节奏一致，无"点一下多两发" |

> 如果出现明显实体堆积（同一时刻上千弹幕）或网络卡顿，记录现象——实体/网络成本需另行评估；本节不自动判失败。

## 7. 花园去重 + 道具形态（4.6 验收）

**已学形态——双场不翻倍**：

```
/gs_learn healing_garden        # 学习命令（过渡用；正式学卡走委托任务）
/gs_test player 1 infinite
/gs_test boss 1 min            # 先让 BOSS 打你几发，掉一些血
```

1. **一次施放**花园，原地站立 20 秒，记录血条回满所需时间 `t_solo`（或看走到半血用多久）。
2. **再施放一次**花园（在自身原位再放第二个），原地再站 20 秒，记录 `t_dual`。
3. 判定：

| 检查 | 通过标准 |
|---|---|
| 去重生效 | `t_dual` ≈ `t_solo`（不会因双场叠加更快回满，也不会更慢） |
| 强场优先 | 强场到期后，较弱场应开始恢复（不会出现"强场消失后血全都不回"） |
| 不治疗满血 | 满血时花园无可见恢复（不溢出刷新） |

> 花园的治疗按世界 gameTime 的 tick 网格触发，同一目标同一 tick 只有最强场生效——若 `t_dual` 明显快于 `t_solo`，说明去重未生效，记账。

**道具形态——不读玩家属性**：

```
/give @p gensokyou:healing_garden
```

右键使用：

| 检查 | 通过标准 |
|---|---|
| 道具固定量 | 恢复量只由道具品质决定，不随玩家属性/增幅核/阶提高变化（连放两次对比） |
| 已学 vs 道具 | 同一品质，道具符卡恢复量**小于**已学形态（已学读取玩家灵力强度） |
| 品质档位 | 若有高品质道具，恢复量明显高于低品质（固定值向上递增） |

> 多人重叠（两个玩家同时在场、治疗互斥与否）需要第二位玩家；第一轮不测，记录为"未测"。
