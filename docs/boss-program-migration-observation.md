## 观察口径

- 记录开发者实际遇到的问题、查阅文件、失败尝试和最终处理，避免把观察者预判算成已发生的问题。
- 区分作者 API 的理解成本、正式宿主接线的维护成本、工具环境问题与历史文档冲突。
- 编译成功不足以证明迁移等价；核对实际数量、时间、目标复制、伤害、跨轮尾弹与清场证据。
- 自动化或模拟测试与实机、生存、真实多人记录分别说明；缺少记录不标为通过。
- 如观察者提供了实现帮助，记录帮助内容，不能把结果描述为完全独立完成。

## 初始文档审查（尚非开发者行为证据）

1. 作者指南 §0、§10 和 skill 顶部将“现有 BOSS 尚未迁移”与“本指南不授权顺手迁移”并列。前者是实现状态，后者是旧任务范围；正式授权迁移时需要清楚地区分。
2. 操作台账头部包含按时间倒序叠加的验收记录，后文仍出现“不能进入迁移”等历史结论。虽然有历史说明，读者仍需跨段判断当前状态。
3. skill 的旧后端部分仍有 Track/Beat、仅单拍 R3 和旧开发清单；顶部已声明适用边界，但完整阅读时有混用风险。
4. change 任务标题仍写“本轮不实施”，而本轮用户已授权执行；排除项仍保留未勾选框，容易被误读为待迁移任务。由迁移开发者在保留用户范围的前提下更新任务口径。

## 开发者行为与验证结果

第一轮返回实现：15卡、2底噪、正式战斗接线、manifest及测试；自报完整build为136 suites / 1077 tests、零失败，strict通过，lang仍有31个既有JEI缺失键。以上为开发者报告，不能据此认定行为等价或实机通过。

观察者初审实际源码发现：

- `YakumoRanPrograms.card3/card7` 的白点名只创建槽0，但说明写成每人6发；目标集合最多5人没有自动展开。这是作者未落实文档已明确说明的多目标规则。
- `card8` 副轨左右各6拍、每拍12成员，代码合计144，说明写72；需要按权威mapping重新核对，不能以说明文字为计数证据。
- 开发者把地面采样、走廊净空、收敛/倾斜方向、轮廓预警及声音等缺作者入口的要求登记为近似并勾选完成。诚实登记差异值得保留，但未获授权的语义降级不满足迁移要求。文档已补充“缺快捷入口不等于可以降级”。
- 未做实机/多人却勾选含这些验收的1.7。报告明确说未执行，没有伪造记录，但完成标记仍过度。
- 开发者报告了`SequenceNode`绝对时间轴跨度、并行句柄校验两个框架阻塞并自行修复；修改仍须补充乱序时间表等测试审查，不能只依赖正式卡编译成功。
- 开发者提出`END_AT_BOUNDARY`与`retain=true`不符。观察者暂不接受为已证实缺陷，要求继续检查调度ownershipEnd和真实跨轮行为。

观察者已续接同一模型会话，要求修正上述实现/验收问题、核对fire调用时间与实际出生时间、核对既有存档旧弹加载策略，并分别报告框架缺陷与自身误用。这属于明确的审查干预；后续成果不能描述为一次独立完成。

当前结论：模型能够产出可构建的接线和内容，并指出入口缺漏，但第一轮未能独立保证契约等价；文档已说明的多目标规则仍被误用。不能把这次结果简单归因为“文档不够详细”。

### 首次正式实机反馈：持续抽搐

### 原因归纳（经实测后的修正）

- 文档问题：历史授权/状态混杂；缺少完整的“战斗中存档→关闭进程→重开→旧弹及预警续行”验收定义；作者入口缺世界采样/真实瞄准等常用链路。
- 框架问题：绝对时间轴/句柄校验/循环生命周期等基础行为存在缺陷；内存checkpoint与正式磁盘持久化之间没有接线；预览独占宿主限制暴露给用户。
- 执行问题：模型多次用近似替代契约，漏掉随机逐拍重采样、重复目标槽、跨轮待出生计划等；声称等价的证据不足。部分问题并非文档没有说，而是未对照旧实现落实。
- 测试问题：不少断言只要求“有弹/有地面光柱/有包络”，没有覆盖逐拍随机性、完整激活数量、真实实体消费NBT和跨进程连续性。总测试数不代表这些关键行为已覆盖。
- 观察者问题：多轮审查仍接受了过早完成标记；两次时间修复依赖理想化模拟、没有实机验证，却让用户反复试错。不能把这些后续失败只归于DeepSeek。

改进应以可执行的交付验收与通用能力为主，文档为入口：明确每种行为的输入/输出、失败条件和完整生命周期，用会失败的端到端测试覆盖，再以实机记录验收。增加更多历史说明或警告本身无法保证作者正确完成。

### 持久化第一版审查

DeepSeek交付版本化二进制ProgramSessionCodec、SavedData、host保存恢复、controller adopt与文件往返测试，自报142 suites / 1112 tests零失败。观察者实际读取日志确认build成功，但代码审查拒绝立即交付：resumed controller未恢复card计数，后续切卡endCard(0)可能遗留旧卡；共享session整体保存包含预览；尚未加载owner在第一tick可能被清；battles map为空并不保证恢复的所有encounter结束；恢复立刻clear磁盘槽带来额外丢失窗口；Save事件与SavedData真实落盘顺序仍需确认。

已续接同一会话要求修复上述实际接线并测试。再次体现“编解码及内存恢复通过”不足以证明“游戏持久化正确”，尤其在保存、加载、恢复后切卡和多owner生命周期之间。

第二版返回后，观察者确认恢复controller身份、预览过滤和SavedData在flush时捕获均已接入，build日志`20261018-174714-build.log`成功；开发者报告143 suites/1118 tests零失败。但进一步读host发现新建BOSS没有attach保存回调（仅恢复分支attach），首次保存仍然失败。观察者直接修复每次persistent bind安装回调，并每tick标脏（只看网络revision会漏纯时间推进）。定向持久化回归另行运行。此问题不属于codec本身，说明仍缺真实host/entity save-restart验证。用户需重启到含持久化实现的版本后重新保存，之前未保存的运行态无法找回。

### 幽灵命中反馈：观察者单人时钟设计缺陷

用户要求停止DeepSeek修改，报告弹幕视觉仍远却已命中。此次观察者独立排查，未委派代理。自由累加实时时钟只有领先上限、没有落后重锚；服务端追赶后可长期落后判伤tick，属于此前观察者修复引入的设计缺陷。
