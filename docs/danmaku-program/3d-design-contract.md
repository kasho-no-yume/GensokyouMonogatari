# 三维符卡设计契约

## 用户确认的设计优先级

1. 限制走位：BOSS 周围半径32格内，飞行玩家不能随意直飞、升降或绕圈而忽略符卡。
2. 驱赶站位：玩家当前所站位置必须持续遭到可信攻击，不能长期站桩。
3. 弹幕艺术：以上机制必须能读、能躲，并呈现有辨识度的图案与节奏。

有效战斗域是球体，不是水平圆盘或朝主目标的锥体。远于32格不作为本契约的主要控制目标。
这些原则覆盖旧规范里“每颗弹都必须朝玩家”“只允许列举的正面几何”等限制；
公共幕面可以通过切断移动路线发挥作用，不必每发都直接瞄准玩家。

## 作者必须交付的设计证据

- 公共约束：分别说明前后、上下、内外圈受到什么限制。边界球壳不等于内部受控。
- 个人驱赶：明确目标采样周期、预警、实际发射、到达时间、有效射程，多人逐人点名。
- 两者配合：玩家离开被锁定的位置后，需要处理什么通路？禁止只堆一套自机狙和无关烟花。
- 解法：说明可用通路及其存续时间；“存在一个缺口”不证明玩家能抵达。
- 几何：视觉尺寸、实际碰撞尺寸、玩家体积分别计算。不能只用弹心距离宣称能过。
- 预算：同时核对单拍、跨轮存活、多人展开、近域密度、渲染遮挡；不得随意放大限制掩盖失败。
- 预览：同源运行器导出，提供玩家视点、自由视点、时间轴、关键拍点与说明。

## 必做的反例检查

1. 在±X/±Y/±Z、8/16/24/32格站桩；不是只测主目标正面。
2. 固定高度、半径、方向、速度绕圈；至少改变高度与初始相位，避免仅针对某条测试路线调参。
3. 持续升降、往返升降、径向往返与背后停留。
4. 1人/5人，查公共幕是否错误复制、个人攻击是否漏槽。
5. 跨循环检查旧弹和预警尾部，不能用突然清场制造长期无压力窗口。
6. 地形、视野外预警、相位切换和高速扫面都必须实机检查。

测试命中一个几何探针仅证明该探针会受威胁，不证明所有路径无逃课，也不证明可躲。
自动化结果、作者推断、用户实机反馈应分开记录，不得把候选方案写成已验证范式。

## 本次失败沉淀

- v2的正面门、翅膀、明暗幕可被飞行绕开：漂亮正视投影不等于空间控制。
- 仅增加弹数或把圆环改成球壳没有自动解决驱赶与内部自由飞行。
- v3初稿的2格栅距，让固定高度绕圈从同一缝隙穿过；必须查移动轨迹与实际碰撞几何。
- 激光端点放在34格处会让32格外圈目标触发生成净距撤批；不能用clearance(0)盖住。
- `MemberProgram.laser` 的布尔参数实际写入 `piercesBlocks`，不能相信参数名clipBlocks；
  外侧向内射入的公共幕需要明确地形策略，并检查穿墙预警是否可读。

## 待用户逐卡反馈的候选经验

露米娅v3用公共移动光条幕+逐人点名验证空间控制。47条栅格、1.7格间距、
实际光束半径0.4格是首轮候选数值，不能直接复制为所有BOSS标准。
大量激光可能遮挡，五卡共享幕面语汇也可能导致辨识度不足；这些需要用户评价后调整。
后续AI应复用检查方法，不应把五张卡机械复制成五套旋转激光。

## 用户逐卡评审记录模板

每轮保留：卡名/版本、出现问题的秒数、玩家距离与高度、移动方式、现象、预期、
修订方案、实际验证结果。若一张卡通过，不顺手重写其他已通过卡。
将反馈归为“空间覆盖”“驱赶”“可解性”“可读性”“艺术性”，但允许一条反馈同时涉及多项。
具体数值只有在对应距离、移动速度和多人条件下获得验证，不能将局部通过推广成通用结论。
