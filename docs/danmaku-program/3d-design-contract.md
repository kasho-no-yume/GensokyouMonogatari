# 三维符卡设计契约

## 目标优先级

1. **空间约束**：在 BOSS 周围半径 32 格的有效战斗域内，不能存在不用读符卡、长期直飞/绕圈/升降即可忽略整张卡的通用解法。
2. **合理驱赶**：持续站桩应有可信压力，但受威胁后必须有时间和空间作出响应。
3. **可读、可躲且有主题**：先看清弹阵和安全路线，再感受符卡意象；不能以“看起来满屏”代替设计。

空间覆盖不等于铺满空间。球壳/环面撞到玩家，不证明球体内部也受控制；某拍没有打中玩家，也不代表那拍没有迫使玩家转位。设计要同时说明公共阵列与个人瞄准如何配合。

## 符卡设计方法

开始写程序之前，先写一页可审阅的**符卡简报**：

1. **意象**：一句话说明这张卡是什么感觉；依据主题选择弹幕语法，不把名称直接当作必须造出的实体物。
2. **主阵列**：一个主要的弹幕几何/运动过程，说明成员从哪里出现、如何展开、之后怎么走。
3. **节奏**：写明预兆、主要攻击、收束/停顿、下一拍怎样改变。点名攻击是某个动作，不是每张卡无差别套用的底噪。
4. **玩家解法**：提供具体可执行的移动选择，并估算弹幕和玩家碰撞体积、反应时间、路线宽度与路线存续时间。只说“有缺口”不够。
5. **空间反例**：交代前后、上下、内外圈、BOSS 背面、贴边的压力来源，以及换区后会遇到的下一项威胁。
6. **视觉身份**：说明玩家如何仅凭阵形、运动和节奏区分本卡；颜色只作辅助，不能是唯一变化。
7. **预算和生命周期**：检查单拍展开、持存时间、跨循环残弹、多人目标、近场密度、渲染遮挡和清卡归属。

**弹幕阵是符卡内容的优先表达方式，不是激光墙的前置装饰。** 球弹、扇簇、开口弧、环/螺旋、离散弹带等，都可按主题选用；激光应因主题或某个清楚的节拍而出现，而非默认铺满战场。特定 BOSS 的具体偏好写在该 BOSS 谱面中，不把露米娅的审美约束冒充全项目通则。

一张卡通常只需一个主图案和一个服务于主图案的辅助动作。若同一符卡要求玩家同时解两套互不相干的密集威胁，先删掉一套或改成先后节拍，不要让读解负担替代难度设计。

## 公平性与弹幕预算

| 检查 | 设计要求 | 说明 |
|---|---|---|
| R1 预警 | 威胁要从玩家可读的位置出现，或先给足够明显的预警 | 绕到背面、出现在视野外的攻击，不能依赖玩家猜测。 |
| R2 可解性 | 密度、速度、碰撞尺寸与同步动作合起来后，仍有可抵达的处理方式 | 平面/空隙截图不证明三维角色能穿过；单点不受击也不证明可玩。 |
| R3 预算 | 核算单次展开和持续/派生峰值，不能只看卡面总弹数或单个拍点 | 多人复制、残弹跨轮、预警出生和近场重叠都要进入账本。 |

没有通用的“改大上限就通过”做法。静态验证不通过时，优先重看阵列几何、时序、发射位置、生命期和实际通路；只在证明确属系统预算错误时才改系统上限。

## 必做的路线反例

### 自动化探针

- ±X/±Y/±Z 方向、多个有效半径的固定站位；测试仅证明该站位会遇到某项威胁。
- 固定高度绕圈：改变半径、方向、初始相位与高度，避免只针对单条预设轨迹。
- 持续/往返升降、径向往返、朝向 BOSS 后方再停留。
- 至少检查一个跨循环窗口，计入旧轮弹体和新一轮预警，不通过卡边界清场伪造安全窗口。
- 1 名与多人目标各测一次；核对个人攻击逐人展开、公共图案不重复复制，以及实际总数。
- 读取真实生成事件、碰撞尺寸和生命周期；不能仅测计划表或视觉轨迹。

探针命中仅表明固定的反例路线不安全，不证明其他路线也无解，更不证明这张卡可以躲。反过来，一个探针没有命中也不自动等于设计失败，要看它能否绕开本卡并长期逃课。

### 预览与实机

- 先用同源运行器看玩家视角、自由视角与关键拍点；核对提示是否被 BOSS、地形、弹幕自身或其他玩家遮挡。
- 在生存模式实测真实 AABB、移动速度、碰撞、地形遮挡、伤害、BOSS 运动和相位切换。创造/旁观模式或无伤几何探针不能代替实机结论。
- 多人时检查每名玩家看到的预警与其目标槽对应，公共弹幕数量不因人数成倍增加。
- 每条试玩反馈记录卡名/版本、时间、位置、高度、路线、人数、发生现象和预期；归类为空间覆盖、驱赶、路线可达、可读性、卡间辨识、预算或主题表达。
- 一轮修订优先只改一个主要维度，再重新跑受影响的检查。一个轨迹通过，只验收那个轨迹和版本，不外推成全卡已通过。

## 设计状态不得混写

每张卡分别标记 **设计中 → 待预览 → 探针通过 → 待实机 → 实机通过**。必须留下对应证据；编译通过、预览导出、静态 lint、路线探针和实际生存试玩是不同结论。若方案只是一份概念简报，要明确写“候选”，不能称“重做完成”。

## 露米娅谱面当前结论

v3 曾用大量长激光幕作主要公共控制，自动化探针确认部分固定路线会遇幕；这不能证明可躲性。用户指出它重复、难以躲避、偏离原符卡意象，故 **v3 作为设计方案退回，不应继续当作露米娅的设计范式**。自动化通过状态仅保留为那几种固定探针的历史结果。

露米娅 v4 设计候选在 [rumia-score.md](rumia-score.md)：四张正式卡名各自使用不同弹幕阵语法，以弹阵为核心；该候选尚未实现、预览或实机验收。其他 BOSS 只复用本契约的审查方法，不机械复制这四种图案。
