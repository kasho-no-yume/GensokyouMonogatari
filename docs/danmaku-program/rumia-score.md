# 露米娅符卡谱面 v4 候选：以弹幕阵表现宵暗

**状态：设计候选，尚未实现、未预览、未做实机可躲性验收。**
本稿取代 v3 的设计建议；当前 `RumiaPrograms.java` 仍是 v3 激光幕方案，不要把此稿写成已上线内容。
四卡名称和顺序沿用露米娅正式牌组；不把「子夜之鸟」增为第五张卡。

## 设计核心

露米娅的主角不是“激光”，而是宵暗：月光成为唯一可见的直线，双翼在无固定中心的夜色中交替，光暗边界呼吸般收放，终局暗球只显露半面。
这些方向取自 `sheet/bossspellcard.xlsx` 的露米娅页；它们是本项目对官方卡名与意象的设计说明，不声称复刻原作弹路。
把这些意象译成**弹幕阵的疏密、开合、绕行和负空间**，而不是一圈会伤人的暗墙。

- 主体使用球弹等可读的离散弹幕阵；光线可以做一小段提示或点睛，不承担整张卡的封路工作。
- 每张卡只保留一个主图案和一个辅助动作，靠弹阵语法与节奏区分；不靠换色重复同一面激光幕。
- 一轮有清楚的「提示 → 弹阵展开/出射 → 可行动窗口 → 变位再来」节奏。点名只作为弹阵中的压力拍，不重复套成五卡共同的自动追踪背景音。
- 有威胁不等于全空间封死。给出的空隙必须让玩家体积能通过，并能在预警和弹速所允许的时间内到达。
- 本稿描述的是创意与玩家决策，不是已验证的弹数、伤害或 Java 操作。具体数量要在预览和可躲性测试后定。

## 四张卡的独立签名

| 卡 | 视觉动词 | 主弹幕阵候选 | 玩家要读出的决策 | 不要退化成 |
|---|---|---|---|---|
| 月符「月光射线」 | **唯一的光 / 揭示** | 场面先留暗，再用一条极醒目但短促、细窄的月光直线标出方向或露米娅所在；随后以少量珠弹沿该方向排成断续直线，分拍掠过。直线是意象，不是满屏平行光束。光出现也让露米娅短暂暴露，成为她的破绽。 | 读懂唯一的直线后，垂直横切弹列；利用“光出现”的节拍找移动窗口，并留意露米娅显形的短暂时机。 | 多排常驻激光幕，或让“射线”沦为换皮的密集弹墙。 |
| 夜符「夜鸟」 | **无定中心 / 振翼** | 紫、粉羽状扇簇从错开的发射位置交替展开，弹簇本身向外掠行，不围绕固定鸟笼中心；先后拍翼形成两段可读的弧线。少量翼尖珠弹点名补压。 | 跟随左右拍翼节奏横移，穿过刚收起的一翼留下的空处，不要追着某个固定中心绕圈。 | 两道固定“翅膀墙”、持续追踪的羽弹雨，或一轮轮相同方向的自机狙。 |
| 暗符「境界线」 | **划界 / 呼吸** | 两到三道由慢速珠弹组成的开口弧线，分拍向内收、短暂停驻、再向外放；下一轮改变弧线倾角与缺口方位。清楚表现“界线”与“尚未闭合的缝”，不要做成实体结界。 | 选择留在界内还是穿过正在移动的开口；换区时仍需处理下一拍弹阵。 | 六面正交激光幕，或没有真实通路的闭合弹幕围笼。 |
| 暗符「月之暗面」 | **暗球 / 半面显现** | 一颗缓慢绕行的暗色球心表现月背；球心周围只用少数弧形珠弹标出“可见的一半”，随球体转动渐次遮去或显露，末段从月缘弹出离散弹簇。球体本身是意象，不暗设看不见的伤害体积。 | 看清哪半边正显露、边缘弹簇将从哪里出现，再沿可见月缘的空档切出。 | 三层旋转激光网、全场暗判定，或一口气铺满空间的终符弹幕。 |

表中的弹型与顺序仅是候选。特别是“射线”“划界”等名称，不要求字面复刻；最终图案要让人先读作一张可玩的符卡，再读出其主题。

## 统一节奏与差异边界

可先用同一个**节拍骨架**验证四张卡：短提示、有限弹阵、短呼吸、改变相位后再来。骨架只统一阅读负担，不统一图案、弹数、射速或角度。某张卡若需要更长预警或更稀疏的阵，按它的构图来定。

每张卡开始落地前写清：

1. **意象一句话**：观众一眼应该感到什么，不写“更难/更多弹”。
2. **主图案与签名动作**：弹幕从哪来、如何成阵、怎么运动；辅助效果只服务主意象。
3. **玩家选择**：看到提示后至少有一个具体可执行的移动方案；说明该路会保持多久、下一拍如何改变它。
4. **空间反例**：检查前后、上下、内外圈，以及绕圈、升降、贴边和背后停留；说明公共阵列和个人点名如何配合。
5. **可通过性与预算**：以弹体和玩家 AABB 计算实际通路；计入预警尾部、跨轮残弹、多人逐人展开、近场密度和画面遮挡。

四卡的目标差异是：**唯一月光下的断续直线弹列 / 无定中心的交替双翼扇簇 / 收放的开口弧线 / 绕行的暗球与半面月缘弹阵**。
如果缩小看仍像同一张栅格墙，只换了颜色或方向，就还没有完成主题设计。

## 设计到验收的状态

| 阶段 | 交付 | 状态判定 |
|---|---|---|
| 主题简报 | 一句意象、主图案、玩家决策、卡间差异 | **设计中**；没有具体构图不得开始堆操作。 |
| 几何草图 | 时间轴、弹阵示意、预警、数量级、可走路线 | **待预览**；数值是待验证的提案，不是平衡结论。 |
| 同源预览 | 玩家视角与自由视角、循环边界、关键拍点、公共/个人弹幕分层 | **待检查**；只看静帧不算验收。 |
| 自动化反例 | R1/R2/R3、六向站位、多初相位绕圈、升降/径向移动、循环尾弹、1/5 人展开 | **探针通过**只表示这些固定反例被覆盖，不表示所有解法都公平。 |
| 生存试玩 | 至少检查预警可读、通路可达、受击归因、地形与多人视线/遮挡 | **试玩通过/失败**；记录具体位置、时间和路线，不用自动化结果代替。 |
| 收敛 | 按问题类别一次改动一个主要变量，重新跑相关检查 | 只有预览、自动化和实机证据分别记录后，才可标为已验收。 |

问题分类：**空间覆盖、被迫驱赶、路线可达、视觉可读、卡间辨识、预算/多人、主题表达**。一条反馈可以涉及多项。
若固定探针都能受威胁但玩家说“完全躲不了”，下一步应先找出玩家实际路线和可达窗口；不要再加弹、加墙或把预算上限调大。

## 当前实现与下一步

- v3 的激光幕程序及 `RumiaCoverageTest` 仍在代码中；固定绕圈/升降探针“能遇到公共幕”不等于玩家不能躲，也不证明弹幕有辨识度。
- 本 v4 文稿不是 Java 改动，没有声称已有四张新卡或已通过预览/生存试玩。
- 下一步：确认四张意象和主要路线 → 按现有作者指南检查操作能否表达 → 制作独立预览候选 → 做路线/碰撞/预算测试 → 逐卡试玩。缺少的通用原语先另行确认，不用激光墙替代。
