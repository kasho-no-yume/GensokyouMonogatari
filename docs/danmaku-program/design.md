现状核查：`TrackRunner` 只在服务端运行；`FormationFrame` 参数复制进每弹；`DanmakuMotionState.PARAM_COUNT=67`；曲射/段式/编队在 `tickDanmaku` 多处改写速度；锁轴键含 trackIndex；预警未共享完整几何计划；安全拒绝只跳过当前拍；快照目标 ID 未成为后续复制依据。现行条款还有「一轨一帧」「只停发不清旧弹」「多拍一次性必须拒绝」等历史实现限制。

这些限制属于本次替换对象。数学、伤害规则和视觉资源有可复用价值；不能把任意旧注释当正确性证据。

## Goals / Non-Goals

**Goals:**

1. 内容通过类型化原子和组合器表达；自定义图案只实现局部生成/求值，不接触网络、世界和生命周期管理。
2. 同一组可以包含不同弹种、多个批次、子组和成员选择器；跨轨共享帧、跨轮残留是显式语义。
3. 同一服务器时刻与相同完整输入得到相同运动状态，支持直接跳转求值、晚加入与事件迟到恢复。
4. 共享输入按组发送；正常确定性飞行无逐弹位置流。权威判伤、取消、目标采样仍由服务端完成。
5. 用现有全部内容、组合探针与可重复性能测量证明可用；不降低图案复杂度来绕过框架限制。

**Non-Goals:**

- 通用脚本 VM、任意用户上传代码、可视化编辑器、外部 JSON 几何语言。
- 连续依赖玩家实时位置却完全零事件、所有网络条件下零视觉误差的承诺。
- 通用刚体物理、弹弹碰撞、任意无限递归派生、所有空间通路的静态证明。
- 玩家武器/技能/妖精弹体的全量替换；此次只迁移 BOSS 及其预览入口。
- 改伤害公式、重新调全部平衡、改变八云蓝是否逐卡必演的血量推进规则。

## Decisions

### D1 类型化程序 + 有界中间表示

作者使用 Java builder 组合 `ProgramNode`。编译器产生不可变 `ProgramDefinition`：类型化操作描述、常量/曲线表、稳定节点 ID、依赖表、预算上界与 program hash。运行时解释注册的操作，不解释任意 Java 回调。

每种操作注册 `typeId/schemaVersion/codec/validator/evaluator/bounds`。几何生成器与轨迹类型走各自注册表，网络统一封套不随新增操作改变；新增操作仍要求双端安装对应实现并协商兼容，不能宣称未知客户端自动理解新语义。

`Track` 降为 visual lane（颜色、职责、倍率、调试标签）。组、帧、目标集、运动均通过显式句柄连接，可以跨 lane；不再用轨道下标充当共享状态作用域。

备选：继续扩展 Beat + 全字段 record。拒绝：组合能力和单位已经被字段复用限制。备选：任意逐 tick lambda。拒绝：无法静态预算、序列化、重建与检查世界依赖。

### D2 状态层次、身份与时间

```text
Encounter (owner UUID, dimension, encounterEpoch)
 ├─ Background program（默认攻击，独立时钟）
 └─ CardInstance (cardSerial, programHash, startServerTick)
     ├─ Cycle (cycleIndex)
     ├─ Frame / TargetSnapshot / WorldSample handles
     └─ GroupInstance (nodeId, occurrence, targetSlot)
         ├─ EmissionBatch (batchOrdinal)
         ├─ ChildGroup ...
         └─ Member (stable memberIndex, birthTick, alive flag)
```

- owner 使用 UUID；会话 epoch 区分同一 BOSS 重启前后。组 ID 在会话内单调分配，事件与快照携带 epoch。成员用 `(groupId,batchOrdinal,memberIndex)`；不以可复用实体 ID 当身份。
- CardTime、CycleTime、GroupTime、MemberAge 是不同类型的时间域，操作必须声明使用哪一个。统一换算至维度 server gameTime；渲染支持 fractional tick，判伤用整数 tick 区间。
- 两拍共享世界坐标帧不代表共享成员年龄。形成一个逐颗点亮的环时，显式选 group time；多个独立花朵共享母程序时，各自选 group/member birth time。
- 同 tick 执行顺序固定：权威外部终止/目标失效 → 读取边界解析姿态、捕获输入 → 段结束触发/准备/准入（含原子替换）→ 发射及状态门提交 → 求区间轨迹 → 碰撞与派生决策 → 发布事件/检查点。节点有稳定拓扑序；零时长依赖环构建时拒绝。分裂消耗母弹后只对子代做该区间碰撞；区间内碰撞新产生的派生请求最早下个整数tick生效，首版不做同tick递归碰撞链。
- 区间统一 `[start,end)`；成员在 birthTick 出现于 age=0。tick S 的碰撞覆盖 S→S+1，先应用 S 生效的伤害门；到截止 tick 不再造成伤害。同 tick 出生/结束的结果由此唯一确定。

### D3 坐标层与运动通道

一般位置定义为：`world_i(t) = FrameSnapshot × GroupTransform(t) × Local_i(t)`；允许有限层级父组变换。`Local_i` 含图案生成的初始坐标与可选成员路径，激光同时求位置和方向。方阵整体转弯只改变组平移路径，不自动旋转方阵平面；如要随切线转面，必须显式 `OrientAlongPath`。

一个作用域的平移、旋转、缩放、朝向、可见性、判伤门、寿命分别是独立通道。顺序段按时间拼接；并行写不同通道合法；并行写同一通道必须通过显式 `ComposeTransform/AddOffset/MultiplyScale` 指定次序，否则编译拒绝。禁止最后写入者获胜。

路径首批提供 `Hold/Linear/SpeedCurve/Arc/Segments`，变换提供 `Rotate/Orbit/ScaleCurve/Breathe`。速度曲线用闭式积分；恒速圆弧使用确定性数学；段边界缓存前缀终态，直接求值复杂度与段数有关、与弹龄无关。相对转向以已知段起态求绝对结果，不禁止相对描述。

数学采用 Java 21 严格浮点语义与统一 `StrictMath`/固定运算次序；采样输入先经过同一 wire 量化再同时供两端使用。同参数同时间核测试要求逐位一致；时钟/网络量化导致的观测误差另行计量。不再用「含 sin/cos 就不能做」限制所有路径，但新增数学实现必须通过跨 JVM/平台 fixture。

`Detach` 在指定 tick 取解析世界位置与切向速度，显式选继承速度或指定新方向。之后独立世界路径不再读取父组变换；取消归属仍保留原卡/父组链。花瓣爆散是 Select(petals)+Detach+RadialDirection+Linear；中心弹是 Select(core)+SampleTarget+AimAtPoint+Linear。

### D4 新 BOSS 数据运行时，不使用每弹网络实体

最终后端选用每维度 `DanmakuWorldRuntime` 的紧凑组/成员存储，服务器批量求值和碰撞，客户端共享同一求值库并批量渲染。逻辑组不是 Minecraft Entity。此选择避免一组仍产生 N 次 AddEntity/SetEntityData/配对快照；若永久保留该载体，组级低带宽收益会被原版追踪成本限制。

碰撞复用 `DanmakuHitScan` 的规则，抽出输入为几何段/碰撞体、owner、过滤器的纯判据与服务端适配；伤害和擦弹接口增加 `DanmakuHitContext`，不要求每枚弹都有实体身份。保留 `danmaku_damage × laneScale × memberScale`，在命中时读存活 owner 的属性；owner 消失则清理攻击。球弹用扫掠，静止弹用相交；激光用受限射线及既有命中节流。弯曲轨迹每 tick 以误差受限子段扫掠，不能用长弦跳过障碍；默认误差≤0.02格，最多8子段，超限声明在构建期拒绝或降低允许运动参数。

物理半径不受闪亮视觉缩放影响。半径随时间变化必须显式配置碰撞通道。球弹撞块消解、穿墙球弹和激光裁剪分别声明；新运动不能顺带改变命中类型。

派生子弹统一进入调度器和预算，不在成员 tick 内直接创建；父弹提前被移除，则其尚未执行的尾珠发射被取消，已经生成的尾珠按声明存活。

中间阶段可以有 EntityBackend 适配器用于比对，但不得作为最终完成状态。非 BOSS 实体继续走旧路径，两个后端不能同时为同一攻击判伤。

### D5 发射计划是预警与真弹的同一输入

`PrepareEmission` 根据已采样帧、目标和种子生成不可变 `EmissionPlan`：真实源点、方向、成员参数、图案 ID、发射时刻。预警直接绘制该 plan 的源/轮廓/未来射线；真弹消费同一 plan。随机几何使用无状态索引随机函数，不能两次取世界 RNG。

有提前预警的 plan 可以在预警时下发；实际出生仍需要服务端 `CommitBatch` 批准安全与预算。客户端可以预先显示无害预警，不得在等待批准期间自行当成已发射。批准晚到按出生时刻直接求当前位置，并记录 late-birth；不能把客户端出生时刻改成收包时刻。

安全判据是策略，不是给全部旧卡强加 6 格。蓝声明 `minClearance=6`，检查战斗范围内所有存活可受攻击玩家（不仅最多5名点名目标），扣真实碰撞体距离。预警反应时间另外校验，净距不能代替反应时间。卡4激活时重新查询声明的通路条件，失败则取消该激光批。

准入至少以完整 batch 为原子，含实际展开成员数。蓝再声明 `onFailure=CancelGroup`：任何后续 batch 失败，停止该组余下计划、已有成员立即停判伤并按声明淡出、预警撤销；已在过去造成的伤害不回滚。每名玩家的个人组分别取消，公共组独立。不能把「本轮取消」含糊地解释成只跳过这一拍。

### D6 目标、随机与外部事实

- `CaptureTargets` 固定最多5名的 UUID 有序集合与槽号，`CaptureFrame`/`SampleTargetPoint` 固定位置。复制份数只来自该集合，当前最近玩家重排序不得改变槽号。
- 服务端发现目标死亡/退出/离开战斗资格，发布 `InvalidateTarget`，取消该槽未来个人拍；已经发出的弹依声明 `continue` 或 `collapse`，蓝默认继续其既定路径到全卡收束。不会转派。
- 大妖精环在 age60 再瞄准，是运行期采样；每个环只发一份目标点事件，成员从各自确定位置算方向，无需48份完整快照。玩家的未来位置不能因「可预测」降为出生时可知。
- RNG=`hash(encounterSeed,nodeId,occurrence,targetSlot,lineage,generation,memberIndex,channel)`；lineage包含每代父/孩子序号。可跳转、不依赖遍历次序，删掉一支不改变其他支。可提前确定的随机选择不逐tick发事件；从运行时有效目标集合选择仍须发布结果。
- `ResolveSurface` 为服务端有限世界查询，结果坐标/有效 mask 进入 plan；雨、地柱不在客户端重新找地面。激光受动态方块遮挡的长度由服务端权威裁剪，改变时批量更新量化长度；静态场景不持续发全量长度。不断扫过地形的激光会增加事件量，须单独测量。

### D7 组级协议、兴趣管理与恢复

统一消息封套：`protocolVersion, dimension, encounterEpoch, streamRevision, serverTick, kind, boundedPayload`。

| 消息 | 内容与发送条件 |
|---|---|
| Definition | programHash、schema、操作/图案描述、曲线、已解析服务端配置；每连接按 hash 缓存，缺失时发送；不发送可执行代码 |
| Start / Checkpoint | 卡/背景实例、活跃组、各时钟锚点、已采样输入、存活成员 mask、已发生决策、未来计划与 acceptedRevision |
| DecisionBatch | CommitBatch、CancelScope、InvalidateTarget、TargetSample、RemoveMembers、BeamLength 等实际运行期事实；含 effectiveTick、group/batch handle、revision |
| Clock / Digest | 每连接每活跃维度低频共享时钟观测和轮转组摘要，默认40tick；不逐弹发送位置 |
| ResyncRequest / End | 缺描述/版本不匹配/摘要失败时按作用域恢复；终止与 tombstone 防止旧消息复活 |

有序 TCP 不另造丢包重传协议。序号用于幂等、旧 epoch 拒绝、兴趣订阅切换与异步初始化后的完整性检查；缺描述时有界暂存，超限请求 checkpoint，不无限等缺号。协议长度上限、每连接请求频率、group/plan 数上限在 codec 与运行时同时检查；大型初始快照按有界 chunk 分帧传输，完整提交前不产生部分攻击。

兴趣管理按预测世界 AABB 加跟踪边距订阅组，不能只看 BOSS 所在区块，否则远离 BOSS 的弹会消失。每组限制最大跨度；过大组按 batch/空间簇分片，维持原身份与共享定义引用。玩家进入范围时获得当前 checkpoint，不重播历史音效；离开只释放客户端副本，不销毁服务端攻击。父组不在范围内时仍提供求值所需父变换闭包。

Checkpoint 是自足状态，不拼接较晚的 entityData；包含采样结果、段起态、目标有效性、成员删除、派生游标/已批准批次、收束状态。发射与伤害有游标，恢复只重建状态不重复执行历史副作用。客户端事件历史只保存当前 checkpoint 后仍需重建的有限窗口；新 checkpoint 后截断。

预测轨迹不是权威命中。客户端可以对本地方块做保守遮挡显示以减少穿墙闪现，但不能因此永久删除成员或影响服务端结果。

### D8 延迟与不拉回的边界

客户端全体组共用维度服务器时钟估计，含速率与陈旧判据；程序 revision 不得借用 age，时钟误差与程序输入变化独立检测。正常可预知轨迹直接在 renderServerTime 求值，不消费逐弹位置修正。

未来生效事件尽量提前发送；不可提前知道的重瞄/准入决定在实际采样 tick 发布。迟到时从 effectiveTick 的解析边界状态安装事件，再直接求当前时刻；不重放世界碰撞和伤害。渲染可在≤2tick内消去小视觉偏移（默认≤0.25格），不修改判伤轨迹；超过阈值或涉及新生/死亡时直接应用并计数。不能承诺任意延迟下既完全即时又无可见修正。

不整体延迟所有攻击来隐藏网络延迟，避免把画面和服务端判伤系统性错开。未收到 Commit 的批次只能显示已知预警。时钟失信时在最后可信时间冻结表现并请求恢复，不继续无限外推；持续失信有显式诊断。恢复音效采用 `(epoch,nodeId,occurrence)` 去重，晚加入不补播。

### D9 生命周期、循环与持久化

- 一次性、固定长度循环、持续周期流为显式 PlaybackPolicy；不靠 `repeatEvery=0` 或缺字段猜测。有限 Repeat 到尾后停止发射，成员依寿命存活。
- 正常跨轮：`retainUntilLifetime` 允许花海、尾珠、雨的旧代存活；每轮生成新身份，不覆盖旧组。蓝用 cycleTime220 全卡当轮收束，230清空，240新轮。
- 切卡：保留已有血量选择/循环边界挂起规则；切换时旧卡的全部组、派生和预警立即停判伤并终止，下一卡从0开始。正常跨轮残留不等于跨卡残留。
- 死亡/卸载/维度离开：Encounter 统一取消卡、底噪与全部派生；发 End，释放预算。BOSS 底噪使用同一运行时独立实例，大妖精与山女允许叠加，蓝关闭。
- v1 BOSS 战运行实例是临时状态：服务端 BOSS 卸载或重启不保存弹幕；重新激活 BOSS 从当前血量所选卡的第0轮开始，新 epoch；旧 BOSS 弹实体加载时按迁移标记清理。客户端重追踪不会重启服务端战斗，必须 checkpoint 恢复。这是显式存档行为变化，仅限 BOSS；旧非 BOSS 弹存档规则维持。
- owner 存活且已加载时，攻击只在已加载碰撞区域结算；不得为弹幕强加载区块。飞入未加载区域的 batch 成员终止并发布移除，不在加载后复活。

### D10 预算、校验与扩展纪律

预算分三层：每 tick 实际展开/派生峰值、每玩家近域危险密度、世界总存活/CPU上限；预警有独立 FX 数量上限。完整 batch 原子准入，拒绝事件保持双端一致。长期重复按可计算窗口统计，不无限展开程序。

静态验证：时间域/句柄作用域、循环界限、同通道冲突、无界派生、类型单位、最大段数/层级、预警对 plan 的引用、真实成员数（花心与激光每节点两射线都计）、寿命/跨轮上界。空间通路、地形遮挡、多人交叉压力通过离线采样与实机验收；不宣称 lint 自动证明可玩性。

新增路径或图案必须能独立注册，不修改世界 runtime 的 dispatch 主循环、通用消息封套或全部成员字段结构。新增需要世界查询的原语属于 DecisionProvider，给出数据输出与成本上界，不能偷放进纯 evaluator。

### D11 分裂事务、移动源与持续喷射

常用基础详见operations §10，四个强制验收样例见pattern-recipes。ReplaceMembers以净占用准入，同一提交结束母弹并生成子代；普通母弹结束不级联撤销已脱离子代，CancelScope才执行归属清理。有限代数、每代分支数和寿命必须可预算。

移动发射源必须区分三类：静态快照、可解析Member/GroupPose、服务端逐发采样ExternalEntitySource。前两类可共享函数，外部实体必须同步采样结果；其自身碰撞仍由原实体处理，不再叠一个伤害代理。已出生子弹的跟随与源速度继承由Emit参数明确声明。

Billboard面向每个玩家摄像机只影响显示；炮口朝向在世界坐标下由同一角度函数定义。CreateEmitter按整数tick重复发射，固定频率/角速度无需逐帧同步，但动态预算准入仍需按tick批量确认。低带宽不等于高频派生可以无限或完全无事件。

### D12 消除作者层歧义

固定/移动源的计划不必提前物化每颗弹坐标。计划可以保存不可变的确定性源路径及未来出生时刻，届时双方求同一出生姿态；这仍是同一份计划。外部实体的未来姿态未知，只能在发射时采样；如果要求提前准确预警，必须提前冻结该批源位置，不能同时承诺实时跟随和预警完全重合。

水平转弯必须指定参考轴。蓝卡6采用锁定帧的U轴（在F/R平面内转±25°并回F），不是世界Y轴；这是对表格“相对F水平”的明确解释，避免F含俯仰时转弯终点不回F。任何改为世界水平的内容必须另行声明。

ComposeTransform的顺序见operations §10。AddOffset和MultiplyScale只作分别“位移相加”“缩放相乘”的显式组合器，不能自动合并所有写入。空间上界bounds由各操作提供保守界；不能在任意目标距离下保证的扫掠上限同时进行运行期检查，超出时按明确拒绝/终止策略处理并记录，不仅依靠构建期检查。

## Risks / Trade-offs

- [数据后端迁移面大] → 先用同一描述双后端影子对比，仅一个判伤；代表性卡通过再迁移全部，最终删除 BOSS 旧路径。
- [组共享可能增加恢复复杂度] → 自足 checkpoint、不可复用身份、终止 tombstone、父变换闭包；不复用 Minecraft 实体引用承载组。
- [任意组合可能失控] → 通道单写者、显式合成、层级/派生/操作数量上限；本次实现现有需求、operations §10常用基础与指定探针；future扩展保留入口，不交付空实现。
- [RNG/三角函数分歧] → 统一量化、StrictMath、固定计算次序、跨平台样本；所有随机函数按索引而非执行次数消费。
- [世界裁剪与命中事件仍随成员增长] → 批量稀疏 mask/长度更新、兴趣分片；分别统计定义、决策、恢复成本，不宣称所有带宽 O(1)。
- [表格与代码冲突] → `content-mapping.md` 列明迁移口径与已知缺陷；不能以旧截图相似代替需求验收。
- [性能未获证实] → `migration.md` 明确同等弹量 A/B 门槛；未达标不移除回退后端，不靠降低弹数过关。

## Migration Plan

1. 冻结测量样本、内容与协议基线；以新 specs 明确旧规则适用域。
2. 实现纯程序/操作核、编译和无世界测试；先证明组合与任意时刻求值。
3. 打通组级同步、数据后端、碰撞/渲染桥接和恢复；用蓝1/4/6与花海/尾珠作纵向切片。
4. 达到正确性、带宽和性能门槛后迁移全部内容与默认攻击，处理生命周期与存档切换。
5. 清除 BOSS 旧入口、旧字段扩展债与临时适配器；非 BOSS 兼容代码按引用保留；更新技能/主规格和两项扩展的交接状态。

迁移期配置按 encounter 选择后端，开战后不热切换。回退必须结束当前 encounter 后重新生成，不能让旧后台接管新程序的半程状态。撤回代码或配置不丢失非 BOSS 数据；BOSS 临时弹幕按上述规则重开。
