# 配置面规范（config-surface）

> 本文件是「什么数值可以进配置、进哪个配置」的**唯一操作手册**，由 `openspec/project.md` §4 引用，
> 由 capability `config-surface` 规范。新增任何数值前先读本文件。
>
> 背景：本 mod 曾把所有数值塞进单一 `gensokyou-common.toml`（COMMON），膨胀到 605 键 / 101 KB，
> 战力数值因此可被任意修改，客户端与服务端还各读各的。本规范终结这一做法。

## 1. 一句话判据

> **把某个值翻倍，会不会改变「同一场战斗的结果」？**

- **会** → 战力数值 → **代码常量**，禁止配置化。
- **不会**，但会改变资源累积速度 / 世界节奏 → **SERVER 配置**。
- 只改变画面 / HUD / 手感 → **CLIENT 配置**。

## 2. 三个桶

| 桶 | 载体 | 权威性 | 内容 |
|---|---|---|---|
| 战力数值 | 代码常量（`*Numbers` / `*Scaling` / `*Tuning`） | 随 jar 版本，天然两端一致 | 伤害、生命、属性、怪物/BOSS 预算、弹幕武器强度与**消耗**、符卡、掉落概率、装备强化、药水、弹幕内部容差 |
| 玩家配置（玩法经济） | `gensokyou-server.toml`（`ModConfig.Type.SERVER`） | 服主权威，登录同步给客户端 | 仪式产灵/缓存/受灵/消耗/冷却/产出、仓储上限与黑名单、整地/引爆器成本与默认值、刷新概率倍率 |
| 客户端设置 | `gensokyou-client.toml`（`ModConfig.Type.CLIENT`） | 各玩家本地 | 画质档、绘制距离、镜头抖动、预警符、HUD 血条/技能栏、工具默认值 |

### 2.1 为什么战力数值用常量而不是 SERVER 配置

1. **战力自成体系**：伤害与血量是一套精调过的闭环，允许调单个数字会破坏击杀时长与可挨发数的关系。
2. **常量比配置更可靠**：常量随 jar 版本走，服务端与客户端必然一致；配置需要同步管道，且历史上正是「客户端读本地 config」导致引导书数字与服务器不符。
3. **单一真相源**：常量 + 单测锁定，改动必然过 spec 与回归测试。

### 2.2 为什么经济用 SERVER 而不是 COMMON

COMMON 在双端各读本地文件、**不同步**。经济数值需要客户端展示（引导书、GUI 信息行），
必须由服务端权威并同步。SERVER 类型登录时同步，正好满足；单机时玩家即服主，照样可调。

## 3. 决策树

```
新值要往哪放？
│
├─ ① 翻倍会改变同一场战斗的结果？
│    └─ 是 → 代码常量（禁止配置化）
│
├─ ② 它是"玩家自己的偏好"（画面/HUD/手感/便利），
│    │  且不同玩家不同也不破坏公平？
│    └─ 是 → CLIENT 配置
│
├─ ③ 它改变资源累积 / 世界节奏，且必须全服一致？
│    └─ 是 → SERVER 配置（并在 change 的 design.md 记录判据结论）
│
└─ ④ 它是实现细节（协议容差/性能上限/美术几何）？
     └─ 是 → 代码常量
```

## 4. 已裁决的灰区（不要再重新讨论）

| 灰区 | 裁决 | 理由 |
|---|---|---|
| 掉落概率（材料/信物/符卡/拉维坦） | **常量** | 掉落=变相调战力 |
| 装备技能（灵铁免耗、星银精准采集、额外矿概率、星银套装灵力伤害加成） | **常量** | 星银套装加成是纯战力；同类连坐 |
| 药水（回灵比例、彼岸花毒伤倍率） | **常量** | 战斗续航/战力 |
| 仪式产出数量 | **可调，但只暴露每阶倍率 `*_MULT*`** | 产出基线属设定；倍率是「与其它 mod 配合时压价」的真正痛点 |
| 各阶标准灵力池表 | **常量** | 它编码战力曲线，只是被借来算泡澡速率 |
| 仪式 `fx*` 特效几何/颜色 | **常量**，由 CLIENT 画质档收口 | 美术指导，不是玩家偏好 |
| 仪式产能/容量/受灵/消耗、仓储、工具成本 | **SERVER 配置** | 非战力经济，玩家点名的可调面 |

## 5. 新增一个可调项的 checklist

1. 用第 1 节判据得出结论，并写清理由。
2. **先向用户确认，或确认这是用户主动提出的**——否则不得新增。**没有键数上限**，但不得擅自添加。
3. 默认值 = 策划推荐值；附一句用途注释。
4. 放对文件（SERVER / CLIENT），命名 `lowerCamelCase`，与同段风格一致。
5. 在 change 的 `design.md` 记录该键的判据结论。
6. 更新 `ConfigSurfaceTest` 的白名单。
7. 客户端要用该值时，走同步后的 SERVER 值或同一份常量，**不得**读本地文件独立计算。

## 6. 反例（历史教训）

- `BOSS_SECONDS_T1/T3/T4/T5` 从未被读取；`MONSTER_SPAWN_ROLL` 注释自承未接线。
- BOSS 血量两套并行口径（通用 `bossHpMin/Max` 与每 BOSS `bossSeconds`），策划不知该改哪个。
- `client/book/RitualTierComponent` 直接读本地 config 现算经济数值并在引导书展示——dedicated server 上撒谎。
