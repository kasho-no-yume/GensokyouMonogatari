# 玩家符卡设计与开发规范

一句话目标：**玩家的符卡是「技能」，不是「弹幕」。** 所以规范的核心是
**功能优先——先回答"它替玩家解决了什么问题"，再回答"它长什么样"。**

与 `boss-dev-design` 严格分工：

| | 谁的设计物 | 心智模型 | 读哪本 |
|---|---|---|---|
| BOSS 符卡 | `BossCards.java` 轨道表 | 一段可读的弹幕**戏** | `boss-dev-design` |
| **玩家符卡** | `SpellCardEffects.REGISTRY` | 一个由灵力驱动的**功能** | **本 skill** |

> BOSS 符卡的所有 R1/R2/R3 可读性契约、轨道编排、形状词汇**都不适用于玩家符卡**。
> 玩家符卡不要求"每一发都朝着敌人"——它是玩家自己瞄准/自己在场内经营的东西。
> 把两套规范混用是本 skill 最容易犯的错。

---

## 0. 三条铁律

1. **功能优先。** 一张卡必须先说清它解决什么（恢复/防御/位移/控制/清场/欺骗/资源），
   再谈数值。纯"往某方向放一波弹"的卡在玩家侧是**空卡**——武器已经在做这件事了。
2. **数值忠实于该卡自身的曲线，禁止全表共用一条缩放曲线。**
   伤害卡要跟得上怪物 HP（近线性），回血卡必须被压得远低于 HP 成长（否则超模）。
   见第 2 节——这是本 skill 存在的最主要原因。
3. **卡的效果只允许"传递式"接入世界**：宿主实体 / 玩家附件 / 事件钩子 / `MobEffect`。
   **MUST NOT** 在效果函数里直接写一大坨一次性逻辑然后什么都不留
   （那样无法持续、无法同步、读档即丢）。

---

## 1. 功能优先：先分类，再设计

每张卡在动数值前 MUST 先归入下面某一类。**分类决定它该不该随灵力强度成长、成长多快。**

| 类别 | 解决的问题 | 例（本项目） | 该不该随灵力强度成长 |
|---|---|---|---|
| 恢复 | 续航 / 据点 | 花符『癒しの花園』 | 弱（远低于 HP 成长） |
| 防御 | 吃弹 / 免伤 | 花符『鮮花之鎧』 | 中（挡弹数随敌弹密度） |
| 控制 | 让敌人失去行动/视野 | 闇符『ディマーケイション』、網符『蜘蛛の巣』 | 弱（控制是二元的） |
| 反制 / 净化 | 把负面转成武器 | 疫符『病の返し』 | 弱（计数固定） |
| 召唤 / 自动攻击 | 替你输出 | 式神『狐の従者』 | **强（近线性）** |
| 位移 | 机动 | （预留）網符拉丝 | 中 |
| 欺骗 / 脱战 | 换目标 / 骗技能 | （幻符已砍） | 弱 |

### 四角色人设映射（前期 BOSS 群）

符卡的功能主题 SHOULD 来自对应角色的**人设签名**，而不是从角色名硬凑。

| 角色 | 人设签名 | 玩家卡功能主题 |
|---|---|---|
| 大妖精 | 花、生长、温柔的守护 | 恢复 / 护盾 |
| 露米娅 | 操纵黑暗、在黑暗里危险 | 致盲 / 隐匿 / 脱战 |
| 黑谷山女 | 蛛网、疫病、把灾祸带走 | 区域减速 / 免控反伤 |
| 八云蓝（伪） | 式神、计算、"伪"（幻象） | 自动召唤 / 欺骗 |

> **「伪」的用法**：八云蓝是残影/伪物，"伪"天然支持**零伤害的欺骗类**效果
> （分身、假技能）。这是人设直接长出来的机制，不是硬编的。

## 2. 品质 × 灵力强度缩放模型（核心）

### 2.1 为什么不能用一条统一曲线

玩家灵力强度（`AttributeKey.SPIRIT_POWER`，见 `docs`/config grace 表）**每阶 ×≈9**：

| 神恩阶 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| `max_spirit` 标准值 | 1,000 | 10,000 | 100,000 | 1,000,000 | 10,000,000 |
| **灵力强度 standard** | **1** | **10** | **90** | **773** | **6523** |

- 武器伤害是**线性**吃灵力强度（`WeaponFiring`：`spiritPower × 核倍率 × …`），所以跟得上怪物。
- 但**符卡不能统一线性**：怪物同阶 HP 每阶 ×10，而玩家 HP 只 30→560（×≈18 全期）。
  - 伤害符卡若总增长只有 ×14 → 高阶形同废卡（"拉完了"）。
  - 回血符卡若总增长 ×14 → 高阶一口回半条命（"吓哭了"）。
- **结论：每张卡声明自己的缩放指数 `α_card`，禁止全表共用。**

### 2.2 公式

```
S      = 玩家当前灵力强度（PlayerAttributes.spiritPower(player)）
α_card = 该卡自己的缩放指数（config，逐卡）
值     = Base × S^α_card
```

- `Base` = 该卡在品 1 / 灵力强度 = 1 时的基准值。
- **道具符卡不看玩家属性**：`值 = Base × S_std(品)^α_card`（固定，品即档）。
- 若需要"卡内某参数不随品质变"（如控制时长、半径），直接给**固定表**，
  不走公式——**控制与范围的膨胀比数值膨胀更危险**。

### 2.3 α 怎么取（经验法则）

| 卡的类别 | α_card | 每阶倍率 | 理由 |
|---|---|---|---|
| 伤害 / 自动攻击 | **0.85 ~ 1.0** | ×6~9 | 必须跟得上怪物 HP（×10/阶） |
| 防御 / 挡弹数 | 0.2 ~ 0.3 | ×1.5~1.7 | 敌弹变多但不必 1:1 |
| 恢复 | 0.15 ~ 0.2 | ×1.4~1.6 | **刻意远低于 HP 成长**，前期强、后期转为辅助 |
| 控制 / 反制 | 0.1 ~ 0.15 | ×1.3~1.4 | 控制是二元的，膨胀即超模 |

> 「收益指数级降低」这条**只对功能性收益成立**。对伤害卡，降低到 0.85 已经是
> 在"跟得上"与"不超模"之间的折中；把伤害卡也压到 0.3 就是制造废卡。

### 2.4 已存在、直接复用的乘区（不要再造）

- 冷却：施放时经 `PlayerAttributes.effectiveSkillCooldown`（吃 `spell_cdr`）。
- 时长：`buff_extend` 由 `EffectDurationHandler` 作用于 `MobEffect`。
- 伤害/回血：再乘 `(1 + spell_amp)`（`AttributeKey.SPELL_AMP`，逐阶 +15%→+100%）。
  **注意**：`spell_amp` 目前是"预留无消费点"的属性（见 config `ATTR_BASE_SPELL_AMP` 注释），
  玩家符卡将是它的**首个消费者**——实现时顺带更新该注释。
- **道具卡不吃以上三者**（它是固定数值 + 卡片本身即消耗）。

## 3. 双形态：道具符卡 vs 已学符卡

同一张卡有两种载体，**共用同一执行器**（`SpellCardEffects.perform`），但数值语义不同。
设计一张卡时 MUST 同时给出两形态的数值。

| | 道具符卡（掉落 / 一次性） | 已学符卡（委托习得 / 灵力驱动） |
|---|---|---|
| 数值 | 固定 = `Base × S_std(品)^α_card` | 动态 = `Base × S^α_card` |
| 品阶 | 掉落时即带 1~5 品 | 由学习时的阶级决定（1~5） |
| 门槛 | 无素质要求（凡人可用） | 需阶级达标 |
| 消耗 | 卡片本身（`stack.shrink(1)`） | 灵力 `spCost` + 冷却 |
| 定位 | 付费跳级 / 应急爆发 | 正途 / 常驻 |

- **不做"道具比同品已学更强"的额外倍率**（曾考虑，已否决）：两者同品即同数值，
  简洁且不需要解释。若将来确需，再加 config `itemCardMultiplier`（默认 1.0）。
- 道具能不能被凡人拿到高品，是**掉落/经济问题，不是数值问题**——设计数值时不必考虑。

## 4. 单卡解剖模板

一张玩家符卡的规格 SHOULD 包含以下字段（`reference/card-roster.md` 即按此写）：

```
名称        「X符『……』」（东方格式，中英双份 lang）
归属角色    人设来源
类别        §1 的分类
形态        功能 / 攻击
触发        瞬发 / 持续 / 引导
表现        玩家看到/听到什么（粒子、光影、音效、UI 提示）
机制        精确的行为，含边界条件
数值表      5 品逐档（Base + α + 派生表）
缩放        哪些参数吃 α_card，哪些固定
接入点      宿主实体 / 附件 / 事件钩子 / MobEffect
红线        这张卡"不许做什么"
```

### 反馈可读性（玩家卡同样适用）

玩家符卡**不要求** BOSS 那套前向威胁契约，但**"玩家能不能读到卡生效了"是硬要求**：

- 挡下弹幕 → 必须有破碎特效 + 音效 + actionbar 计数（否则玩家不知道卡在帮忙）。
- 免疫/控制生效 → 必须有视觉锚点（光罩、变暗、轮廓、粒子）。
- 持续型 → 圈/场的边界要能看见，剩余时间要有反馈。

## 5. 复用的原语与接入点

### 5.1 注册与载体

| 需求 | 现有位置 |
|---|---|
| 卡效果注册表 | `spirit/SpellCardEffects.java`（`REGISTRY` + `Entry(effect, spCost, cooldown, themeColor)`） |
| 道具形态 | `item/spellcard/SpellCardItem` 子类 + `ModItems` 注册 |
| 已学形态 | `spirit/SkillStateData`（learned / equipped / cooldownUntil）+ `/gs_learn` |
| 卡面 tint | `client/GensokyouItemColors`（读 `Entry.themeColor`） |
| 图标 | `tools/gen_tex.py`（ASCII 像素图 + 调色板，禁止逐像素脚本） |

### 5.2 持续型效果的宿主（关键）

一次性 `perform(level, player)` **表达不了**范围场、护盾计数、召唤物。
持续型 MUST 落为下列之一：

| 形态 | 用在哪 | 参考实现 |
|---|---|---|
| 宿主实体 | 范围场、召唤物、环绕物 | `entity/OrbitYinYangOrb`（`DATA_HOST` 存 UUID、`tick` 解析宿主、双端各自定位） |
| 玩家附件状态 | 护盾计数、免控、隐身 | `spirit/SkillStateData` 同目录的 Attachment 写法 |
| `MobEffect` | 致盲、减速、免疫 | `registry/ModMobEffects` |

### 5.3 事件钩子（只有这些，不要另开）

| 想做的事 | 钩子 |
|---|---|
| 挡弹射物 / 反伤 | `LivingIncomingDamageEvent`（判 `source.getDirectEntity() instanceof AbstractDanmakuProjectile`） |
| 玩家主动攻击 → 结束控制卡 | `LivingHurtEvent`（判 `source.getEntity() == player`） |
| 阻止新负面效果 | `MobEffectEvent.Added`（取消） |
| 日常 tick | 宿主实体的 `tick()` 或 `PlayerTickEvent` |

### 5.4 BOSS 也要吃效果时

控制类卡常要求"对 BOSS 生效"。BOSS 的锁定与移动在 `AbstractTouhouBoss`
（`refreshTargets` / `BossSteering`）——**在 BOSS 侧加可选的"被控制"开关**，
不要改轨道调度管线，也**不要**指望原版 `Slowness`（BOSS 常免疫）。

## 6. 新增一张玩家符卡 · checklist

```
设计
  □ 归属角色 + 人设签名（§1 映射表）
  □ 类别（决定 α 档）
  □ 功能一句话："它替玩家解决___"
  □ 两形态数值表（5 品）
  □ 反馈可读性：玩家怎么知道它生效了

实现
  □ SpellCardEffects.REGISTRY 注册（id / effect / spCost / cooldown / themeColor）
  □ 在哪里读灵力强度：PlayerAttributes.spiritPower(ServerPlayer)
  □ 持续型 → 宿主实体 / 附件（禁止裸一坨逻辑）
  □ 控制/挡弹 → 走 §5.3 钩子
  □ BOSS 需生效 → BOSS 侧开关
  □ config：Base / α_card / 各固定参数进 defineInRange
  □ lang zh_cn + en_us：符卡名 + 必要的提示语
  □ 图标：gen_tex.py
  □ 道具形态：SpellCardItem 子类 + ModItems 注册

验证
  □ 数值单测：α 曲线、上下限、道具固定值
  □ 实机：生存模式（创造/和平会让测不出伤害）
  □ 退出重进（持续型状态是否自愈）
```

## 7. 常见坑

1. **把统一 α 硬套全部卡** → 伤害卡废、恢复卡神。每卡独立 α（§2.1）。
2. **回血按 HP 比例成长** → 高阶回半条命。恢复类刻意压到 ×1.4~1.6/阶。
3. **控制类做范围/时长随品质膨胀** → 高阶全场无限控。控制/范围给固定表。
4. **一次性逻辑不留状态** → 读档即丢、双端不同步。走宿主实体/附件。
5. **指望原版 `Slowness` 控 BOSS** → BOSS 抗性吃掉。走自定义属性修饰符。
6. **忘了道具卡不吃玩家属性** → 数值漂移。道具用 `S_std(品)` 固定。
7. **挡弹把近战/环境伤害也挡了** → 只判弹射物来源。
8. **创造模式/和平难度测伤害** → 恒不生效（见 boss-dev-design §14 坑 10/11）。
