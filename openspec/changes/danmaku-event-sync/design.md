## Context

确定性轨道可以让客户端低带宽重建位置，但运行时仍有一类变化不是轨道初始参数的纯函数：服务端临时改向、灵符目标切换或永久丢失、分裂生成、激光阶段和权威方块裁剪、提前销毁等。若这些变化继续依赖客户端目标实体、方块状态或本地 tick 推断，服务端和客户端会在网络延迟、区块加载和实体重建后走不同状态。

本变更只解决“不可预测变化如何同步”。轨道时间轴负责连续运动，渲染状态隔离负责避免样本污染；事件层负责把状态变化以服务器时间和序号交给客户端重放。

## Goals / Non-Goals

**Goals:**

- 统一表达弹幕的离散运行时变化。
- 保证重复、乱序、旧事件和缺号不会破坏客户端状态。
- 让事件按服务器时间重放，降低到达延迟对视觉相位的影响。
- 对非确定性行为使用关键帧，而不是无限预测。
- 保持服务端玩法权威。

**Non-Goals:**

- 不实现确定性轨道位置函数。
- 不让客户端事件结果参与伤害或分裂配额。
- 不保证丢失事件期间客户端拥有最新的不可预测状态。
- 不把所有每 tick 变化都转成事件；高频连续运动应由轨道或关键帧负责。

## Decisions

### 1. 事件统一信封

每个事件包含：

```text
scopeId        轨道或实体身份
entityIndex    可选的轨道实例索引
serverTime     事件发生时间
sequence       scope 内单调序号
kind           事件类型
payload        类型参数
```

选择统一信封而不是每种行为一个无序 payload，是为了让客户端拥有统一的幂等、缺号和生命周期处理。

### 2. 客户端按序号应用，按服务器时间重放

事件按 scope 维护 `nextSequence`。重复和旧序号直接丢弃；缺号事件暂存，直到补齐或收到包含完整状态的快照。应用时使用 `serverTime` 将状态插入轨道时间轴，不使用包到达 tick 作为发生时间。

这避免了“晚到的分裂事件在当前 tick 突然播放”和“重复分裂事件生成双份视觉子弹”。

### 3. 事件与快照互为恢复边界

事件缺号、实体重新创建或客户端超过缓存窗口时，客户端必须接受新的 scope 快照。快照携带当前状态、最后应用序号和时间锚点，应用后丢弃更旧事件，保留未来事件。

相比无限等待，快照可以恢复丢包；相比立即跳过缺号事件，快照不会把错误状态当作连续状态运行。

### 4. 按行为分类

- `REDIRECT`：服务端改向/速率变化。
- `TARGET_CHANGED` / `TARGET_LOST`：灵符目标状态。
- `SPLIT`：父弹结束、子弹身份和轨道索引。
- `PHASE_CHANGED`：激光或其他阶段状态。
- `GEOMETRY_KEYFRAME`：权威长度、位置、方向等非确定性几何。
- `DESPAWN`：提前销毁或服务端生命周期结束。

客户端只对这些事件更新表现状态；服务端仍独立执行真实逻辑。

### 5. 分裂事件先分配身份，再呈现

服务端在生成分裂子代前分配稳定身份、轨道/实例索引和预算结果，事件只描述已获准的子代集合。客户端重复收到事件时按身份去重，不自行决定子代数量。

这保持 BOSS 弹幕上限和服务端分裂预算的权威性，也防止客户端因为重复包看到更多弹幕。

### 6. 非确定性行为使用关键帧

灵符追踪和方块裁剪不依赖客户端是否恰好加载同一目标/区块。服务端定期发送关键帧或状态事件；客户端在短窗口内插值，超过最大预测窗口进入不确定状态并等待新快照。关键帧不会被当作连续每 tick 位置包。

### 7. 生命周期和旧包防复活

每个 scope 有出生版本和结束标记。收到 `DESPAWN` 后客户端清理事件缓存、关键帧和渲染状态；任何旧事件、旧实体位置或年龄包不得重新创建 scope。未知 scope 的事件只能暂存有限时间，不能创建幽灵弹。

## Risks / Trade-offs

- [Risk] 事件乱序会暂存内存。→ 每 scope 限制缓存数量和时间，超限转快照恢复。
- [Risk] 事件缺失导致表现暂时停滞。→ 提供周期快照/关键帧和显式不确定状态，不继续错误外推。
- [Risk] 大规模分裂形成事件尖峰。→ 批量编码子代身份与轨道索引，并复用轨道快照。
- [Risk] 事件序号跨存档不连续。→ 将 scope 版本和最后序号纳入服务端存档，重载时以新快照建立新版本。
- [Risk] 客户端与服务端对事件参数解释不一致。→ 使用协议版本和事件类型注册表，未知版本拒绝并请求快照。

## Migration Plan

1. 增加事件信封、序号状态和客户端缓存，不迁移行为。
2. 先迁移提前销毁、激光阶段和目标丢失等低频事件。
3. 迁移分裂身份和服务端预算结果。
4. 迁移中途改向、目标切换和几何关键帧。
5. 为缺号/重建接入周期快照，并清理旧位置/年龄包对事件状态的覆盖。

## Open Questions

- 缺号恢复是由客户端请求 scope 快照，还是服务器向所有追踪者周期广播快照？
- 事件 scope 应以轨道为主还是实体为主？建议轨道事件优先，实体生命周期事件保留实体身份。
- 关键帧频率是否按运动曲率、目标变化和网络质量动态调整？
