## Context

`danmaku-timeline-sync` 负责确定性轨道的时间和连续位置；已归档的 `danmaku-render-state` 负责模拟、权威样本和渲染状态隔离。本变更只处理无法由已同步轨道纯函数唯一推导的运行时状态。

当前代码中最明确的非确定性边界是：灵符每 tick 根据本端看到的目标位置转向，并可能各自在本端判定永久丢失；激光客户端根据本端方块世界裁剪视觉长度，而服务端根据服务端方块世界判伤。服务端临时改向/速率变化也会通过普通运动同步形成“先错后纠”的路径。相反，激光固定延迟/持续阶段、相位显隐、悬停和普通生命周期边界已有年龄与同步参数可推导，不应仅因为存在 event proposal 就全部事件化。

`docs/danmaku-sync-architecture-and-open-problems.md` 中关于抖动、年龄差和事件需求的描述是历史调查材料。尤其是沿本地速度投影得到的 `lagTicks` 不能自动证明年龄差，硬纠正还可能污染投影。事件协议的触发条件必须来自服务端状态变更和带服务器时间的关键帧，而不是从该文档的旧诊断数字反推。

## Goals / Non-Goals

**Goals:**

- 用统一信封表达真正不可预测的离散变化和有限频率关键帧。
- 保证重复、旧版本、乱序、缺号、实体重建和跨生命周期包不会破坏客户端表现状态。
- 按 timeline 的服务器时间重放事件，不按网络到达 tick 重新计时。
- 对灵符目标和激光权威几何提供受限关键帧/事件路径，超过预测窗口进入明确降级状态。
- 保持服务端命中、伤害、目标选择、分裂预算、销毁和其他玩法状态权威。

**Non-Goals:**

- 不实现服务器时间轴、确定性轨道函数或轨道身份基础；这些由 timeline 提供。
- 不把所有阶段、显隐、悬停、生命周期结束和每 tick 变化都转换成事件。
- 不让客户端事件结果创建服务端子弹、决定预算或参与伤害。
- 不保证丢包期间客户端拥有最新不可预测状态；恢复失败时必须降级而不是无限外推。
- 不绕过 render-state 的状态入口，不允许普通位置包、事件和关键帧形成多个模拟坐标写入者。

## Evidence Boundary

- 已确认：灵符客户端目标状态和目标丢失判定依赖本端目标可见性/位置，具备潜在双端分歧；这是首批候选，但仍需记录服务端与客户端状态变化来确定事件频率。
- 已确认：激光服务端 `getActualLength()` 与客户端视觉裁剪使用各自世界，方块加载差异可能产生几何差异；是否值得关键帧化需按激光数量和方块变化频率测量。
- 未证明：历史文档中的特定年龄差、抖动次数或符号翻转不是事件触发证据。它们必须由带时间的样本和独立的状态版本重新验证。
- 已知现状：普通分裂目前由服务端创建子实体并受服务端预算约束，客户端没有独立补生成逻辑。因此分裂事件不是默认首批需求，只在客户端需要提前呈现或轨道实例协议要求时启用。

## Decisions

### 1. 依赖 timeline 的统一事件信封

每个事件至少包含：

```text
scopeId        轨道或实体身份
scopeVersion   事件所属的轨道/生命周期版本
entityIndex    可选的轨道实例索引
serverTime     事件实际生效的服务器时间
sequence       scope 内单调序号
kind           注册表中的事件类型
payload        类型参数
```

`scopeId + scopeVersion` 防止旧轨道事件作用于新生命周期；`sequence` 负责同一 scope 内的顺序、重复和缺号；`serverTime` 负责重放时刻。事件不得自建第二套本地时间或仅携带“收到后延迟多少 tick”。

### 2. 客户端状态机

每个 scope 维护：

```text
currentVersion
nextSequence
pendingEvents
appliedState
lastAuthoritativeTime
predictionDeadline
phase = TRACKING | WAITING_GAP | UNCERTAIN | DESPAWNED
```

处理规则：

1. 版本低于当前版本直接丢弃；新版本只有通过快照/注册建立后才接受。
2. 序号低于 `nextSequence` 为旧事件，等于它才可应用，高于它则有限暂存并进入 `WAITING_GAP`。
3. 应用事件时把状态变更插入服务器时间轴；迟到事件不能从网络到达时刻重新开始阶段或动画。
4. 缺号超过数量/时间上限，请求或等待 scope 快照；不静默跳过缺失事件。
5. 超过关键帧预测窗口进入 `UNCERTAIN`，停止扩大外推；收到有效快照/关键帧后原子恢复。

### 3. 事件与快照的恢复边界

scope 快照携带当前版本、当前服务器时间、完整的非确定性状态和最后已应用序号。接受快照后：

- 丢弃不属于当前版本、序号不大于快照序号的事件；
- 保留当前版本中序号更大的未来事件；
- 清理失效关键帧、旧预测和旧渲染目标；
- 由 render-state 的统一入口原子建立模拟/权威/渲染基准。

事件先于实体注册时只能按 `scopeId + scopeVersion + entityIndex` 有限暂存；注册失败或超时清理，不能创建幽灵弹。实体移除、scope 结束和切世界必须清理事件缓存。

### 4. 首批事件与关键帧

首批只接入有代码证据和实际表现价值的边界：

- `TARGET_CHANGED`：服务端选择或更换追踪目标，携带稳定目标身份或明确的无目标状态。
- `TARGET_LOST`：服务端判定永久丢失，客户端不得自行提前改变权威状态。
- `REDIRECT`：服务端确实改变方向/速率，携带生效时间和完整的新运动输入。
- `GEOMETRY_KEYFRAME`：激光或其他非确定性几何的服务端位置、方向、长度、阶段和有效时间。

`PHASE_CHANGED` 只有在阶段不能由 timeline 轨道时间重建时才启用。`DESPAWN` 只有在普通实体移除无法满足按发生时刻重放或旧包防复活时才启用。`SPLIT` 只有在客户端需要在实体生成包之外提前呈现子代时启用，并必须携带服务端批准的子代身份集合。

### 5. 灵符与激光的具体接入

灵符的客户端不再以本地目标是否存在、角度是否超过阈值作为服务端状态依据。服务端发布目标变化和永久丢失事件；事件到达前客户端可以在有限窗口按旧状态表现，超时后进入不确定状态。客户端事件不得改变服务端目标选择或命中。

激光的服务端判伤继续使用服务端实际裁剪结果。客户端视觉关键帧只用于渲染状态，包含服务器时间、起点/方向、权威长度和阶段；渲染缓存按关键帧序号/时间失效，不能把视觉长度反喂给服务端判伤。

### 6. 分裂和生命周期的条件性处理

服务端仍负责创建子实体和预算。若未来轨道模式使实体生成包不能及时提供完整表现，则 `SPLIT` 事件先携带服务端批准的 UUID/实例索引集合，再允许客户端去重显示；客户端不能按本地 `splitCount` 补充子代。

普通实体移除继续使用已有实体生命周期协议。显式 `DESPAWN` 只作为有服务器时间的表现边界和旧包拒绝标记，不替代服务端实体移除，也不能复活已结束 scope。

## Risks / Trade-offs

- 乱序/缺号会使表现短暂停滞。限制缓存并用 scope 快照恢复，宁可显示不确定状态也不静默跳过状态变化。
- 关键帧增加带宽。只对非确定性几何和目标状态发送，并按变化频率/预测窗口测量，不把它当每 tick 位置流。
- 事件时间早于当前客户端时间时可能需要重放或立即重建。以 timeline 时间插入状态，超出可重放历史就请求快照，不伪造过去的逐 tick 动画。
- 旧 SynchedEntityData、运动包和事件可能互相覆盖。每个状态字段指定唯一写入者，兼容模式下拒绝新旧双重驱动。
- 大规模分裂会形成事件尖峰。仅发送服务端批准集合，批量编码并复用轨道快照；先测量再决定是否启用。

## Migration Plan

1. 定义事件信封、scope 版本和客户端状态机，先不迁移行为。
2. 接入快照边界、重复/乱序/缺号处理和诊断，验证未知 scope 不创建实体。
3. 迁移灵符目标状态；用服务端事件替代客户端独立的永久丢失判定。
4. 依据激光方块差异实测决定是否启用权威几何关键帧；先迁移视觉，不改变服务端判伤。
5. 仅在有明确需求时迁移中途改向、提前销毁或分裂表现，并为每类行为定义唯一写入者。
6. 在 timeline 和 render-state 的兼容模式下完成延迟、丢包、暂停、区块卸载、重追踪和旧包复活验证。

## Open Questions

- 缺号恢复优先客户端按 scope 请求快照，还是由服务端向当前追踪者周期推送？需要结合追踪人数和事件频率。
- 事件 scope 对编队轨道还是实体实例为主？建议连续运动用轨道 scope，实体生命周期和目标状态保留实例身份。
- 灵符目标变化发送离散事件即可，还是需要短周期目标位置/方向关键帧？由实测转向误差和目标可见性决定。
- 激光关键帧发送服务端裁剪长度，还是发送方块命中点/几何版本？需要考虑客户端起点偏移和方块变更频率。
- 事件版本与轨道 `scopeVersion` 是否共用一个 epoch？必须保证重载后旧事件不会作用于新实体。
