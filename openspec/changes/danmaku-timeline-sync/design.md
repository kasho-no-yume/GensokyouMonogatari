## Context

当前弹幕运动分为累加式和解析式两类。客户端通过本地实体 tick 自行推进，并用原版位置包调用 `lerpTo`。这在确定性轨迹上节省了持续带宽，但存在三个耦合：实体本地 tick 不是服务器时钟、位置包会改写模拟起点、渲染直接使用被纠偏的实体位置。

结果是：正常新发射弹幕通常只存在固定传输相位差；实体重新追踪、读档或客户端实体重建后，年龄种子可能与已有本地 tick 组合出错误相位；硬纠正又会污染下一 tick 的速度和滞后诊断。单独增大速度相对阈值或加入 EMA 相位推前，无法证明客户端正在绘制正确轨迹。

本设计面向 Minecraft 1.21.1 / NeoForge 21.1.248，服务端仍是所有命中、销毁和不可逆行为的权威端。目标是让确定性弹幕以轨道时间重建，让非确定性变化以有序事件或关键帧同步，并让渲染纠偏永远不改变逻辑模拟。

## Goals / Non-Goals

**Goals:**

- 将确定性弹幕的客户端位置定义为服务器时间轴上的轨道函数，而不是客户端本地 `tickCount` 的偶然累积结果。
- 将网络带宽从“每枚弹每 tick 的位置驱动”降低为“每轨道/事件/关键帧的变化驱动”。
- 让客户端渲染连续、无周期性硬拉回；位置样本不得污染模拟速度、碰撞扫描或相位诊断。
- 保证重复追踪、实体重建、延迟包、乱序包和丢失实体不会产生重复弹、幽灵弹或不可解释的相位跳变。
- 保留服务端权威的命中、生命周期、分裂配额和销毁结果。
- 允许确定性、半确定性和非确定性弹幕使用不同同步策略，但接口和诊断语义统一。

**Non-Goals:**

- 不承诺在断网期间客户端仍能准确显示服务器刚刚发生的不可预测事件。
- 不把客户端预测用于伤害、无敌帧、分裂配额或其他玩法判定。
- 不要求所有弹幕都强行改成同一种运动学实现；累加式、解析式和关键帧式可以共存。
- 不通过无限增大相位外推或隐藏硬失步来追求表面平滑。
- 不在本变更中重新设计弹幕视觉材质、几何形状或 BOSS 符卡编排。

## Decisions

### 1. 以服务器时间轴作为确定性弹幕的唯一表现时钟

每条确定性轨道拥有服务器生成时间、轨道起始年龄/时间、轨道参数版本和生命周期。客户端根据估计的服务器时间计算轨道时间，再求 `position = f(track, time, index)`。

选择时间轴而不是继续扩展 `peerAge + tickCount`，因为后者只能修复一次实体重建，不能表达客户端时钟推进、重复种子和轨道重放。服务器时间锚点允许多个客户端在不同追踪时刻重建同一轨道，而不共享错误的客户端年龄值。

候选方案：

- 继续使用年龄种子：改动小，但持续依赖本地 tick 速率相等，无法处理重复种子和时钟漂移。
- 每 tick 同步位置：质量直观，但高密度弹幕带宽为 `O(弹数 × tick)`。
- 服务器时间轴：一次发送轨道输入，客户端可重建，符合弹幕确定性运动的结构，作为主方案。

### 2. 以轨道为同步单位，以弹索引为实例身份

编队、环、玫瑰线和同一符卡批次的弹幕使用轨道 ID、轨道版本和索引标识。轨道快照包含可重建运动所需的常量；轨道参数不能引用只存在于服务端且没有同步语义的运行时对象。

选择轨道级同步是为了避免把同一组编队参数复制到几十枚 `SynchedEntityData`，并减少实体重新追踪时的参数竞态。实体仍可以存在以复用现有碰撞和渲染注册，但其位置表现由轨道状态驱动。

### 3. 严格分离模拟状态、权威样本和渲染状态

客户端为每枚弹维护三类状态：

```text
simulationState      本地按轨道/事件重建的逻辑状态
authoritativeSample  最近收到的服务器样本或事件锚点
renderState           仅供 renderer 使用的连续表现状态
```

普通位置包只写 `authoritativeSample`。它不得直接调用 `setPos` 改写模拟起点。渲染状态可以在可信误差范围内平滑追赶，真失步时由轨道快照/事件重新建立，而不是用一帧硬拉回继续运行。

这比单独把位置写入渲染字段更严格：渲染纠偏不能改变速度、命中扫描、寿命、分裂守卫或下一次相位估计。

### 4. 不可预测变化使用单调事件序列

轨道只描述纯函数能够重建的部分。改向、目标切换、目标永久丢失、分裂、阶段变化、提前销毁、激光长度权威更新等行为发送事件，事件至少包含轨道/弹幕身份、服务器时间、单调序号、事件类型和参数。

客户端必须按序号幂等应用事件：重复事件不重复生成子弹，旧事件不得回滚新状态，缺号时请求或等待新的轨道快照/关键帧。事件时间用于重放，不能简单按网络到达时刻立即改变表现。

选择事件而不是持续同步目标位置，是因为事件数量与行为变化数量相关，而不是与弹幕存活 tick 数量相关；同时可以明确哪些状态不再声称是纯函数确定性的。

### 5. 非确定性弹幕使用关键帧降级，不使用无限相位外推

灵符目标跟踪、依赖服务端方块裁剪的激光长度和服务端临时改向等状态，不满足双端逐位确定性时，使用低频关键帧或事件。关键帧包括服务器时间、位置/方向、必要的阶段状态和序号；客户端在两个可信关键帧间只做受限插值/短时预测。

`L_hat` 或 EMA 相位估计只能作为渲染层的受限辅助，并必须满足：误差在可解释窗口内、连续样本稳定、轨迹切线一致、无缺失事件、未发生硬失步。任何条件不满足时进入 `UNCERTAIN`/`DESYNCED`，不得继续扩大外推。

### 6. 实体生命周期采用快照和序号闭环

开始追踪时客户端先获得实体/轨道快照，再获得时间锚点和事件状态；如果包处理时实体尚未注册，必须按身份暂存，而不是静默丢弃。实体重新出现时，重复的快照/年龄信息只能刷新尚未初始化的状态，不能无条件重置正在运行实体的时钟。

客户端实体移除、轨道结束和服务器销毁事件必须清理所有待处理样本、事件和渲染状态。未知实体事件不得创建没有对应服务器生成记录的幽灵弹。

### 7. 服务端权威逻辑与客户端表现分层

服务端继续运行真实碰撞、伤害、分裂配额、生命周期和区块/方块判定。客户端可以运行同一轨道函数用于表现和诊断，但客户端命中结果永远不改变服务端状态。服务端销毁或事件序号推进后，客户端必须停止旧轨道，即使旧实体仍有本地渲染缓存。

### 8. 兼容与渐进迁移

旧实体 NBT 和旧网络字段继续可读。旧存档中没有轨道状态的弹幕进入兼容模式：先按现有实体同步恢复，再在下一次服务器快照时转换到新状态；兼容模式必须被诊断标记，不能假装拥有确定性轨道。

迁移顺序为：先建立诊断和纯函数轨道接口，再分离客户端状态，然后接入时间锚点和事件，最后把编队/确定性发射路径切到轨道级同步。候选 C 不作为前置步骤。

## Risks / Trade-offs

- [Risk] 轨道快照协议和事件序列增加了协议状态复杂度。→ 为每个轨道使用版本、序号、生命周期和快照重置点，并覆盖乱序/重复/缺号测试。
- [Risk] 服务器时间估计本身会受网络延迟和客户端暂停影响。→ 使用低频锚点、受限漂移、单调性检查；时间估计只驱动表现，不驱动服务端逻辑。
- [Risk] 非确定性弹幕仍可能在关键帧之间短暂偏差。→ 限制预测窗口，超过窗口显示为等待/降级状态或使用最新权威样本，不无限外推。
- [Risk] 旧实体注册和原版 renderer 仍可能隐式读取 `Entity.position()`。→ 建立统一的渲染位置访问层，逐个审计所有弹幕 renderer、激光裁剪和包围盒。
- [Risk] 追踪范围不足会造成实体尚未创建而不是位置不同。→ 将可见性作为独立同步问题处理，调整追踪范围/轨道可见范围并补充进出追踪测试。
- [Risk] 事件与轨道快照的带宽在符卡切换或大规模分裂时出现尖峰。→ 使用批量轨道快照、索引化子弹和服务端预算；分裂事件在服务端先分配身份，再按批发送。
- [Risk] 浮点超越函数仍可能在不同客户端产生微小差异。→ 确定性轨道使用项目允许的数值纪律；对于必须使用超越函数的运动归入关键帧模式，不宣称逐位重建。
- [Risk] 复杂迁移可能短期同时存在旧位置包和新轨道协议。→ 以每实体同步模式标记能力，单一模式拥有位置/事件所有权，禁止两个模式同时改写模拟状态。

## Migration Plan

1. 增加轨道/时间轴纯函数和诊断模型，不改变现有运行行为。
2. 为客户端加入独立的模拟、权威样本和渲染状态，并让旧位置包先进入样本层。
3. 增加服务器时间锚点、轨道快照和客户端待处理包缓存，验证实体重建、重新追踪和读档。
4. 将确定性编队与批量发射迁移到轨道级同步。
5. 将改向、分裂、激光阶段、目标丢失等行为迁移到事件序列或关键帧。
6. 以延迟、抖动、丢包、重排、暂停、区块卸载和跨区块追踪场景进行实机验证。
7. 保留兼容模式和诊断开关；若新协议发现问题，可按同步模式回退到旧路径，不回退到同时驱动同一状态的双重路径。

## Open Questions

- 轨道协议是继续复用现有实体生成包，还是新增专用轨道 payload 并让实体只作为视觉实例？优先保留实体兼容，但需要实测包量和生命周期复杂度。
- 客户端服务器时间锚点采用 `gameTime`、相对 tick 序列还是自定义单调 epoch？需要结合暂停和单机内嵌服务器行为验证。
- 激光长度变化是否全部事件化，还是仅对方块变化发送关键帧？需要根据激光数量和方块变化频率测量。
- 对未知事件缺号时，客户端应请求局部快照，还是等待下一次周期快照？需要与现有网络基础设施和服务器负载目标结合。
