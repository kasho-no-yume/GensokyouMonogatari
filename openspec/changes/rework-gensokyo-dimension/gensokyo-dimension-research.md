# 幻想乡维度技术调研与八区地形草案

面向 Minecraft 1.21.1 / NeoForge 21.1.248。地理方位、尺度与素材分布按草案审阅结果采用；建筑阶段沿用本期预留的地块。

## 岛屿布局与世界生成

- 固定一座主岛、八块地理分区和八块地标预留地。布局原点为 `(0,0)`，主岛设计包围盒约 `8,192 × 8,192` 方块（`-4096..4096`），双轴环绕周期约 `12,288` 方块（边界 `-6144..6144`）；后续按生成样图只调整岛岸细节，不改变已公开锚点。海拔细节、植被、矿脉随种子变化。按需生成这座岛，全岛包围盒约含 26 万个区块。
- 用一份有限的二维布局描述海岸、八区边界、山脊、河谷、雾之湖盆地和地标锚点。保留跨区域的山脉和河流，分区边缘用高度与植被渐变衔接。雾之湖是红魔馆范围内的内陆湖，仍属于该群系。每区的连通性以地表陆地为准，用原版群系的四方块分辨率与实际地表共同核验。大陆能走通，各区又能各自连成一片。
- 自定义 `BiomeSource` 按 X/Z 查布局，自定义 `DensityFunction` 或等效地形控制使用同一张布局，约束高度、湖床与海底。先沿用 `minecraft:noise` 的区块生成流程，将主题方块分层、植被和矿脉留给 surface rules 和 placed features。原版洞穴、含水层和矿脉需要按区域约束，确保岛外没有露出海面的陆块，预留地也没有洞口或涌水。若局部地形经原版噪声流程难以控制，再评估自定义 `ChunkGenerator`。
- 本机 NeoForge 源码核对了 `BiomeSource`、`DensityFunction` 的 codec 接口，以及 `BIOME_SOURCE`、`DENSITY_FUNCTION_TYPE` 的内建注册表。`CommonModLoader` 在解冻注册表后发 `RegisterEvent`，随后重新冻结。首个原型应通过注册事件验证 codec 的启动、数据包解码与重启读档。原版 bootstrap 会冻结注册表，构造器里的直接注册不适用。
- 维度 ID 沿用 `gensokyou:gensokyo`。既有存档已生成的区块会保留旧地形，与后续新区块可能断层。单岛与八区验收用新存档，旧幻想乡区块的兼容方案另行评估。

### 候选区域关系

```text
                            北
                    守矢神社 · 山与湖
           白玉楼 · 白樱台地       红魔馆 · 雾之湖
           魔法森林                人间之里        博丽神社 · 东侧丘陵
           地灵殿 · 裂谷与地下空腔   迷途竹林
                            南
```

人间之里作为岛心低地。博丽丘陵朝内陆缓降到村外，给首次入境玩家一条容易辨认的路线。魔法森林、竹林分别提供浓密横冠和高细竖线两种景观。守矢在远处形成主山轮廓，白玉楼以阶状白色台地形成第二处高点。

博丽庭院落点使用博丽锚点 `(3072,128)`，安全地表目标高度 `Y=96`，保持脚下实地与至少两格净空；入口朝向岛心（西）。孪生门中心为 `(3088,128)`，与落点同一预留地且不占庭院中心。以上坐标是跨种子固定地理契约；高度与坡度约束优先于当地随机地形，锚点周边装饰不得侵入预留范围。

创造模式提供一张幻想乡群系地图道具供调试。地图从世界生成使用的布局绘制全岛俯视图，用颜色和图例显示八区边界、名称及外侧的三途川。新存档里可以直接查看尚未探索的区域。

三途川是第九个群系 ID，覆盖主岛外海。近岸是灰砂浅滩与少量彼岸花，向外过渡成深色水域。环绕线两侧使用同水位、同水色、同雾效与匹配的海底，避免在接缝附近布置可远眺的独特景物。各区的辨识度优先来自山势、树冠和地表材质，隔开雾效后仍应看得出差别。

大面积实体方块优先使用幻想乡的通用岩石、深层岩、灵草表土、腐殖层和三途灰砂。让区域共用基础岩土，再加各自的代表性岩层或植被。水、冰、雪、竹子等可复用原版，评估方块占比时分别看陆地地表和地下主体，避免海水体积掩盖实际观感。灵土有耕种价值，适合斑块分布。星银矿可用矿石特征替换指定的幻想乡岩石，再按原有配方精炼。自然获取密度需结合现有仪式产出和养成进度评审。 [素材与精炼规范](../../specs/gensokyo-materials/spec.md)

自定义地表需要实测竹子、生物和树苗的放置、存活与生长条件。神树可由神木材与树叶组成专用树形。遇到原版特征依赖方块标签的情况，优先补齐幻想乡岩土类型的标签并验证结果。

## 三途川如何环绕

把正方形地图的东西边和南北边分别接起来。比如向东过界时，X 减去整幅地图的宽度，Z 和航向保持原值。高速过界保留越界距离，擦过角落时同时处理双轴。数学上这是环面。东西向或南北向从陆地出发、沿原航线一直走便可绕回陆地。某些在外海开始的航线会一直错过主岛。若设计目标是任何海上出发点和航向都能抵岸，就要额外设计航路引导或定向送回岸边的规则。

先做同维度的服务端位置同步，临近接缝按需准备目标区块。区块准备和发给客户端是两件事，专服原型要检查位置跳转后有没有空白区块。1.21.1 的客户端位置包处理对绝对坐标轴会清掉该轴速度，航速需要专门恢复并验证。乘船要把船、驾驶者和乘员作为一个整体同步。测试覆盖四向、斜穿角落、来回过线、船与飞行、低视距、联机延迟，以及目标区块尚未生成的情况。

第一版可用外海薄雾和相似的海面把换边藏起来，验收重点是没有维度加载画面，方向和速度连续，船与乘员一起抵达。若要求在接缝两侧都能直接看见、交互和建造，还需同步两侧的区块与实体并协调客户端渲染、碰撞和坐标。仅靠服务端瞬移无法达到这一档体验。地图模组和 F3 坐标也会看到实际位置的跳转。

## 博丽庭院出生点与八个地标

将博丽庭院中心定为固定锚点，博丽群系完整包含庭院、缓冲地与进入地块的缓坡。生成时固定该小块地形的高度和坡度，并约束树木、洞口和水体。入口落点用确定的脚下高度、上方空间与朝向，孪生隙间用庭院边缘单独的固定门位。建筑阶段可在同一坐标用结构标记补上落点和门位。入境使用入口逻辑，死亡后是否回庭院是单独的复活规则，草案按保留现行复活行为处理。

每区登记一个地标锚点和一块地形预留范围。建筑阶段按那一个锚点确定性放置对应地标，分区里的村庄、神社等用结构整体计一次。当前验收检查预留地适配性。以后做结构时再检查重复加载、交错生成和跨区块放置下全维度各地标仍只出现一次。

## 原型验证顺序

1. **布局与 codec。** 在新世界用最少的占位材质加载幻想乡，验证专服及单人能够启动、进入、重启和读档。导出多种子的群系与高度俯视图，核验一块主陆地、八个非空且各自连通的陆地区域，以及八处锚点位置与庭院坡度。
2. **海上接缝。** 用缩尺海域测四边、角落、双人同船和飞行。记录目标区块加载、可见空白、速度变化和专服卡顿，再确定环绕边界的制作规格。
3. **地形走查。** 每区挑三类观察点，远景看轮廓、边界看过渡、内部看材质和路线。检查博丽落点和隙间往返、雾之湖水位、地灵殿入口，以及自定义地表上的竹木和矿脉。

### 2026-11-22 首轮区块验收记录

- 在隔离的专服新存档中对种子 `424242` 与 `987654321` 加载并生成幻想乡区块；两次都通过自定义群系源/地形 codec 加载。
- 两种子均核验八个地标坐标的目标群系、干燥地表，另检查红魔馆范围内的雾之湖、岛外三途川群系和水体，以及地灵殿入口竖井。
- 生成图像为 256×256 预览，地形高度取每个采样格中心实际生成区块的海床高度图；群系图直接取共享布局（不依赖探索状态）。图像保存在变更目录 `evidence/`。
- 海床高度与局部噪声会随种子变化；各区布局和预留地坐标保持固定。用 32 方块采样的共享布局测试确认八区非空且各自连通。预览图是布局验收采样，不替代高分辨率全岛联机走查。

### 2026-11-22 隙间重复生成修复

- 症状由孪生门维护的高度图搜索引起：搜索不优先复用已存在的门块，维护路径又将新门按完整生成流程初始化；门块可能令后续搜索偏移到相邻格，重复补门并重播生成表现。
- 现在先在庭院门位周边查找既有孪生门，复用唯一门位并清理附近重复门；安全地表搜索遇到门块时直接返回。修复缺失门时瞬间初始化为已开启状态，不触发召唤粒子/音效；初次仪式开门也不再发生成音效。
- 专服探针在庭院锚点放置两块测试隙间后运行定位，验证最终仅剩一块且返回锚点。每次正式进入/退出的手动联机体验验证仍待完成。

审阅时可优先看八区相对位置与陆地尺度、白玉楼和地灵殿如何融入同一大陆、三途川接缝的观感，以及星银矿等素材能否作为进入幻想乡后的自然收益。本文结论来自仓库配置和本机 1.21.1 / NeoForge 源码核对，实机表现等待原型验证。
