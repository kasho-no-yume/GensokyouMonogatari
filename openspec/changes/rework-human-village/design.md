# Design: 人间之里聚落与生活地表（2026-11-26 修订）

## 1. 目标与反馈

依据 `问题记录.txt` 第 2～4 条及用户补充：聚落应分布在人间之里群系的大部分可建区域，向中心变密；建筑组团之间留出的空地形成街巷；以黄褐色生活土面为底色，局部嵌石板。保留已有四大地标、装饰与十套町家 NBT/GLC3，不重画已交付建筑。

第一版的固定半径 200、220 格边缘禁建、26/24/12 栋配额和逐户正交 A* 接路不再是当前约束。完整历史与 GLC3 格式见 [design-v1.md](design-v1.md)。

## 2. 群系范围与密度

`VillageSettlementField` 在主岛范围以 64 格步长采样实际 noise router 持有的 `GensokyoLayout`，通过距离变换得到粗略群系内部距离。房屋地块还需检查外扩 64 格后的九个位置都属于人间之里；这是一项采样保护，不能称为精确欧氏边界距离。

归一化外向程度 `t = radius / (radius + sampledEdgeDistance)`，中心趋近 0，群系边缘趋近 1。房屋不再被限制在中心小圆内。按错列且平滑偏移的候选组团生成，组团还带独立的稳定种子抖动：

| 分区 | 条件 | 每侧候选房屋 | 共享空地基准宽度 |
|---|---|---|---|
| 内区 | `t < 0.38` | 3 | 4 格 |
| 中区 | `0.38 ≤ t < 0.72` | 2 | 6 格 |
| 外区 | `t ≥ 0.72` | 1 | 10 格 |

组团内两排房屋朝向共享空地，门脸可小幅错位。共享空地两端开放，放屋前先预留，门外锚点也受后续建筑避让。占地与四角高度仍检查，超过 2.5 格高差的地块跳过。全村最多 8192 个建筑实例；超过预算明确拒绝，不静默只生成某一侧。实际数量、覆盖率和观感需后续验证，不预报一个未经运行的实测栋数。

`OccupancyGrid` 用按需分配的 16×16 稀疏区块桶，避免分配整岛密集网格。地形保留中央及稗田固定台地，外围使用低频缓坡，未把整个群系压成一个平面。人间之里群系移除 `sacred_grove`，保留模板庭树；完整土面通过净空过滤器拒绝植被/土壤斑块覆盖，外围草地斑块仍可有灌木和花草。回归目标还要求可建地采样点至少 65% 在住宅 96 格范围内，避免仅靠增加少数远方房屋通过范围检查。

## 3. 完整体地表 landmark

新增 `gensokyou:landmark_packed_earth`（夯实村土）：

- 普通完整立方体，自带最终黄褐色 16×16 顶/侧贴图，顶面有四向随机旋转。
- 与建筑 landmark 一样不可生存破坏、防活塞、无物品形态、无掉落；整地器不能铲除。
- **不**注册到 `tintedBlocks()`，模型无 `tintindex`，不需要 GLC2、GLC3、实例或坐标颜色查询。
- 地形 surface rule 在人间之里替换干燥表层一格，下面仍是幻想土/石；低 surface noise 留少量草地斑块，陡坡仍可露石。
- 核心演出留白及未铺石的门前地面明确使用此方块，保证可落脚；普通外围地表由 Worldgen 自然产生。
- `ResidentGround` 明确接纳此 ID，仍检查加载状态、真实碰撞、流体和头顶净空。

贴图源为 `tools/textures/landmark_packed_earth.py`，经现有 ASCII 贴图工具生成。灰模建筑和博丽地标的既有染色管线不改格式。装饰石板与桥栏在原核心盒及已同步村庄建筑的相邻区块内继续用程序化兜底色，不为整岛无关 landmark 启用兜底；不再沿十字轴生成深色边石。

## 4. 空地、装饰铺装与桥

`VillageRoadRouter` 保留类名与旧存档枚举值以兼容，当前职责是公共留白、门前小铺装和必要桥梁：

1. 固定核心保留原 116 个表演槽位需要的通行空间，默认材质改为 `EARTH`。这些预留格不再表现为十字石板大道或完整矩形石环路。
2. 不为外围住宅寻找一条通往中心的铺装支路，不运行旧 A* 或距离场。
3. 每个入口最多处理门外 3×3 小地面；特殊地标和约五分之一普通住宅使用石板，其余为土面。模板本体不被覆盖。
4. 跨溪保留必要桥梁，桥下水源连贯；不将水面铺成土。
5. 只在已有公共节点/桥附近保留必要家具，不为整个新区按固定间隔布满路灯。

`VillageWalkability` 对建筑矩形和水面之外的**全部留白**做按需平面洪泛，检查入口可达；石板是否连续不是通行条件。此诊断不模拟三维地形、精确模板内通道或玩家身形，不能代替实机步行。`stats` 显示“平面入口可达率”，不得再显示为实际道路连通率。

## 5. 高度与固定地标

密度地形的 `surfaceHeight=72` 是实心/空气分界，高度恰为整数时最高实心块为 71。因此 v2 的普通核心土/石地面块在 **Y=71**，脚底为 **Y=72**。外围地板用 `ceil(averageSurfaceHeight)-1` 估计表层，并在建筑占地内整地、补地基；仍需真实区块核对噪声和边界的细小误差。

已有模板的固定世界最小角在 v2 统一下移一格，水平位置与旋转保持不变：

| 模板 | v2 最小角 | 原始尺寸 | 旋转 |
|---|---|---|---|
| `hv_dragon_plaza` | `(-214,70,86)` | 29×16×29 | NONE |
| `hv_hieda_residence` | `(-238,74,-44)` | 76×28×64 | NONE |
| `hv_suzunaan` | `(-253,71,114)` | 38×26×34 | NONE |
| `hv_geidontei` | `(-148,71,164)` | 42×29×36 | CLOCKWISE_90 |
| `hv_kourindou` | `(-364,71,60)` | 44×25×36 | NONE |
| `hv_gate_east` | `(-78,71,91)` | 14×12×19 | NONE |
| `hv_gate_west` | `(-316,71,93)` | 10×11×15 | NONE |
| `hv_gate_north` | `(-207,71,-74)` | 15×11×10 | NONE |
| `hv_watermill` | `(-182,69,156)` | 12×13×12 | NONE |

普通桥面实心块在 71，河心底半砖在 72（脚底 72.5）。溪水仍在 69、70，护岸顶仍为 71。东口在同一表层替换土面，v2 不再用额外一格高的村道加接缝楼梯。v1 仍保留原有高度和接缝处理。

## 6. 居民

核心 JSON 保持 116 槽位及原始脚底原点 `[-200,73,100]`，供旧世界继续使用。客户端读到 v2 布局后统一将核心活动点降低一格；布局更新时清除旧 walker，防止沿用旧高度。资源包替换这一场景时也遵循同一基准。

用户后续实机确认房屋数量增加，但行人仍少。本轮取消“一户一个点、三分之一只走三格”及核心 240 格排除，改为围绕观察者的兴趣点补充街巷人流：

- `VillageResidentAnchors` 只保存区块化建筑描述。按需查询附近门前、街巷、广场和地标外围；核心编排路线也提供兴趣点。三格空间键去重并稳定外观，不在全村预建居民槽位。
- `ResidentStreetCrowd` 每 40 个未暂停的本地 tick 或玩家水平移动 8 格刷新一次兴趣点，源点限 72 格；每 tick 最多 48 次地面探查，已核验的附近路线最多缓存 384 条，离开 96 格回收。
- 约八成动态候选尝试 8～16 格行走路线，必要时缩短至至少 4 格；每半格检查支持、半格高差和扫掠碰撞，允许部分路线转弯，共线节点压缩后最多 16 点。其余候选驻足。动态行速为外观基础速度的 1.25 倍，节点暂停最多 12 tick；核心编排节奏不改。
- 只读取客户端已加载区块，使用客户端确实收到的 `MOTION_BLOCKING` 高度图。房屋内部整块排除，广场/冠木门仅允许低层公共地面，避免把 roof height 当成活动地面；仍执行真实碰撞及 landmark 支持面验证。
- `ResidentPopulation` 在几何检查后才占名额，每 tick 最多 12 次补入尝试；坏点短暂退避、后备点继续补位，避免最近无效点挡住后续居民。有效 walker 保留身份、位置和进度，离开 96 格后不再 tick。动态新居民避开玩家 8 格及已有居民 1.2 格范围，减少贴身刷新与初始堆叠。
- 核心与动态人流共用 **96 人、96 格**活动/绘制上限，当前附近候选总数仍限 512。保留现有共享模型/贴图/批次、视锥剔除和远处细节简化，不新增居民网络包或服务端状态。96 人以内的实际帧耗仍待硬件采样，不推断为已通过。

土面也可支持正式居民，但自然草地仍不能。外围活动点仍可能被草斑、障碍或未加载区块拒绝，不能绕过安全检查硬显示。重连、切维度清理实例索引；资源重载清理旧 walker，保留当前世界有效的房屋描述。

本轮人流也适用于已有 v1/v2 合规村庄，不修改建筑、路格、地形或网络格式；更新客户端并重新进入即可，不要求为这项居民调整新建世界。

## 7. 放置、网络与存档

`HumanVillagePlan.layoutVersion` 和 SavedData 写入 v2。读 v1 时保留原建筑、路格与完成进度，不重新求解、不搬家、不自动覆写已生成区块。旧的四个 RoadType ordinal 保留，`EARTH` 追加在末尾。

服务端按建筑覆盖区块建立索引，模板检查、放置、进度更新、保护判断仅访问相交建筑。只对有建筑、小铺装或核心溪流的已加载区块排队；每 tick 最多处理两个，模板仍按当前区块裁剪，禁止因建筑一角被加载而加载其他区块。v2 不再逐列装箱保存建筑保护集合，保护直接查询区块内建筑边界。

布局同步增加布局版本，模板字典与 ZigZag 坐标编码保持；实例上限同步增加至 8192。快照测试预算改为 256 KiB，必须后续实际运行确认，不沿用第一版 2～3 KiB 的结论。网络格式改变，需要服务端和客户端使用同一模组版本。

**体验新版完整结果应使用新测试世界。** 已有村庄仍读 v1；新的地表规则仅对新生成地形生效。不得通过删用户存档或强制覆盖来展示新版。

## 8. 验证与剩余验收

维护回归覆盖：多种子分布范围/绝对覆盖与梯度、建筑分离/河道避让、门外平面可达、局部铺装不再形成逐户长支路、完整快照往返、v1/v2 存档、核心路线降低一格及外围门口旋转。

本轮仅做廉价静态检查、资源引用检查及贴图源/成品核对。编译、JUnit、原生服务端探针、客户端性能和观感未执行，不能引用第一版测试报告代替新版通过。

后续新世界走查重点：从边缘进入聚落时连续遇到建筑；内区街面足够紧凑；共享空地转折自然；土面/石板/门槛齐平；高台、桥、溪岸和四大地标实际可达；外围居民正确出现；重连染色与低视距分片无回归。保留视觉验收未完成状态。
