# 现有符卡消费矩阵

此文件是实际路径审计及新版消费契约，不表示执行器已接入。全部增幅在服务端施放时取样，写入宿主/附件的具体数值，不在每次伤害或读档后重新读取装备。道具形态只使用固定品质参照，不吃玩家增幅、减耗、CDR或持续属性。

最新用户确认优先于下表旧候选“防御容量域”字样：不新增该域。护盾次数作为效果量吃符卡强度，并可设最终硬上限；护盾时长允许延长。每个参数明确列出增幅域，其他参数固定。参数最终上下限、卡片最短冷却均可选，默认无额外限制；启用后增幅不能突破，在指导书记载。具体上限须依据2～8次受击目标校准，不能从示例3次直接当作最终决定。

## 共通规则

- 已学形态所有有效卡：在实际施放入口扣除固定阶级基准成本×(1−减耗)，成功施放时确定冷却base×(1−CDR)，至少1tick。失败零效果、零消费。
- MobEffect的普通buff_extend只处理普通状态，不对已经处理过符卡持续的同一参数再乘一次。
- 同种增幅的各来源先平加再应用一次，不按装备来源额外连乘；伤害增幅不扩大治疗，防御增幅不等同全伤免疫。
- 用户已确认旧spell_amp保留原ID与值作为遗留通用增幅：仅旧治疗/召唤消费点继续使用，分别受分类合计上限，不复制两条、不增防御用途；新版池只投分类ID。旧记录无需随机或数值转换。
- 学习数量、固定早期卡、具体卡的功能重做不在本次范围；本矩阵不代表这些入口已兑现。

## 验收必须报告的交付差异

1. 环绕玉同tick多次hurt、狐召唤同目标多实体hurt，是否被无敌帧截断；理论请求伤害不能冒充实付伤害。
2. 治疗场多人重叠去重，最强/最弱场遍历顺序不影响结果；不跨世界存静态强引用。
3. 读档后宿主数值与到期保留；重登/换装不能让同一个参数再次增幅。
4. 最大持续/CDR下的有限存量与实际性能，不以“有限”代替“预算内”。
