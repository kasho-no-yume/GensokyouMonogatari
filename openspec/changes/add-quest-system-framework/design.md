# Design: 可扩展任务框架与阿求委托测试入口

## Context

- 项目总纲把“已学符卡仅能经幻想乡任务习得”列为规则，但完整主线剧情仍是非目标；阶段 D 只规划后续委托扩展。
- `TouhouNpcEntity` 已有服务端权威对话与交易入口；对话按玩家维护会话。
- NPC `!/?` 目前是实体级同步数据，无法表达同一 NPC 对不同玩家的不同任务状态。
- 人间之里已有固定的 `hv_hieda_residence` 地标。周边人群是客户端表现；具名任务发布者必须作为独立服务端 NPC。
- 项目已有可序列化玩家 Attachment、世界 `SavedData`、数据包 reload listener、Screen 和屏幕投影渲染的实现范式。

## Goals / Non-Goals

**Goals:**

- 用一套任务生命周期承载主线、支线、委托；明确任务类别与进度归属不是同一个维度。
- 支持单阶段委托与多阶段任务，任务目标类型可扩展。
- 正确区分存档级共享主线进度和玩家私有支线/委托进度。
- 提供委托书任务日志、单项追踪、屏幕空间导航标记及阿求处接取/回报入口。
- 用不带正式剧情含义的测试内容覆盖任务链路。

**Non-Goals:**

- 编写或启动真实主线；只有共享进度模型与显示接缝。
- 定义委托从哪里来、何时刷新、是否每日、如何随机或数量上限。
- 本轮设计真实任务文案、经济数值、正式符卡奖励或制作目标。
- 地图 UI、地图 pin、玩家小队/协作任务、多人共享支线/委托。

## Decisions

### D1 任务类别与进度归属分离

任务定义包含类别与进度范围两个字段：

| 类别 | 本变更支持的进度范围 | 语义 |
|---|---|---|
| 主线 | 世界共享 | 同一存档最多一个当前主线阶段；完成/推进对所有玩家一致 |
| 支线 | 玩家独立 | 每名玩家独立接取、推进、回报，可同时持有多条 |
| 委托 | 玩家独立 | 固定单阶段、无子任务链；通常一个目标，接取和回报发生在发布 NPC |

非法类别/范围组合在加载定义时拒绝并报告，不静默转换。主线内容未在本变更中注册；世界共享状态接口由服务端存档数据承载。每名玩家仍可单独选择是否追踪当前共享主线，不改变其共享进度。

共享主线定义按有序任务 ID 序列组织，展平为唯一的线性阶段序列；世界 SavedData 保存单调递增的主线阶段游标及当前阶段目标进度。阶段完成后游标推进，最终阶段完成后进入下一主线任务；本变更不提供实际主线序列或内容。主线不介入个人奖励分配，主线定义的个人奖励必须为空；材料目标只检查或扣除当次有效交互玩家的背包，不聚合全服背包。

任务簿显示当前世界主线（若存在）以及该玩家已经接受、尚未最终完成的支线/委托。主线不需要由每位玩家重复接受；已完成并领完奖励的个人任务不再列为“当前已接受”。

### D2 任务定义、实例与目标扩展

任务定义使用稳定 namespaced ID，数据包含类别、进度范围、线性阶段、阶段目标、奖励、发布/回报 NPC 及可选导航目标。内容由服务端资源数据加载；目标使用 namespaced 类型 ID + 类型专属 Codec/处理器，不把目标种类硬编码进任务主状态机。

任务定义和一次接取实例分离：个人任务进度以定义 ID + 实例 ID 标识；将来同一委托定义可再次发布时，不会与旧实例的进度/回报状态混淆。委托定义 SHALL 恰有一个阶段且 MUST NOT 链接子任务；阶段内可有多个并行目标，以支持“击败 N 个”等数量条件。当前静态测试提供源不实现重复发布或刷新。

阶段按顺序推进；单个阶段可含多个并行目标，默认全部完成才进入下一阶段。阶段必须至少包含一个显式目标，客户端不得请求跳过阶段。任务状态最少区分进行中、待回报、完成；具体状态由服务端维护。目标一旦完成即锁存，已完成阶段和待回报任务不因后续库存或世界状态变化退回未完成。

本轮内建目标：

- `have_items`：服务端检查玩家当前背包持有数量；不是制作判定，已持有的材料在任务接受后第一次检查时可满足条件。一旦达到所需数量即锁存完成，之后丢弃、转移或消耗材料不取消资格，持有目标本身不扣料。
- `submit_items`：目标独立配置收件 NPC，与任务奖励回报 NPC 分离。玩家通过收件 NPC 的任务按钮交付；服务端先校验该次全部提交目标的材料，再一次性扣除和推进，避免部分扣除或重复提交。收件人与领奖者相同时允许一次操作同时上交和领奖；收件人不同则先交付、完成其余目标后回指定回报 NPC 领奖。
- `kill_entities`：只计入任务实例激活后、可归因到该玩家的击杀；不回溯接受前击杀。
- `talk_to_npc`：必须绑定稳定 NPC 角色 ID 和对话动作 ID，只在任务目标激活后，玩家点击有效服务端对话会话中的对应按钮才完成。右键打开对话、翻页、取消或选择“否”均不完成；对话选项可提供任务动作以表达“是否准备好开始学习”等确认。新阶段不能复用刚刚用于推进旧阶段的同一次按钮事件。

未来新增目标只需提供其数据解码、事件/状态判定、进度表示和可选导航目标解析；任务日志、追踪与任务生命周期不因新增目标种类改写。探索目标不在本轮实现，且将来按“接受后新触发”语义设计。

### D3 持久化及服务端权威

- 世界共享主线状态保存在存档级 SavedData；单人世界、多人服务器和重启后指向同一个主线状态。
- 玩家个人接受实例、进度、待回报奖励状态及当前追踪项保存在玩家持久数据中，死亡后保留。
- 任务定义和所有进度转移由服务端决定。C2S 只传稳定任务/实例 ID 与请求动作；服务端重新检查任务是否可接、回报 NPC/距离、目标完成条件、奖励状态及追踪资格。
- 接取、目标推进、阶段转移、材料消耗、奖励领取各自保证幂等；重发网络请求不得重复扣料或发奖。
- 普通死亡、退出重登、服务器重启和存档重载均保留个人任务与主线进度。这里的资源热重载专指服务端任务资源再次加载（如 `/reload`），不包括普通启动加载或客户端材质重载。
- 主线热重载保留线性阶段游标，按新序列显示该阶段；已越过的阶段不重新激活。当前阶段定义变动时允许重建该阶段未完成目标进度；游标超出新序列或资源缺失时保留游标并诊断，不夹回早期阶段。
- 支线/委托热重载允许清除，不做定义快照或迁移。使用持久的个人任务资源代次失效旧实例及其追踪，覆盖在线及离线玩家；普通服务器重启不增加代次。

### D4 委托书及阿求交互

委托书是打开任务日志的入口，不承载任务进度；丢失、复制或换手道具都不改变玩家数据。任务日志按主线、支线、委托分组，只呈现当前已接受内容（共享主线存在时对所有人显示），不显示未发现、未接受、已完成归档或锁定条目。每项显示标题/说明、当前阶段、目标进度、已知奖励和追踪状态。

阿求交互展示“可接取测试委托”“材料交付”和“已完成待回报”操作。未接受委托不进入委托书；测试委托只有通过阿求交互才能接受或领取，目标材料可依定义交给其他 NPC。所有 NPC 的对话可展示该玩家当前阶段绑定的任务对话按钮或材料交付按钮。本轮的提供源是静态测试集合，不以每日任务/随机刷新/定时轮换实现。

委托可接取列表由独立的任务提供源提供；任务运行时只校验提供源给出的可接取实例，不拥有每日/定时刷新器。这样后续可以接入不同 NPC、世界事件或轮换策略，而不改变任务实例和目标处理。

奖励领取使用服务端事务：只有任务处于待回报且玩家在配置的回报 NPC 有效交互中才可领取。上交同时领奖时先在库存副本上校验扣料后的全部奖励容纳空间，再提交库存和任务状态；空间不足不扣料、不关闭任务。异地上交后领奖失败不会撤销已完成上交。成功后记录已领取并关闭该任务实例。测试奖励只用于证明通路，不定义正式经济或学卡规则。

### D5 单项任务追踪及导航 HUD

追踪状态是每位玩家自己的单选字段。选择另一任务会原子替换旧追踪；取消追踪可为空。追踪只选择任务，不代表任务接受；无导航目标的任务仍可追踪并在委托书显示进度，但不绘制方向标记。

导航目标与目标完成条件分离。当前阶段可选一个目标解析器（固定世界位置或实体锚点）；HUD 只显示当前追踪任务当前阶段的导航目标，不为多个阶段/目标同时画标记。

进入待回报时，导航自动覆盖为奖励回报 NPC；成功领奖后清理该实例的追踪。NPC 未加载时固定驻留角色可用已保存建筑锚点解析位置；不强行加载目标区块。

标记使用屏幕空间渲染而非世界空间实体/几何：按相机视线投影目标方向，固定 GUI 尺寸，绘制在 GUI 层，因此不随世界距离缩放、不受深度测试/方块遮挡影响。目标位于屏幕外或相机后方时将方向指示钳制到屏幕边缘；同时显示到目标的方块距离。接受、追踪、阶段推进、目标位置变化、完成/回报及维度切换均须更新或隐藏标记。

导航目标所属维度与玩家当前维度不同时，不推算跨维度方向；隐藏方向标记并在任务日志/追踪状态处说明目标维度。精确距离取三维直线距离，表示方向感知而非可行路径长度。

### D6 NPC 头顶标记按观察者计算

现有头顶符号仍是 NPC 的世界空间提示，与任务导航 HUD 分开：

- `!`：当前世界共享主线下一步明确要求与该 NPC 对话。
- `?`：该观察玩家有来自该 NPC 的可接取支线/委托，或有待在该 NPC 回报的任务。
- 无状态时不显示；同一 NPC 同时满足两类时显示 `!`，交互列表仍呈现全部可用操作。

客户端显示状态必须按观察者玩家同步/计算，禁止将个人任务状态写成 NPC 的全局 QuestMarker。阿求测试委托只驱动对应玩家看到的 `?`。

### D7 阿求固定驻留稗田居所

阿求注册为独立、持久的 `TouhouNpcEntity` 子类，固定在 `hv_hieda_residence` 内部的接待/居住区域，不纳入客户端居民人群。使用居所模板的固定局部锚点换算世界位置；锚点须在实现前通过模板/展示场景确认，不根据玩家或随机数漂移。世界坐标由已保存建筑实例的原点、朝向与布局版本换算，避免把 v1/v2 地标高度差或未来地标调整复制为 NPC 侧硬编码坐标。

已对实际结构 NBT 确认局部脚部块 `(38, 2, 12)`，实体中心 `(38.5, 2, 12.5)`、朝南（yaw 0°）：局部 y=1 为地板，y=2/3 为空气，前方书案侧通道通畅。v1/v2 使用相同局部位置，由保存的建筑 minY 决定高度；旋转同时作用于位置与朝向。

人间之里按 chunk 延迟放置建筑，阿求生成须挂接 `HumanVillageSavedData` 中稗田居所建筑实例的完整放置状态；不得因单个相交区块完成而提前生成。复用建筑实例 ID/完成状态与实体唯一性检查作幂等保护，不另建与布局进度重复的建筑状态。反向 chunk 加载、重启、v1/v2 布局及已生成居所的旧存档均须补齐且不得重复生成。使用项目现有 NPC 占位渲染路径，不要求本变更制作阿求正式模型。

补生成检查也覆盖已完成放置区块的再次加载。NPC 角色身份使用稳定角色 ID；实体 ID/UUID 只标识当前实体或会话，恢复流程更换 UUID 不改变任务角色。

### D8 测试内容范围

测试提供源只为端到端验证而暴露少量带“测试”标识的单阶段委托：覆盖接取、材料持有完成锁存、同地/异地上交、接受后击杀计数、指定对话按钮、奖励待领取/领取、返回领奖导航和追踪替换。多阶段支线与世界共享主线只用隔离测试夹具验证，不向玩家发布。测试内容不采用“每日”语义，不表示正式任务或最终文案/数值。

世界共享主线用隔离的自动化测试验证归属与同步，不向玩家注册或展示真实主线任务。

## Risks / Trade-offs

- [每玩家 NPC 标记会增加同步复杂度] → 用面向单个观察者的任务状态同步，不复用 NPC 实体级全局字段。
- [世界共享主线与玩家私有追踪看似冲突] → 主线进度在世界级，追踪选择在玩家级；不同玩家可独立决定是否显示同一个世界目标。
- [资源 reload 时任务定义可能改变] → 主线保留线性阶段游标；支线/委托按持久资源代次失效，普通重启仍保留。
- [同阶段多目标可能对应多个地点] → 每阶段至多一个导航目标，目标完成条件仍可包含多个并行项。
- [居所跨 chunk 分段放置] → 只在建筑完整后生成 NPC，并用持久幂等标记防重复。
- [跨维度目标无法给出真实方向] → 不伪造跨维度箭头，提示目标所在维度。

## Open Questions

当前无阻塞问题。任务簿使用 300×200、1 texel = 1 逻辑像素的樱符底图，由共享调色板与 ASCII 装饰生成；文字、列表、目标、奖励、交互控件与 HUD 均由 Java 绘制。
