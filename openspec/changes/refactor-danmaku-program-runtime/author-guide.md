# 先读这份：怎样用通用操作写弹幕

状态：**设计稿，尚未实现**。本文中的名字是拟定接口，不是可以直接调用的Java方法。实现清单以`tasks.md`为准；原子操作完整契约见`operations.md`，案例见`pattern-recipes.md`。

## 1. 六个概念，先分清

| 词 | 通俗解释 | 例子 |
|---|---|---|
| 程序（Program） | 一份可重复执行的表演说明书 | 先亮符印，再发三波，最后淡出 |
| 组（Group） | 一批共享运动或管理规则的弹；可以有子组 | 移动的龙卷风，内部三层旋转圆环 |
| 成员（Member） | 组内的一颗弹或一条激光 | 第3层圆环的第5颗弹 |
| 坐标帧（Frame） | 一个原点和三条轴，相当于局部坐标纸 | 以BOSS眼位为原点，朝玩家为前方 |
| 发射批次（Batch） | 同一时刻必须完整生成的一小批成员 | 一面18发的带门面板 |
| 分轨（Lane） | 作者用来标记颜色、职责和伤害的栏目 | 青色主阵、白色点名；不决定共享作用域 |

一个组可以发很多批，一批可以有很多成员；一个组也可以跨两个颜色轨。不要把这三个“集合”混成一个整数groupId。

“原子操作”是可独立复用的基础功能，例如直线运动、采样目标位置、结束一颗弹。“组合器”安排这些功能何时执行，例如顺序和重复。“宏”是常见操作的快捷组合，例如分裂=生成子弹+结束母弹，但有完整的失败与执行顺序约定。宏不是新的一套物理模拟。

## 2. 写一个弹幕，依次回答这些问题

1. **摆成什么样？** 选择球面、环、扇、方阵等图案生成器。它只给出局部位置、方向、编号和标签。
2. **谁整体移动，谁单独移动？** 整片推进写在组路径；每颗向外飞写在成员路径；允许两层同时存在，但要指定先后坐标变换。
3. **什么时候发？** 写明确的出生时间、次数和间隔，注明是卡时间、轮时间还是弹的年龄。
4. **发射点跟谁？** 出生位置快照、跟随确定性母弹、采样外部实体，是三种不同选择。发出后是否继续跟随也必须单独选。
5. **什么时候伤人、什么时候结束？** 可见不等于有伤害；静止不等于无害；停止发射不等于清掉旧弹。
6. **谁提供未知信息？** 玩家当前坐标、撞墙、被打掉等只能由服务端决定。之后双方拿同一结果各自计算。

默认操作参数没有暗含特殊表演：旋转贴图不自动旋转炮口；组缩放不自动放大判定；母弹消失不自动销毁所有已发出的子弹；BOSS动了不自动拖动已锁轴的图案。

## 3. 四种时间不能混写

假设卡从服务器tick1000开始，第二轮从1240开始，子组从1260开始，某颗弹从1270出生。在服务器1280：

| 时间 | 值 |
|---|---|
| CardTime（卡开始以来） | 280 |
| CycleTime（本轮开始以来） | 40 |
| GroupTime（该组开始以来） | 20 |
| MemberAge（该弹出生以来） | 10 |

蓝的“220收束”指CycleTime；“弹出生30tick后转弯”指MemberAge。不同出生时间的弹不能直接拿同一个age判断全卡收束。

`[20,40)`表示包含20、不包含40：20开始生效，40已经结束。所有端点遵守这个规则。`Wait(20)`只是让下一条指令晚20tick运行，不会让已经发出的弹停住；停住要写Hold。

## 4. 什么可以双方独立算

- 固定路径、旋转、减速、已知时刻分裂：规则和种子已知，可以独立求某一时刻的状态。
- 玩家当前在哪里、某弹是否命中、这次预算能否容纳新弹：服务端给结果，客户端不能自己猜成事实。
- 跟随一个普通Minecraft实体：客户端看到的实体位置可能滞后，必须采样服务器位置；不能当成确定性母弹。

“纯函数求值”就是：给同一份参数和时间，直接算出同一位置；不用先从第0tick跑到第200tick。“检查点”就是能恢复当前表演的一份完整存档快照；此处用于网络恢复，不代表BOSS弹幕要写入世界存档。

其他术语：codec=读写网络数据的规则；bounds=一个操作最多影响的空间和数量；epoch=这一场战斗的编号；revision=这份状态更新到第几版；mask=哪些成员还活着的紧凑标记；tombstone=已结束记录，防止迟到消息把它重新创建；closure/闭包=恢复计算所需的全部父组参数，不是任意Java回调。

## 5. 实现者的固定顺序

先建立能离线计算的操作与图案，再接服务端世界查询，最后接同步、渲染和碰撞。不得先写一个复杂实体tick，再用网络补丁试图让两边追平。

遇到新表演先查目录：已有操作可组合就写内容；缺一种数学路径就注册Path；缺一种空间排列就注册Pattern；需要当前世界事实就注册Decision。只有新的需求改变“如何组合或管理状态”时才讨论修改核心。

实施时必须维护可用操作台账：`planned`（仅设计）、`implemented`（代码已接入）、`verified`（必要测试通过）、`legacy-only`（只在旧后端可用）。**没有代码入口和验证证据，不能把planned改成verified。** 技能首页负责链接台账，不复制另一套可能过期的API说明。

## 6. 文件优先级与歧义处理

- `specs/`是验收约束；`design.md`说明架构；`operations.md`解释操作语义；`pattern-recipes.md`是如何组合的例子。
- 配方中的示例数值不是全局限制；48发是内容/预算问题，不是球面生成器数学上只能有48点。
- 发生矛盾必须同时修订相关文档，不能选择一个较好实现的版本悄悄做。开放参数不等于开放语义：性能阈值可实测调整，“是否继承母弹速度”必须由作者声明。
