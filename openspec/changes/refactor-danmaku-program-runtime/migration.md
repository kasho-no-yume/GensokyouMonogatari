# 迁移、旧规格交接与验收门槛

## 1. 分阶段交付

| 阶段 | 交付物 | 进入下一阶段的条件 |
|---|---|---|
| M0 基线 | 内容manifest、旧行为差异、性能/流量固定场景、命中依赖清单 | 能重放相同种子、目标动作和弹量 |
| M1 纯核 | 程序类型、操作注册、编译器、无世界轨迹/生命周期测试 | 任意时间求值、分段连续、组合探针通过 |
| M2 纵向切片 | 数据后端+协议+碰撞/渲染，蓝1/4/6、花海、尾珠 | 目标失效/取消/晚加入/延迟/清场正确 |
| M3 内容迁移 | 所有20张正式卡（3+4+8+5）与底噪 | 逐卡数量/时序/表现/多人测试通过 |
| M4 收尾 | BOSS旧路径退出，技能与主spec同步，测量报告 | 无重复判伤/逐弹网络流；预算与性能门槛通过 |

代码迁移期间按encounter选后端，不能一半卡旧一半卡新；影子后端只记录预测，不碰世界伤害。回退时先结束战斗再重开。M2通过前不大规模重写BossCards，以免组合模型未稳就制造第二批内容包袱。

## 2. 旧规范的适用域

本change为相关既有capability增加明确的“程序后端替代契约”。它们优先适用于 `DanmakuProgram` BOSS；旧条款继续约束未迁移的entity后端。归档时必须保留这一适用域，不能把旧规则和新规则同时应用于同一实例。

| 旧capability / 限制 | 程序后端替代 |
|---|---|
| track-composition：多拍一次性必须循环、一轨独立、四行为开关 | 显式Playback.Once/Loop/Stream；跨lane组和帧；类型化操作 |
| track-composition/pipeline：分裂可按剩余配额逐个生成 | 新backend以batch原子准入，实际展开与派生总数计量；旧实体仍按旧规则 |
| motion：帧复制进每弹、一轨一帧、禁止组引用、换卡只停发 | 非实体逻辑组，共享闭包，显式生命周期；切卡和死亡统一结束 |
| motion：法线推进作为所有编队通则 | 法线是对应内容的方向选择，通用路径允许任意明确方向 |
| behaviour：全部参数必须entityData、tickCount推导 | 类型化定义/实例参数/权威事件，server time |
| leg-motion：同类段、最多8段、禁止显式尾部静止 | 异构段表、资源上限独立于同步字段；显式HoldTail合法 |
| pipeline：单次决定只能完整单弹快照、预测玩家未来当已知 | 小型权威事件优先；玩家未来位置必须真实采样 |
| timeline：三角函数只能旧Rodrigues例外、时钟失信退本地累加 | 确定性数学注册；冻结可信时刻并恢复，不制造第二时钟 |
| BOSS弹实体存档/年龄恢复 | 数据实例临时化；owner卸载/重启新epoch；客户端重追踪使用checkpoint |

适用域delta不是永久双架构承诺。M4更新 `boss-dev-design` §3/4/6/17，清理以历史实现限制充当普遍设计原则的说明。非BOSS仍使用的旧实体spec保持有效，不能为删除旧代码而暗改玩家弹行为。

## 3. 两项在途change如何交接

| 变更 | 已有价值 | 本次处理 |
|---|---|---|
| extend-danmaku-orchestration | 锁轴/预警/窗口需求、实机缺陷、命令与诊断经验 | 对应需求迁入Frame/Plan/DamageWindow/Segments/CancelScope；代码作为基线。M4显式记录被替代任务，不把缺失的旧实体测试勾完成，不把旧实现当新架构已交付 |
| extend-danmaku-shapes | 平行面板、轴节点双射线、FAN/CAGE缺陷说明 | 图案需求纳入typed generators；放弃gapDeg=列数等字段复用方案；完成新生成器验收后以superseded说明关闭旧路线 |
| danmaku-entity-test-scaffold | 现有实体路径集成测试需求 | 新纯核不依赖它；碰撞桥接和非BOSS回归仍需可运行NeoForge测试环境，独立协调，不以其未落地跳过集成验收 |

proposal阶段不移动/删除这些change；实现阶段在具体验收完成后写交接说明，保留历史证据。OpenSpec没有“替代即完成”的自动语义，不能直接把48/61改为61/61。

## 4. 验证矩阵

### A. 纯核与组合

- 同一程序随机顺序查询t=0..600，与连续查询、checkpoint后查询得到相同状态；无隐藏可变累加依赖。
- 直线/曲线/圆弧/旋转/呼吸与局部图案组合；段边界位置连续，声明平滑者速度连续；显式脱离后世界位置连续。
- 变更遍历顺序、删掉无关成员、取消另一组，不改变任何幸存成员的RNG结果。
- 跨轨帧、跨拍组时钟、跨轮寿命、目标slot失效、派生取消、同tick结束优先级。
- 新增一个仅测试用PathType与PatternType，不编辑主循环/通用payload/member字段即可运行与恢复；这是扩展架构验收。
- `pattern-recipes.md`四个用户案例全部为M2门槛：两代分裂7N/4N、移动母弹nxm、移动自旋龙卷风、高频billboard法阵；含外部实体源变体及预算拒绝/中途恢复。
- operations §10新增基础必须有独立组合小样，future项不算未完成任务，也不能标成已经可用。

### B. 权威与网络

- 1/2/5名客户端，目标换序/退出/死亡/重进；中途追踪、离开再进入、父组不可见、owner与弹相距很远。
- 网络RTT0/100/250ms，抖动0/30ms；客户端停顿0.5s/2s；服务器低TPS、时钟陈旧；模拟旧epoch/重复event/缺definition/半份checkpoint。
- 检查t220关伤害、t230消失、t240新轮；EndCard/死亡清空派生和背景；迟到消息不得复活已结束作用域。
- 客户端重建不重新造成伤害、重复生成子弹、补播历史音效；服务端结果与独立权威事件日志一致。
- 同时测试static与动态方块激光裁剪，数据弹不得因非实体后端而穿透既有遮挡。

### C. 内容与实机

- `content-mapping.md`逐卡manifest比较真实出生数、时序、寿命、前后窗、颜色、尺寸与倍率。
- 蓝1/2/5/6/8平地/起伏地、近身/14格/22格、生存模式；卡4真实中心断口与重新验证；卡7多人公共通路。
- 大妖精静止环重瞄、花心4倍和花瓣爆散、雨地形采样；山女尾珠静止接触与随机漂移；露米娅地雷一次触发。
- 结构测试不能证明通路可达，记录观察者走位路径与受伤事件；失败回写设计/manifest，不能仅“lint绿”。

## 5. 流量和性能门槛

固定硬件/JDK/分辨率/视距/压缩设置、同一seed/玩家脚本，暖机30s、采样180s、3次重复；报告中位数及p95，不比较不同弹量。旧实现有缺拍时，以共同低层场景强制相同出生/存活分布；内容修复增量与架构成本单列。

场景至少包括：48→480成员同图案、800与2000存活压力探针（测试配置临时提高cap，不写入默认平衡）、大妖精花海、山女尾珠、蓝8五人、旋转激光遇动态方块、中途加入生成突发。

| 指标 | 完成门槛 |
|---|---|
| 确定性常态网络 | 运动期间逐弹AddEntity/SetEntityData/MoveEntity/校准位置流为0；定义缓存命中后只发实例/决策/共享时钟与摘要 |
| 共享描述缩放 | 同pattern从48→480成员且无例外/碰撞时，组初始逻辑字节≤2倍；成员数/seed用紧凑字段，不逐成员复制相同轨迹 |
| 总流量 | 同等确定性场景每客户端逻辑字节与线上字节分别报告；逻辑弹幕流量较旧路径降低≥50%，线上压缩收益单列不强求同倍率 |
| CPU | 同等弹量服务端danmaku tick p95≤旧基线110%；2000探针无弹弹平方遍历。若旧基线无法精确对齐，先补基线，不以新内容较少弹量代替 |
| 客户端 | 同等可见弹量frame time p95≤旧基线110%，分别报告求值/渲染/分配；视觉质量相同 |
| 漂移/恢复 | 无注入异常的确定性运动逐位核一致、0运动参数失配、0逐弹硬纠正；时钟调整与真实事件迟到单独计数 |
| 资源回收 | EndEncounter后下一tick活跃组、成员、FX、派生计划、owner锁和预算归零；客户端End到达后同样归零；重复20次无持续增长 |
| 恢复成本 | checkpoint按活跃状态有界，不携带整场无限事件历史；记录每次恢复字节和耗时，不能靠频繁checkpoint替代正常同步 |

这些是待验证目标，不是已测结果。未达标回到M2分析瓶颈，不以降低弹数/关闭碰撞/缩短寿命偷偷达标。动态世界导致的必要事件单列，其带宽允许随事实变化增长。

## 6. 工具和交付证据

沿用 `/danmaku card` 与 `/gs_boss danmaku`，增加 program/epoch/group/batch、late decisions、definition cache、checkpoint、cancel reason、CPU phase、真实展开数读数；预览与实战使用同一runtime。

使用既有链路计量/延迟工具。报告必须分线上压缩后字节与逻辑包字节，记录50ms突发窗口，包含新旧后端、程序hash、种子与配置。

实现检查走 `tools/gradle_task.ps1 build`；需要运行服务器/客户端时同样走wrapper。完成文档后运行 `openspec validate refactor-danmaku-program-runtime --strict`；运行实现后再加入lang审计与相应测试，不把proposal验证冒充代码验证。
