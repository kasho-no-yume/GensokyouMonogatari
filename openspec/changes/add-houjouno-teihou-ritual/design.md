## Context

`gensokyou:houjouno_teihou_circle` 已提供 0–2 阶、4/8/12 个祭品台的可启停结构，但尚未注册行为。现有五个资源生产仪式在缺料或灵力不足时都只跳过当次结算，保持 `enabled=true`；手动停止才关闭生产。现有通用 `ritual_recipes` 面向整结构聚合匹配、固定结果和原料消耗，passive 模式还不受启停门控，无法表达“每台种子独立、种子保留、动态成熟 loot”的本仪式。

Minecraft/NeoForge 没有覆盖所有作物的统一“种子、成熟状态、正常收获”接口。标准 `CropBlock` 可自动处理，但西瓜、南瓜、瓶子草、下界疣、甜浆果、可可豆、甘蔗、仙人掌以及非标准 mod 作物需要显式定义。现有三段式灵力来源、统一核心冷却、行为 GUI 信息行、路由端点和空投工具可复用。

## Goals / Non-Goals

**Goals:**

- 实现 0–2 阶启停型、每 60 秒成功结算一次的农业收获仪式。
- 每个有效祭品台独立计费、独立采样，种子永久保留。
- 自动兼容标准 `CropBlock`，显式支持全部原版农业特例，并允许 mod 注册非标准收获适配器。
- 保持欠费全有全无且不改变 `enabled`，手动停止只关闭生产。
- 保留完整 `ItemStack` 组件，聚合、拆栈后使用现有核心空投链路。
- 提供配置、GUI、调试探针、指导书与可重复验证的测试入口。

**Non-Goals:**

- 不在世界中真实种植、催熟、放置临时农田或触发完整玩家破坏流程。
- 不模拟经验、幸运、精准采集、附魔工具、玩家右键采集或 `BlockBreakEvent`。
- 不把树苗、树木、蘑菇、装饰植物、成熟成果方块或无生长阶段的幻想乡植物自动视为作物种子。
- 不扩展通用 `ritual_recipes` schema，也不新增 passive/activation 配方模式。
- 不承诺仅凭标准标签自动识别所有非标准 mod 作物；此类 mod 必须显式适配。
- 不为本仪式新增独立 JEI 配方页；参数与兼容说明进入指导书。

## Decisions

### 1. 使用专用 Behavior，不复用通用仪式配方

为 `gensokyou:houjouno_teihou_circle` 注册独立 `RitualBehavior`。生产只放在 `serverTick`，由核心现有 `enabled` 门控；`serverPassiveTick` 只承担槽内灵力核心到缓存的补料，不执行生产。仪式不声明 activation/passive `ritual_recipes`，也不使用 periodic requirements。

选择理由：通用 matcher 是整结构多重集模型，passive 执行不受 enabled 控制且默认消耗原料；本仪式需要每台独立、非消耗、动态 loot 语义。

### 2. 成功结算后冷却，欠费仅空转

`serverTick` 在 `actionCooldown>0` 时直接返回。冷却为 0 时扫描全部祭品台并尝试一次完整结算；仅在成功扣费并提交产物后设置默认 1200 tick 冷却。

无有效种子、解析失败或灵力不足时保持 `enabled=true`，不扣费、不产出、不改冷却。灵力恢复后由下一次 `serverTick` 自动结算，不需要额外的自动恢复状态。`actionCooldown` 沿用核心现状：手动停止期间仍继续递减；玩家重启时若冷却已归零则立即结算，否则等待剩余时间。

### 3. 数值按结构等级独立配置

所有可调值进入 COMMON 配置，行为不硬编码字面量：

- 缓存基值默认 40000，容量倍率默认 12。
- 受灵基值默认 40000，受灵倍率默认 12。
- 单台成本基值默认 4000，成本倍率默认 4。
- 单台采样基值默认 1，采样倍率默认 4。
- 周期默认 1200 tick。

结构等级只取 `RitualMatch.level()`，不取视觉仪式石品阶。容量和受灵即使默认同值也使用独立配置通道；输出速率保持 0。全部指数乘法使用饱和 `long` 运算。

### 4. 每台种子是一个确定性收获单元

扫描结构内全部真实祭品台。一个台位上的物品若被显式适配器或标准作物自动路径识别为正确种子/繁殖材料，即形成一个有效收获单元。相同物品放在四个祭品台上就是四个单元；祭品台位置和重复数量不影响判定，但每个物理台位分别计费和采样。

有效单元的输入 `ItemStack` 永久保留。结算不对祭品台执行写入、扣减或替换，即使产出中包含同种种子。

### 5. 作物解析采用三层兼容模型

新增只读、无世界副作用的收获适配器注册表。显式注册优先于自动识别。

1. **标准自动路径**：输入是 `BlockItem`，其方块继承 `CropBlock`，方块的克隆/种子身份与输入物品一致。成熟状态由 `getStateForAge(getMaxAge())` 构造，再调用成熟状态的空工具 `getDrops`。此路径不依赖 `c:seeds` 或 `minecraft:crops` 标签，因而自动覆盖遵守同一形态的 mod 作物。
2. **原版显式适配**：为西瓜、南瓜、瓶子草、下界疣、甜浆果、可可豆、甘蔗、仙人掌注册适配器。西瓜与南瓜每次采样直接产出一个完整 `minecraft:melon` / `minecraft:pumpkin`；甘蔗与仙人掌每次采样固定产出一个对应物品；其余特例构造正确的成熟状态并使用其正常空工具 loot。
3. **mod 适配接口**：非标准 mod 在运行时按物品或资源标识注册适配器。适配器接收服务器等级、核心位置、随机源、输入栈和只读收获上下文，只能向本次批次收集输出，不得修改世界或祭品台。适配器失败只使该台退出本批次并记录诊断，不阻断其他有效台位。

不创建固定的 mod 物品 JSON 清单，避免未安装 mod 导致整文件拒载。

### 6. 正常收获固定为成熟状态的空工具 loot

标准与状态型适配器使用成熟 `BlockState` 的 loot 语义，工具传 `ItemStack.EMPTY`，不提供玩家、工具或方块实体上下文。由此保留作物、可能种子、数量概率、附魔和自定义组件，但不包含经验、破坏事件、工具门槛、精准采集或特殊手工收割动作。

独立物品型适配器（完整西瓜/南瓜、甘蔗、仙人掌）直接返回规定物品栈。每次采样都创建独立随机结果；不先掷一次再把数量乘四。

### 7. 先完成批次规划，再一次支付和提交

一次结算按以下顺序执行：

1. 扫描并解析所有台位。
2. 对每个有效单元独立执行 `1 × 4^level` 次采样，将结果收入该台的临时批次。
3. provider 解析为空或抛出异常的台位退出本批次；若仍有有效单元，按剩余单元数重新计算总成本。
4. 以 `SpiritPowerHelper.canCover` 验证三段式来源：槽内核心 → 自身缓存 → 半径内其他核心；托管 `SpiritBank` 的可用量按当前结算周期实际可取额度计算，不把被限速的存量提前当作可用。
5. 以一次 `payCost` 原子支付 `有效台位数 × 4000 × 4^level`。
6. 支付成功后合并所有临时批次、拆栈并空投，最后设置 1200 tick 冷却。

适配器已成功识别并完成采样但随机结果为空的单元仍计入成本；适配器执行失败并在支付前退出的单元不计成本。已记录的适配失败按独立失败重试间隔重试，正常灵力不足则在采样前直接空转，避免每 tick 重复执行昂贵 loot。任何支付失败都丢弃本批次，保持 `enabled`、种子、冷却和产出不变。

选择三段式来源是为了与五个现有资源仪式及 `core-socket-powering` 一致；本变更不采用无尽藏的自动关闭或仅扣自身缓存语义。

### 8. 按完整组件聚合并复用统一空投

聚合键必须同时满足物品相同和全部数据组件等价，不能只使用 `Item`。累计数量使用饱和 `long`，每个聚合项按该物品当前最大堆叠数拆分，再交给 `RitualOutputs` 在核心上方、配置半径的圆盘内生成物品实体。

2 阶满台每周期最多 12×16=192 次采样。适配器只构造成熟状态并取 loot，不在世界中执行 192 次种植；相同输出的堆叠合并控制实体峰值。

### 9. 停止生产不影响受灵

手动停止把 `enabled` 置 false，因而不再进入 `serverTick`；路由 `receiveRouted` 仍可向核心注入灵力。行为在 `serverPassiveTick` 中调用槽内电池到缓存的补料，不检查 `enabled`，因此手动停止期间仍可为下次启动预热。电池补料按灵力核心自身速率执行；行为声明的 `spiritInRatePerSecond` 只约束万象共鸣路由。

只有手动停止和结构失效可以改变 `enabled`。缺料、欠费或适配器错误都不得改变开关状态。

### 10. GUI、调试和指导书共享同一纯计算口径

GUI 信息行显示：运行/停止、冷却剩余、占用台位、有效/无效台位、单位成本、本批总成本和预计采样次数；大数使用紧凑显示，精确值放 tooltip。灵力不足时仍显示“运行中：灵力不足”，启停按钮保持停止态，不得伪装成未启动。

调试子命令输出单行机读摘要：pattern、level、enabled、cooldown、台位/有效/无效数、单位/总成本、采样数、stored/capacity 与各适配器失败计数。指导书的 0–2 阶参数页从同一配置公式现算数值，并列出内置原版支持范围和 mod 适配说明。

## Risks / Trade-offs

- **非标准 mod 无法自动识别** → 提供稳定的运行时适配器注册接口；标准 `CropBlock` 保持零适配自动支持。
- **mod loot 或全局修改器可能昂贵或有副作用** → 最坏情况 profile 192 次采样；适配器契约禁止世界写入，异常按台隔离。
- **组件不同的同物品无法完全合并** → 仅在物品和完整组件完全一致时合并，无法合并时接受更多实体但禁止丢数据。
- **三段式 nearby 兜底可能在同 tick 被其他核心抢先** → 使用 `canCover` + 单次 `payCost`；支付失败丢弃整批，不产生部分产出。
- **停止期间预充灵力可能最终未被使用** → 这是用户确认的机器受灵语义；GUI 持续显示存量与容量。
- **无有效种子或欠费时每 tick 扫描** → 台位数最多 12，优先保持与现有资源仪式一致的即时恢复；后续仅在实测成为热点时再引入脏标记优化。
- **降阶后存量可能暂时超过新容量** → 保留溢出，不销毁资源；停止继续注入直至存量回到容量以下。

## Migration Plan

1. 注册行为、容量分派和配置默认值，保留现有 pattern 与语言键。
2. 引入适配器注册表、标准自动路径和原版特例，再接入独立采样与原子结算。
3. 接入 GUI、被动电池补料、调试探针与指导书参数页。
4. 运行纯逻辑测试、仪式结构/语言校验、编译和实机周期验证；用标准 mod 作物与至少一个显式适配样例验证兼容接口。

本变更不新增持久化任务字段或存档迁移。已有 `enabled` 与 `actionCooldown` 继续沿用核心存档格式。回滚时移除行为注册与新配置即可，既有祭品台物品和核心缓存不受影响。

## Open Questions

无。作物范围、独立采样、欠费保持 enabled、停止继续受灵、西瓜/南瓜整果以及甘蔗/仙人掌单件产出均已确认。
