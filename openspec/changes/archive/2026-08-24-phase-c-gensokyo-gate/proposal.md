# Proposal: 阶段 C — 幻想乡之门

> 需求依据：`openspec/project.md` §3.3/§3.6、§7 阶段 C。
> 本提案为**框架级**：划定本阶段交付边界；design/specs/tasks 在开工前细化。

## Why

灵力经济就绪后，玩家需要通往终局内容的门。阶段 C 打开幻想乡（全局永久开关），
建立商人/委托的社会系统，并落地"已学符卡 + 技能槽 + HUD 键位"这一核心战斗形态——
学卡唯一途径是幻想乡任务（project.md §3.3），因此三者必须同阶段交付。

## What Changes

- **结界引爆大仪式**：消耗巨量灵力+稀有材料的多方块大仪式；引爆后幻想乡维度永久开放（全局开关）
- **幻想乡维度壳**：地形生成沿用主世界风格；本阶段不含寝宫精细结构
- **商人 NPC**：主世界自定义商人实体（行为参照流浪商人）；幻想乡内可交易角色框架
- **委托任务（最小形态）**：作为已学符卡的唯一习得载体（任务类型集见 project.md 开放问题 #1）
- **符卡学习机制**：通过完成任务习得符卡 → 写入玩家数据（per-player，存档持久）
- **技能槽系统 + HUD/键位**：3–5 槽位随成长解锁；战斗中键位释放、冷却/耗灵显示的客户端 HUD
- **更多符卡内容**：首批"可学习"卡池

## Capabilities（本阶段将产出的 spec）

- `barrier-break-ritual`：结界仪式与全局开关语义
- `gensokyo-dimension`：维度生成与进入规则
- `merchant-system`：商人实体与交易界面
- `commission-quests`：委托最小形态
- `card-learning`：习得规则与数据存储
- `skill-slots-hud`：槽位/键位/HUD 客户端系统

## Impact

- 依赖阶段 B 的灵力经济（结界仪式是灵力的第一个"终极消耗口"）
- 首次引入客户端 UI 系统层（HUD/按键/界面），客户端-服务端同步面显著扩大
- 维度数据采用 JSON 数据驱动为主，代码只承担入口逻辑

## Out of Scope

寝宫结构与高阶 BOSS（D）、降神变身道具（D）、主线剧情脚本（非目标）

## Deferred（本次未达成，顺延）

  但 1.21.1 内建注册表在 mod 构造期已冻结；当前以低频噪声 blob 布局替代
  （区域大但可能重复）。后续方向：NeoForge 官方口子 / Mixin 提前注入 / 自研维度生成器。
- **地形精调**：守矢山高山体、雾之湖水面凹陷需要自定义 density function（minecraft:x/z
  密度函数类型在 1.21.1 不存在，需另寻塑形手段）。
- **商人 NPC 与委托任务雏形**：顺延至下一迭代；/gs_learn 过渡命令届时移除。
- **SpawnSafetyHandler**：登录/换维时若玩家位于维度底部自动挪至地表——兜底保护已实现。
