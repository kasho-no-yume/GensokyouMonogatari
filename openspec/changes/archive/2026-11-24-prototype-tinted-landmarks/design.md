## Context

地标需要在多个区块中复用同一批灰度建筑方块，同一种方块可以逐格指定单一 RGB。

## Goals / Non-Goals

- 在独立测试维度放置跨区块的墙、屋檐和可开关的门。
- 验证基础形状的抗破坏、逐格染色和室内禁放。
- 完整博丽神社、幻想乡生成接入、全形状库和游戏内编辑工具留在后续阶段。

## Decisions

1. 使用灰度砖、木和瓦验证全块、台阶、楼梯和门。负硬度、基岩级爆炸抗性和阻挡活塞反应由灰模属性提供。
2. 样件固定在独立维度的锚点，由管理员命令安装。结构数据使用原版 NBT 模板。配色资源以版本化样件 ID 定位，GZIP 压缩后发布。每个有染色的区块段保存色号和预期方块编号，各一字节。色号 0 使用原始灰度。
3. 客户端加载时解压配色，在样件维度按坐标查色。实际方块注册 ID 匹配时才逐格上色。缺块、替换和门开关均按此规则渲染。文件读取失败时使用灰度。导出器从同一张样件图纸产出两份资源。
4. 服务端按实际落点阻止保护区内的普通方块放置，覆盖多格方块。独立检查灵力筑基器的清地和铺地。

## Risks / Trade-offs

- 禁放需要覆盖客户端预测和服务端确认之间的差异，边界与门交互纳入实机验收。
- 活塞把外部方块推入、流体、第三方直接写世界是独立入口，原型单独记录覆盖结果。
- 固定样件升级时使用新版本 ID 和独立坐标，避免旧模板读取错位颜色。
