## Why

灵力三仪式（加具土命产灵 / 万象共鸣路由 / 八方归元储灵）各自实现了限速与结算，三者时间基准互不统一：生产者按"每秒一次"入账、路由器按"每 tick 每对"结算、汇按"每次 receive 调用"发放预算。限速权又不在端点本身，导致实测行为漂移：多拉取方同 tick 重复领取满额预算可超端点标称速率；归元实测窗口读数系统性过读（1280 输入显示 1600）；汇内分配与既有 spec 的"均衡进账"不符（实为规范序灌满、零头顺位漏入后核）；路由吞吐显示为滞后 EMA。上一轮归档已自认 10.1 / 10.2 / 10.3 三项遗留。需要把灵力传输的速率结算收敛为单一规范，作为后续高阶电力基建的地基。

## What Changes

- **端点自持每 tick 速率账本（新权威）**：每个灵力端点在内部维护"本 tick 尚可收/发多少"的账本，以 `gameTime` 幂等锁存，同一 tick 内无论多少调用方（多塔）共享同一份额度；整数零头以定点进位跨 tick 累计。调用方预算降级为**建议值**，最终实搬由端点账本 + 头寸截断。**BREAKING（行为语义）**：源/汇速率上限从"每通道各自记"变为"端点全局强制"。
- **生产者按"只能输出的电池"建模**：内部 1Hz 充能与缓冲合法（是储电不是隐藏缓存），无需改产出节奏；其`out`速率上限由端点账本全局强制——多塔合计不得超放电上限。生产者不声明 `in`，不被选作汇。
- **归元汇内分配 = 按核速率上限加权的水位分配**：把现有"规范序依次灌满"改为对每笔进/出的额度在全部可收（/可发）核心间按各核速率上限加权分配，遇核心自身预算或空位/存量封顶则让位给其余核心回填。收/发两向同规则。**对齐既有 spec 的"均衡进账"措辞**（原实现与 spec 不符）。
- **实测吞吐显示改为单调计数器差分**：端点累计 `movedTotal`（单调），显示 = `(now-prev moved)/(now-prev tick) × 20`，按 `gameTime` 精确折算；彻底消除窗口 off-by-one 过读与静默残影。路由吞吐显示口径统一。
- **同 tick 多调用裁决 = 先到先得（FCFS）**：次序由各路由 `serverTick` 的执行顺序决定，与塔的启停历史无关；暂停再启动不会改变既有优先序。跨塔公平分配明确列入非目标（留待将来中央结算）。
- 收编归档遗留缺陷 10.1（预算按调用重复发放）、10.2（实测窗口无衰减封顶）、10.3（分配原则实现与 spec 不一致）。

### Modified Capabilities
- `ritual-power-attributes`: 新增"端点每 tick 速率账本"要求（权威/`gameTime` 锁存/跨调用共享/FCFS/定点进位）与"实测速率单调计数器差分口径"要求；明确声明速率为端点全局强制上限、调用方预算仅为建议值。
