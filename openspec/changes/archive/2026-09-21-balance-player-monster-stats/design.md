# Design: balance-player-monster-stats

## Context

现状（全部占位值）：

- 玩家成长只有一条轴：`graceTierTable` 的"逐阶增量"，`final = 配置基准 + Σ各阶增量`（池两键走台账，其余走 `grace_tier_N` 加区）。
- 现表：`spirit_power` 累计 400、`max_spirit` 累计 10,000、回灵 ≈2%/s、`danmaku_reduce` 累计 72%（cap 0.9）、`spell_cdr` 累计 60%（cap 0.40，已溢出）。
- 伤害公式（`WeaponFiring`）：`单发 = spiritPower × coreBaseMult × weaponLvMult × (1+Σrune%) × critMult`。
- 受弹管线（`AttributeMath.resolveIncoming`）：擦弹 roll → `(1−reduce)×护盾系数` 封顶 90% → 减 flat 抵抗。
- 仪式经济量级 10⁴~10⁹（献祭 4,000×4^N、无尽藏 10⁴×5^N、Sair 10⁹），与玩家池 10,000 脱节。

约束：数值一律进 config；凡人（阶 0）零池；`final = base + Σ贡献` 的加区容器不改结构；洗练必须重掷全部键。

## Goals / Non-Goals

**Goals:**
- 一版可玩的初版数值：T1 平均 DPS 落在钻石剑 ~ 锋利5下界剑之间；每阶 ≈×10。
- 减免公式杜绝"99.9%"显示，且能随指数级怪物伤害同步成长。
- 池量级与仪式经济、符卡消耗对齐；回灵被削到必须补灵。
- 同阶怪"扛 9~16 下、TTK ≈4s"全程平直；跨 1 阶必死、跨 2 阶无望。

**Non-Goals:**
- 不改伤害公式结构、不改加区容器、不动仪式产量表。
- 不定大妖精/芙兰朵露数值（待实机）。
- 不做降神变身。

## Decisions

### D1 灵力上限 ×10/阶，量级对齐经济

累计 `max_spirit`：`1,000 / 10,000 / 100,000 / 1,000,000 / 10,000,000`（增量 `1,000 / 9,000 / 90,000 / 900,000 / 9,000,000`，roll ±20%）。
- T1 池 1,000 与现有符卡消耗（无双 120 / 冰符 60）自然协调。
- 若要亿级（T5=10⁸），把每阶倍率改为 ×~13 或起手 10⁴，表结构不变。
- **替代方案**：保持 ×2.5/阶（T5=10⁵）——被否，高强符卡无消耗空间。

### D2 回灵 = 每阶定值，占池 0.03%~0.3%/s

`baseRegenPerSecond = 0`；逐阶增量 = 该阶池的 **0.12% 中点**、`roll = 0.7`（对称 ±70%，配合 max_spirit 的 ±20% roll，累计占比恒落在 0.03%~0.3%）：

```
1,spirit_regen_rate, 1.2,    0.7
2,spirit_regen_rate, 10.8,   0.7
3,spirit_regen_rate, 108,    0.7
4,spirit_regen_rate, 1080,   0.7
5,spirit_regen_rate, 10800,  0.7
```

因池是几何 ×10，`Σ增量 ≈ 1.11×该阶增量`，故"增量占该阶池比"≈"累计占该阶池比"。回满时间 5.5~55 min。

### D3 弹幕减免 → 灵力护壁指数 P（关键）

存 `danmaku_reduce` 键为**无量纲正实数 P**（加区累加，兼容容器），结算：

```
受伤 = 原伤 × 2^(−P) × protectFactor          // 无论 P 多大恒 > 0
UI 显示：   灵力护壁 ×2^P     （例：×2 / ×8 / ×388）
```

- 每 +1 P = 伤害再砍半；"越靠近 100 收益指数增长"成立，但**永不出现 99.9%**（因为它显示的是除数，不是百分比）。
- 无需 90% 全局封顶，`DANMAKU_REDUCTION_GLOBAL_CAP` 退役。
- 旧 `danmaku_resist`（flat）与指数伤害不兼容，**退役**（配置项移除/置 0 无入口）。
- **替代方案**：保留百分比但只显示"受伤侧"（`受弹 0.26%`）——被否，小数仍难读；指数除数是唯一既直观又不产生 9 的方案。

### D4 DPS 阶梯的杠杆拆分（属性主力 + 武器跨带跃升）

```
DPS(N) = spiritPower × coreMult × weaponLvMult(band) × (1+rune) × critMult × 射速
         ×≈9/阶（主力）    ×1.0        ×1 带内 / ×2 跨带       ≤+80%      ×≈1.1/阶
```

- `spirit_power` 累计 `6 / 60 / 540 / 4640 / 39140`（**×≈9/阶，承担每阶 ×10 DPS 的主力**；此键允许突破旧的 2.5~3.3 带）。
- **武器等级每级覆盖两个灵启阶**（Lv1=阶1-2 / Lv2=阶3-4 / Lv3=阶5，`[1,2,4]`）：只在跨带给一次 ×2 跃升，故阶3、阶5 的总跃升约 ×20（满足"至少 ×10"）。
- **核倍率不随阶**（只做行为分化 + requiredTier 硬门），避免与 weaponLvMult 双叠膨胀。
- 详见 `docs/weapon-design-guidelines.md`。

### D5 全键范围化

- 核心四键（`max_spirit`/`spirit_power`/`spirit_regen_rate`/`danmaku_reduce`）：roll **±20%**。
- 其余 11 键：roll **±35%**。
- `GraceNumbers.MAX_ROLL` 维持 0.95（0.82 合法）。

## Risks / Trade-offs

- [回灵过削导致 T1 裸装不可玩] → 池 1,000 支持 ~100 发；补灵仪式/电容为设计内获取途径；T1 定位本就是"入门后、有基础设施"。
- [护壁键单位变化破坏旧档/旧贡献] → 迁移时对 `grace_tier_N` 的该键**整组重掷**为 P 语义；无生产存档，风险低。
- [×10/阶与武器倍率双叠导致膨胀] → 核倍率不随阶；武器倍率是唯一 gear 乘区；design 与任务中锁死。
- [P 无上限导致某阶近乎无敌] → 同阶弹伤随阶 ×10 同步上调，EHP 与伤害同步；跨阶照旧秒杀。
- [显示改动引起玩家困惑] → 属性查询命令同时打印 P 与 ×2^P；tooltip 用"护壁 ×N"。
