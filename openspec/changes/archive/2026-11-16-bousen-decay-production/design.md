# Design: 忘川灯坛加速衰减产灵

## Context

忘川灯坛（`gensokyou:bousen_circle`）现状：产灵是二元门控——`serverTick` 开头 `if (!allLit) return`，全亮则每秒注入 `R`（100/500/3000），熄灭任意一根即归零并停止一切随机熄灭（自我冻结）。熄灭本身用世界无关的二项采样器（`Binomial(lit, p)`，`p=[.01,.005,.0025]`，200t 周期）聚合结算，与逐根掷币分布等价，且已修复过三处静默 bug（游标/计数混用、拒绝采样偏置、遗留 RNG 流）——这套采样代码经实机验证稳定。

问题：全亮窗口仅 ~62.5 秒（首次熄灭期望），"自主运行余裕"几乎为零；"灭一根 = 灭 64 根"缺乏可读中间态。目标是把产灵改成按熄灭数加速衰减的连续曲线，同时不动熄灭机制、不超模。

## Goals / Non-Goals

**Goals:**
- 全亮仍产满速率 R；熄灭一根开始掉速，越掉越快，到半阈值归零。
- 给到 11–46 分钟的放任余裕，且平均产能为峰值 61–68%（自然限流）。
- 熄灭采样器及其全部自检断言一行不改。
- 供灵端点维持静态，路由不闪断；瞬态灯火状态仍不持久化。

**Non-Goals:**
- 不改熄灭规则（概率、周期、采样、一次熄灭多根的分布）——保持现状。
- 不改三件套数值（产灵/缓存/供灵表）、pattern、配方、存档、网络包结构。
- 不引入自动点灯手段（手动维护是该仪式的核心美学）。
- 不新增渲染态字段；金光判据改动完全在客户端本地完成。

## Decisions

### D1 衰减曲线：`rate(d) = R·[1 − (d/h)^γ]`，h=n/2，γ=2

用户选了"加速衰减（越接近阈值掉得越狠）"而非指数衰减。γ=2 是最小加速指数：γ=1 退化为线性（每根掉一样多），γ≥3 末根掉 35%+ 惩罚过重。h 固定为蜡烛数一半（8/16/32）——用户明确要求阈值为总蜡烛一半；d≥h 时 rate=0。

一阶数值示例（R=100, h=8）：d=0→100, 1→98, 2→94, 4→75, 6→44, 7→23, ≥8→0。三阶（R=3000, h=32）：d=0→3000, 8→2813, 16→2250, 24→1313, 31→185, ≥32→0。

**为什么不用归一化指数 `(e^{−κd/h}−e^{−κ})/(1−e^{−κ})`**：那是前几根掉得狠（凹曲线），与"越灭越狠"的诉求相反；且需要额外引入 κ 而 γ 更直白。

### D2 熄灭截止 gate 从 `allLit` 改为 `rate > 0`

`serverTick` 不再以全亮为前置。产灵每秒按 `rate(d)` 注入；熄灭掷骰的前置改为"当刻 `rate>0`"。rate=0（d≥h）即停掷，灯坛稳定停在半灭态；玩家补灯使 d<h、rate>0 后两者自动恢复，无需再点启动。顺序保持"先产后熄"（现有 spec 断言）。

**为什么不是"一直烧到全灭"**：用户要求"0 产灵就停"，半阈值是这套参数下的恰好落点。写成 `rate>0` 而非硬编码 `d<h`，使规则与曲线参数解耦——将来若调 h 比例或 γ，gate 自动跟随。

### D3 熄灭规则完全不变

评估过三个选项后用户选 C：不改。原因：(a) 单根寿命与余裕时间数学上绑定（余裕 = 单根寿命 × ln2），缩短寿命必然吃掉余裕；(b) 当前 Binomial 已支持一次灭多根，只是 P(k≥2)≈1.2% 不可见，但成片熄灭方案会改动整套采样器与自检断言；(c) 熄灭机制稳定，改动风险远大于收益。保持 p、周期、采样器、RNG 序列、GUI 熄灭 tooltip 全部不变。

### D4 数值维持原值（横评论证）

用户理由：并非每时每刻跑在峰值，衰减已自然压低均值；迦具土以廉价燃料为成本，其 1280/s 是被压低的天花板，不适合作基准。补充论证：忘川占据"无法自动化 + 手动维护 + 大坛面建造成本"的独特生态位，无同类可比。均值 61–68% 落在仪式经济 10⁴~10⁹ 尺度里很温和。三件套配置表一行不动。

### D5 单调性与边界（写入 selftest）

纯函数 `rate(level, lit, total)` 必须满足：`rate(d=0)=R`、`rate(d=h)=0`、`d>d'` 时 `rate(d)<rate(d')`、d≥h 恒 0。配置里 γ 非法（≤0）时钳到默认 2.0，MUST NOT 产出 NaN 或负速率。既有采样器自检（满掩码特判、n·p 恒等、二项均值、均匀性、RNG 健康）全部保留，新增曲线断言并列。

### D6 渲染：金光判据改为"点亮数 > 半数"

客户端仅凭 `movingMask` 的 bitCount 与 pattern 该阶蜡烛总数即可判定 `lit > h`（等价 rate>0），无须服务端下发速率、无须新字段、不破坏稳态零持续包。`ritual-runtime-fx` 的 bousen 场景据此改写。熄灭态淡红 billboard / 冲天光柱逻辑不变。

### D7 GUI：产灵行显示实时 rate

产灵行从"满速率 or 停产文案"改为"实时 rate/s"（全亮时即 R，与现状一致）；停产独立文案只在 `rate=0` 时出现。灯火行 tooltip 补阈值/曲率/当前有效速率。维持信息行宽度红线（可见 ≤11 汉字，明细下沉 tipped）。

## Risks / Trade-offs

- **[衰减曲线精度 vs 客户端表现]** → 客户端只知道"点亮过半"这个布尔，画不出"按 rate 强度渐变"的金光。Mitigation: 本期金光只做有/无两态（以过半为门），强度渐变留待后续；渲染语义不依赖精确数值。
- **[γ 配置可调导致 UI 与服务端不一致]** → γ 是 SERVER 配置，`RitualTierComponent` 展示的分阶级参数是全亮峰值 R（不变），不受 γ 影响；GUI 实时 rate 由服务端计算下发，无一致性问题。
- **[rate 归零后玩家不知为何停产]** → GUI 停产文案 + 灯火行 tooltip 说明阈值；灯火行在 rate=0 时改红色（区别于缺灯的橙色）。
- **[浮点取整]** → rate 用 `Math.round(R·[1−(d/h)^γ])`，与日轮/迦具土的按秒取整口径一致；γ=2、h∈{8,16,32} 下值的粒度足够，无需 carry 累积。
- **[熄灭不变量回归]** → 采样器代码零改动，但 `serverTick` 结构调整后需实机确认"熄灭与产灵同帧仍先产后熄"、"rate=0 后根数冻结"。用 `/gs_debug bousen` 机读单行（新增 `rate`/`d` 字段）断言。

## Migration Plan

1. 加 γ 配置项（默认 2.0），旧存档/配置无该键时回落默认值，行为等价。
2. 行为改动上线后，全亮玩家体验无变化（仍产 R/s）；缺灯玩家首次发现"不再一刀切停产，而是缓慢掉速"——这是期望的产品行为变化，无需迁移存档。
3. 回滚：移除 γ 配置、`serverTick` 恢复全亮早退即可，无数据迁移。
