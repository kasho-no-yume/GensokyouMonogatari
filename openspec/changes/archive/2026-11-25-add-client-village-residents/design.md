# Design

## Context

动机见 proposal.md。现有 `ProgramDanmakuRenderer` 已能在世界渲染事件中直接绘制数据。目标平台为 MC 1.21.1 / NeoForge 21.1.248；原版村民几何可独立烘焙成 `ModelPart`，无需 `Villager` 或任何实体注册。村庄建筑未确定，且联机客户端没有完整世界种子。

## Goals / Non-Goals

**Goals:** 使用共享村民派生模型，以固定身份确定服装、头饰、配色、身材和动作；支持资源包定义活动点、安全的本地移动与可直接使用的预览。

**Non-Goals:** 普通居民的交易、受击、碰撞、寻路 AI、繁殖、持久化、语音或联机一致性。此次不修改建筑/地形/参道，不增加服务端组件。

## Decisions

### 1. 客户端边界

全部代码归于 `client/resident/`，只有 `Dist.CLIENT` 事件订阅者接入。居民是普通 Java 数据，渲染直接调用模型部件；不借用隐藏实体或假玩家。使用已有区块/时间信息，不申请区块、不新增协议。

### 2. 可重复的外观与共享资源

身份由场景资源 ID 和槽位字符串作稳定哈希，外观随机只在身份建立时计算。以原版村民网格作为基础，移除职业帽和外袍默认显示，增加短外套/长袍/围裙、短发/束发/头巾/草帽、挎包/包袱。共享一张有限图集，肤色和衣色分别按部件着色；鼻子与抱臂保留村民辨识度。几何和贴图均不依赖运行时实体。

### 3. 有界活动数据

客户端 JSON 位于 `assets/<namespace>/village_residents/*.json`，声明维度、原点和有名称的槽位；每槽位提供相对路线点和驻足朝向。每条路线最多 16 点、每场景最多 128 居民、全部场景最多 512 居民；无效场景记录错误并跳过，其他场景仍可用。只发布幻想乡中心预留地的一小组接入样例，并要求脚下是 landmark 实体铺装，未铺路时不出现。建筑完成后通过资源包替换坐标即可。

### 4. 运动与世界检查

一个点表示驻足，多点路线按往返方式行走，在节点停留。固定 tick 推进局部路线时间，渲染在前后状态之间插值；步态使用实际通过的距离。移动被阻挡时不推进路线时间，禁止恢复后跳过障碍。地面由客户端已加载区块采样；支持半砖/台阶，拒绝水、洞、过高台阶、无净空和卸载区块。非实体居民可与玩家重叠，但不穿实体方块。

### 5. 绘制和生命周期

初始预算为同时最多 48 名、96 格距离，远处不画小配件。候选按路线范围与相机距离选取，只有入选居民执行地面/阻挡检查；逐帧再做视锥和区块存在性检查。使用常规 cutout 深度绘制与环境光，复用图集/模型，每批只提交一次。资源重载重新加载场景并释放模型引用；世界对象改变、退出和切维度清空本地活动及预览。

### 6. 本地验收入口

创造模式 `/gs_residents preview [1..48]` 在玩家附近创建临时排布，部分驻足、部分沿短路线行走；不写世界、不需要服务器命令权限。`clear` 仅清除预览，`status` 报告本地活动/绘制数量。预览允许普通干燥地面，仍执行已加载/净空/阻挡检查。反馈中英双语。性能上限为实现常量，不新增持久配置键，遵守 config-surface。

## Risks / Trade-offs

- [无真实建筑可接入] → 正式数据由保护铺装激活，预览独立可用；文档交代当前活动点为接入样例。
- [玩家堵路或拆装饰] → 每 tick 检查支持与净空，阻挡时驻足，重新可通行后继续；不承担完整寻路。
- [客户端仍有绘制成本] → 固定候选/活动/距离预算，共享图集和模型；不宣称未经实机测量的帧率。
- [原版模型层可变状态串用] → 每人绘制前明确恢复姿态、显隐与缩放，模型只在渲染线程使用。
- [第三方着色器兼容] → 使用原版实体 cutout 与光照，不使用自定义 shader；真实客户端视觉仍需手动验收。

## Migration Plan

没有服务端数据迁移。删除本地资源或移除实现即可回退；不会留下实体、存档记录或世界方块。构建与单测先验证确定性、阻挡、预算和模型输出；有图形环境时再检查日夜光照、遮挡、资源重载与联机本地性。
