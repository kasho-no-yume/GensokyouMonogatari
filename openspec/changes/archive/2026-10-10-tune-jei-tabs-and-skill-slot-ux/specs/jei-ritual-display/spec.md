## MODIFIED Requirements

### Requirement: 仪式配方卡
`ritual_recipes` 中每条配方 SHALL 呈现为其所属仪式页签下的一张配方卡：输入区按原料逐项展示物品 ×数量，原料超过单行容量时 SHALL 换行展示，MUST NOT 截断；输出区展示 result 物品，无 result 的 effect 配方以本地化效果名文本呈现；卡片 SHALL 标注 spCost（灵力消耗）、minTier（结构阶级，本地化呈现），minPlayerTier > 0 时 SHALL 一并标注玩家阶级前置。卡面各元素 MUST NOT 相互重叠。卡片数据 SHALL 仅由数据文件自动派生。除造化页签外，配方名与效果名 SHALL 经语言键渲染（配方名 `jei.<ns>.recipe.<path>`，效果名 `jei.<ns>.effect.<path>`），中英文环境下 MUST NOT 出现裸 id 或回退英文路径；造化页签的配方卡 MUST NOT 绘制配方名（其原料/产物/阶级信息已足以辨识），结构阶级角标保留。

#### Scenario: 实物产物卡
- **WHEN** 查看一条带 result 的加工配方卡
- **THEN** 输入区网格化显示全部原料与数量（超限换行），输出区显示产物，下方标注灵力消耗与阶级门槛

#### Scenario: 效果型卡
- **WHEN** 查看一条仅含 effect 的神恩配方卡
- **THEN** 输出区显示本地化效果名（如"1 阶进阶"），并标注结构阶级与玩家阶级前置

#### Scenario: 版面不重叠
- **WHEN** 查看任意页签下原料最多的一张卡
- **THEN** 标题、原料网格、输出、费用行互不重叠，均在卡边框内

#### Scenario: 造化页签无配方名
- **WHEN** 查看源初造化之仪页签下的任意配方卡
- **THEN** 卡面不出现配方名标题文本，仅保留右上角结构阶级角标与原料/产物/费用区

### Requirement: 每仪式独立配方页签
拥有配方的每个仪式 pattern SHALL 呈现于其专属 JEI 页签：页签标题为该仪式的本地化名称（复用 `jei.gensokyou.ritual.<path>` 键族）；已登记专属页签的仪式之配方卡 MUST NOT 落入兜底页签，也不再存在把全部仪式混在一起的"仪式配方"总页签。未在代码登记专属页签的 pattern 之配方 SHALL 归入唯一兜底页签（无内容时该兜底页签 MUST 隐藏不占侧栏），以保证"新增配方文件零 Java 亦可查看"。为既有配方仪式增设专属页签 SHALL 仅需在代码页签清单增加一行登记；`ritual_recipes` 中全部仪式（源初造化、八百万神恩、百鬼夜行、星移之仪）SHALL 均已登记专属页签，当前数据下兜底页签 MUST NOT 出现在侧栏。

#### Scenario: 四仪式四页签
- **WHEN** 当前数据含源初造化、八百万神恩、百鬼夜行、星移之仪四个已登记配方文件
- **THEN** JEI 侧边栏出现四个独立页签，各自只含本仪式配方，且无「仪式配方（其他）」兜底页签

#### Scenario: 百鬼夜行页签效果名本地化
- **WHEN** 查看百鬼夜行页签下的召唤配方卡
- **THEN** 输出区显示本地化效果名（如"大妖精"），不出现裸 id

#### Scenario: 页签标题本地化
- **WHEN** 客户端语言为 zh_cn / en_us
- **THEN** 页签标题分别显示中文仪式名 / 英文仪式名，无裸 key

#### Scenario: 未登记配方落兜底且可隐藏
- **WHEN** 某 pattern 有配方但未登记专属页签
- **THEN** 其配方卡出现在兜底页签；当兜底页签无任何配方卡时该页签不显示于侧栏
