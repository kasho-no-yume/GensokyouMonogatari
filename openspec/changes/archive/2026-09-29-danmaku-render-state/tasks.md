## 验证记录（2026-09-29）

### 已实机确认

| 场景 | 结果 |
|---|---|
| `/danmaku flower`（解析式编队弹）飞行中存档退出再进 | 抖动消失 |
| `/danmaku wall`（累加式弹幕墙）同上 | 抖动消失 |
| 曲射（`/danmaku card kitsune_bi 0`，绕竖轴 + 绕横轴反向双轨） | 无明显问题 |
| 悬停（`kitsune_bi` 泡卡，第 34 tick 定住） | 无明显问题 |
| 减速后退（`/danmaku flower ... retreat`，速度穿越 0） | 无明显问题 |
| 长激光（`/danmaku laser-ring`）阶段与光束 | 无明显问题 |

**花与墙在重进后均观察到一次「轻微拉回」，判定为设计内成本。** 快照在 `StartTracking`
那一刻采样，客户端收到时已过 δ 个 tick 网络延迟，故进世界瞬间按 δ 之前的年龄起算；
此后由校准把该偏差吸收进视觉偏移并收敛。`wall` 速 0.10 格/tick、δ≈2 时约 0.2 格
（5 格距离 ≈ 30 px），与观察到的量级一致，且不重复、不抖动。

### 已知盲区（归档时必须留档）

1. **「不抖」只证明纠偏反馈环已断，不证明同刻轨迹正确。** 一个持续偏差会被视觉偏移
   吸收——画面平滑而位置是错的，正是提案自己标注的风险（「把同步 bug 从硬失败静默转成
   错渲」）。本变更为此加了 `sync[]` 诊断（`/gs_boss danmaku` 第三行），
   `rej` / `esc` / `jump` 应为 0，`age[snapshot-*]` 段的绝对值即同刻年龄差。
   **本轮未留下任何诊断读数**，故「无抖动」这一结论尚未被数字确认。
2. **dedicated server 完全未验。** 单人游戏下内嵌服务端与客户端同进程、两端 tick 时序
   天然接近；分机之后两条独立时钟，年龄基准漂移窗口会变宽。本变更在服务端还自建了
   `DanmakuTrackingIndex`（模组侧追踪关系表），其事件路径漏项靠 400 tick 低频对账兜底。
   **用户已决定：整体流程开发完成后做专项 dedicated 回归。**
3. **带宽未实测。** 校准样本是 O(弹数) 的持续开销（400 弹 @ 40 tick ≈ 4 KB/s/玩家），
   只做了算术估算，未测实际包量。`danmakuCalibrationIntervalTicks = 0` 可完全关闭。
4. **`spawnStress` / `spawnPrism` 两个调试命令仍是死代码**（方法已写好但未挂进命令树）。
   与本变更无关，是既有状态；用户已确认当前不需要。

### 后续变更应继承的检查项

- 任何改动 `lerpTo` / 纠偏判据 / 快照协议时，MUST 检查是否重新引入了「网络样本改写
  模拟坐标」这条路径——它是本变更移除的那条，也是原症状的成因。
- 轨道级同步（`danmaku-timeline-sync`）落地时，`LEGACY_POSITION` 分支与校准样本应被
  轨道时间轴取代，届时 `sync[]` 的 `cmp` / `oot` 口径需要一并换掉。
- 事件同步（`danmaku-event-sync`）落地时，`motionRevision = revisionFor(age)` 这个
  近似要被真正的运动版本号替换，否则「年龄变了但运动输入没变」与「运动输入变了」
  两种情况在版本号上不可区分。

## 实现备注（本轮落地形态）

**为什么没有把「两套渲染状态」写进 renderer 内部**：`EntityRenderDispatcher.render` 在调用
renderer 之前会加上 `EntityRenderer.getRenderOffset(entity, partialTicks)`，画完再减回去。
纠偏写在这里就自动覆盖球/刀/符/激光四家，且漏不掉一个——写进各 renderer 的 `render()`
则每多一种弹就多一处可能忘记调用的地方。

**为什么用年龄而不是独立计数器做运动版本**：编队帧、速率曲线、显隐全都以年龄为自变量，
客户端重算轨迹用的也是它。把年龄放进样本，两端就在「用同一个自变量求同一条轨迹」这条
前提上互相校验；`REVISION_MISMATCH` 因此是硬冲突而不是噪声，直接升级为失步。

**为什么全量运动输入不进常规快照**：48 个定标整数约 192 字节，800 颗弹一次性配对就是
150KB。取而代之是常驻的**指纹**（纯 int 运算，两端逐位一致）：客户端每次都能算出自己那份
运动输入的指纹，与权威不符即说明参数不是同一时刻的那份，此时才按需补发整块。这让
「一致采样」从一句承诺变成可检验的事实。

**为什么撤掉了硬纠偏后的滞后抑制窗口**：那条窗口存在的前提是「硬纠偏污染下一 tick 的
速度」。本变更移除了硬纠偏本身，前提消失，窗口随之失去对象——`lag` / `age[]` 读数现在
恒取自未被改写过的模拟速度，投影不再被自身污染。
