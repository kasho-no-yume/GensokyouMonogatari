# Release Notes — 千机核心形态重做：武器轮廓显形 + 全彩流光

**变更名**：`rework-danmaku-weapon-silhouette`
**性质**：主武器形象重做（纯客户端表现）· 无存档格式变更 · 无配置键变更 · **零玩法影响**

---

## 一句话

主武器「千机核心」不再是"一颗装核的球"：**没装核时是一颗全彩流光的沉睡核心（带火冠），装上核之后，外壳直接变成那颗核对应的武器本身**（飞刀 → 三把飞刀，激光 → 高科技激光枪，符纸 → 方形符纸……），同时**彻底修掉了"整体发白"**。

---

## 为什么上一版是白的（算术，不是审美）

上一版渲染器有 4 个加法混合层，**全都携带同一个饱和品阶色**，而亮度调制走的是 RGB 乘法 + 逐通道 `min(255, …)` 截顶：

```
阶 1 绿 #4CAF50 (76,175,80) × band 1.567 → (119, 255, 125)   ← 主通道被截顶，色相自己就漂了
①内层壳 + ②焦点核 + ④外晕 + ⑤环绕环 加法求和 → 主通道再次截顶 → (160, 255, 168) 发白薄荷绿
阶 3 金 #FFC107 → R/G 双双截顶 → (255, 255, 12) 黄白
```

贴图层是纯灰度乘法遮罩（`core_orb_shell.png` 明确"MUST 保持中性灰"），**一点色相都补不回来**。

## 这次怎么修的（三条结构性约束，不是调参）

| | 规则 | 落点 |
|---|---|---|
| **R1 加法预算** | 所有加法层在同一像素上的贡献之和 ≤ **85/通道**；本体层峰值 ≤ **0.62**（158/255）。二者相加 < 255 ⇒ **结构上不可能截顶** | `CoreOrbPalette.Layer` / `alphaWithin(...)`（预算被**算出来**，不是自觉遵守） |
| **R2 HSV 空间合成** | 色相与亮度调制 MUST 在 HSV 侧做，MUST NOT RGB 乘法后截顶。逐面虹彩微偏 MUST 以**扇区中心**为基准 | `CoreOrbPalette.shade(...)` |
| **R3 色相分工** | 品阶色**纯本色**只由本体层持有；能量件用其高亮变体；加法层用互补色 / 白金 | `CoreOrbPalette.Layer.hueSlot()` |

**"全彩"由层间色相分离达成**，不是全色相循环——所以装核后**阶位仍然一眼可辨**（有断言守着）。

## 具体形态

### 未装核（沉睡态）——无品阶归属，全光谱流光

- 球面呈**滚动彩虹**（色相沿表面连续流动，逐顶点插值，不是碎面拼贴）
- **火冠气焰**：10 条火舌从上半球立起，每条由两片交叉条带组成（任何角度都不消失），相位各异 → 不同步地舔；**根部取其下方球面的流光色**（同色源，不会割裂），尖端过渡到暖白
- **球心暗腔**：正对相机的一圈暗色涡旋（反向旋转）——保留"未装核"的可读性，同时是气焰的根部
- 外缘有**色散薄边**（轮廓处色相拆开 ±40°），做进本体层的色相，不是叠上去的白边

> 未装核形态**不受品阶配色环约束**——它没有阶位，套品阶色是空转。装上核后**立刻**回到品阶色 ±30°。已在 `openspec/project.md` §5.4 补例外条款。

### 装核（显形态）——外壳几何即武器本身

| 核 | 形态 | 核自带的能量表现 |
|---|---|---|
| 麟弹 | 三枚锥矢斜向前一字排开 | 每锥一条渐隐流光尾 |
| 单发玉 | 饱满大玉球 | 两道旋转能量纬线 + 内部翻涌 |
| 散弹玉 | 五颗小珠呈扇形散开 | 各自短拖尾 |
| 飞刀 | **三把飞刀**（品字形，1 前 2 后，刃尖朝外） | 刃口高光 + 穿透拖痕 |
| 灵符 | 方形符纸（四角切角） | 四角封印钉 + 中央朱印 + 横穿流动的金符 |
| 激光机枪 / 激光炮 | **高科技激光枪**（枪管 / 消焰器 / 机匣 / 散热鳍 / 握把 / 枪托） | 驻轴光轴 + 发光电池 + 枪口聚焦棱镜 |

装核态**不带火冠**——气焰是"未装配"的生命力表现；武器一旦显形，气焰就转化为武器自身的能量表现。

## ⚠️ 有意推翻的既有条款

**`weapon-gui-visual` 的「MUST NOT 呈枪形轮廓」被本变更推翻。**

- 原条款的本意是**防止回归成旧「符星铳」那一把固定的枪**（上一轮变更的 Why 第一条："形象与系统结构不匹配"——换核而枪不变）。
- 新诉求是**外形随核变化**，且要"放 3 把飞刀""放个高科技激光枪"。若强行保留"球壳包着武器"，武器只占视高 40%，玩家依旧第一眼看到的是球——回到老问题。
- 故条款改写为：**未装核 MUST 呈球形核心轮廓 / 装核 MUST 呈该核对应的武器轮廓**。

同样改写的还有「球体色彩动态化」→ 拆成未装核态与装核态两条，并新增加法预算与 HSV 合成两条硬约束。

## ⚠️ 实机崩溃与修复（务必知悉）

**现象**：物品栏 / 快捷栏里带着「千机核心」→ `IllegalStateException: Not building!` → 必崩。

**根因**：本实现把两个 `getBuffer` 调用提到了方法开头。1.21.1 的
`MultiBufferSource.BufferSource#getBuffer` 只有在某个 RenderType **首次**占用**共享缓冲**时
才会把上一个占用者 `endBatch` 掉（`BufferBuilder.building = false`），
之后再往那个已被结束的 consumer 写顶点就抛 "Not building!"。
共享缓冲只有一个——于是第二个 `getBuffer` 把第一个顶掉了：
本体层（后取的）正常，外晕层（先取的）炸。

**修正**：**取缓冲与写入 MUST 绑在一起**（取 → 写 → 取 → 写）——
仓内其余渲染器一直是这个形状，所以它们不受影响。

**结构性保证**：新增 `emitTo` / `emitFlameTo`，把"取缓冲 + 写入"并成一个方法，
调用方拿不到 `VertexConsumer`；另加 `CoreOrbBufferStructureTest` 守住这条结构。

**验证**：实机载入含该物品的存档 → 世界加载成功、快捷栏逐帧渲染该物品 →
日志零异常、零新增崩溃报告。

## 顺带修掉的既有问题

1. **`tools/textures/danmaku_weapon.py`（旧枪形图标工具）与 `core_orb.py` 抢同一个输出名** `item/danmaku_weapon` —— 后者先跑、前者后跑，导致**兜底图标一直是旧枪**。已删除前者。
2. **逐面虹彩微偏没用扇区中心** —— 24 扇区时色相从中心一路拉偏 ±135°，球会变成品阶外的杂色。已改为以中心为基准。
3. **外壳贴图灰度渐变过陡**（255→140）—— 挤出体与旋转体对 V 的解释不同，强渐变会切出硬边。已平缓化（250→210），仍 MUST 为灰度遮罩。
