## Why

「千机核心」重做后的形态没达到目的：**装什么核都还是那颗球，而且整颗球是白的。**

两个独立的问题叠在一起：

**问题一：渲染溢出，颜色被洗掉。** 现在的渲染器是 5 层叠，其中 4 层是加法混合，且 4 层**全都携带同一个饱和的品阶色**。亮度调制走的是 RGB 乘法 + 逐通道 `min(255, …)` 截顶：

```
阶 1 绿 #4CAF50 (76,175,80) × band 1.567 → (119, 255, 125)   ← G 通道截顶，色相自己漂了
加法求和（内层壳 + 焦点核 + 外晕 + 环绕环） → G 再截顶 → (160, 255, 168)  发白薄荷绿
阶 3 金 #FFC107 → R/G 双双截顶 → (255, 255, 12)  黄白
```

玩家看到的"整体是白色的"就是这条算术链的结果，**不是审美问题**。而且贴图层是纯灰度渐变（`core_orb_shell.png` 明确"色相由渲染器逐顶点调制"），资产层一点色相都补不回来。

**问题二：形态信息传达失败。** 「外壳随核变化」是上一轮变更的核心诉求，但现在的实现是**实心球壳 + 埋在里面的一个小符号**：

| 核 | 现在的焦点核 | 玩家实际读到的 |
|---|---|---|
| 飞刀 | **一片**平面刀身（`standingBlade`，单片） | 一根线 |
| 激光 | 一个 0.11 半径的小棱镜 | 一个点 |
| 单发玉 | 0.16 半径的小球 | 一个点 |
| 散弹玉 | 5 颗 0.085 半径的小珠 | 五个点 |

焦点核只占视高 40%，且形状全是抽象几何体。**玩家看不出"我现在拿的是飞刀还是激光枪"**——这正是"放 3 把飞刀""放个高科技激光枪"要解决的问题。

**问题三：语义反了。** 现在的空槽形态是一颗灰色小球（`EMPTY_COLOR = 0x8A90A4`），读作"没装东西的球"。但空核心是整件物品的**初始形态**——玩家拿到武器时看到的就是它。它理应是最有表现力的那一个（"沉睡的核心等待被唤醒"），而不是最灰的那个。

## What Changes

### 1. 未装核态 → 沉睡态：全彩流光球 + 火冠气焰

空核心**没有品阶**（品阶随装入的核而来），因此它是全光谱流光唯一合法的归属地。

- **全彩流光**：球面呈滚动彩虹，色相 `h(v, t)` 沿轴向参数连续流动；亮度调制**在 HSV 空间做**（色相在流，不是亮度在闪）。
- **火冠气焰**：8~12 条火舌从球面立起、尖端收成点、相位各异地舔动；**火舌根部取其下方球面的流光色**（同色源，不会割裂）。
- **球心暗腔**：球心保留一圈反向旋转的暗色涡旋（不是纯黑孔）。它同时承担三件事——保留"未装核"的可读性、作为气焰的根部、表达"在等待被填入"。

### 2. 装核态 → 外壳直接变成该核种类的武器轮廓

外壳不再是"容器"，而是**武器本身**。形态按 `DanmakuKind` 对齐：

| 核 | 种类 | 武器轮廓 | 核自带的"气" |
|---|---|---|---|
| 麟弹 | CONE | 三枚锥矢斜向前一字排开 | 每锥拖一条渐隐流光尾（速射连喷） |
| 单发玉 | SPHERE·单 | 一颗饱满大玉球 | 2 道旋转能量纬线 + 内部翻涌 |
| 散弹玉 | SPHERE·群 | 五颗小珠呈扇形散开 | 各带短拖尾 |
| 飞刀 | KNIFE | **3 把飞刀**（品字：1 前 2 后） | 刃口高光面 + 穿透拖痕 |
| 灵符 | TALISMAN | 方形符纸，四角封印钉 + 中央朱印 | 金色符文横穿纸面流动 |
| 激光 | LASER | **高科技激光枪**（侧面轮廓：枪管 + 散热鳍 + 发光电池 + 枪口聚焦棱镜） | 枪身发光带 + 枪口聚焦环 + 驻轴光轴 |

- SPHERE 的两种（单发玉 / 散弹玉）**MUST 不同**（既有 spec「同种不同形」硬条款），沿用既有的"核覆盖档案"机制。
- 激光机枪 / 激光炮**暂共用一个 LASER 档案**（按用户决定："目前只需要对齐各自的核种类就好"）。
- **气焰只属于未装核态**。装核后各武器形态自带辉光/轨迹，**MUST NOT** 另加气焰。

### 3. 色彩合成重构：加法预算 + HSV 空间

三条硬规则（可直接写成断言）：

- **R1 加法预算**：任一像素上所有加法层贡献之和 **≤ 85/通道**；本体层峰值亮度 ≤ 0.62（158/255）。二者相加 ≤ 243 → **结构上不可能截顶**。
- **R2 合成空间**：色相与亮度调制 **MUST 在 HSV 空间做**，MUST NOT 用 RGB 乘法 + 逐通道 clamp。
- **R3 品阶归属**：**只有装核态受品阶色约束**（品阶色 ±30°）；未装核态无品阶，全光谱合法。

同时把加法层**按色相分工**：同一色相 MUST NOT 被两个加法层同时持有（品阶色只归本体层持有，加法层走互补色/暖色），"全彩"由**层间色相分离**达成，而非全色相循环。

### 4. spec 同步（两处硬冲突）

- **`weapon-gui-visual`**：「MUST NOT 呈枪形轮廓」的场景与「球体色彩动态化」的 ±30° 要求**都需改写**——前者改为"未装核 MUST 呈球形核心轮廓 / 装核 MUST 呈该核对应的武器轮廓"，后者拆成未装核态（全光谱）与装核态（品阶 ±30°）两条。
- **`openspec/project.md` §5.4**：为"未装配形态（无品阶归属）"补一条例外条款——它不受品阶配色环约束，但装核后 MUST 立即回到品阶色 ±30°。

## Capabilities

### New Capabilities

（无——形态与色彩要求均落在既有 `weapon-gui-visual` / `danmaku-weapon` 两条能力上，不另立能力以免重叠。）

### Modified Capabilities

- `weapon-gui-visual`: 「弹幕武器图标为球形核心」改为「未装核呈沉睡态球形核心 / 装核呈武器轮廓」；「弹核外壳档案」的形态表整体重写（球形容器 → 武器轮廓）；「球体色彩动态化」拆为未装核态与装核态两条，并新增加法预算与 HSV 合成两条硬约束。
- `danmaku-weapon`: 「主武器玩家可见名称」中"该武器的形态 SHALL 为球形核心而非枪形"改为按装核状态分述；「外形随弹核变化」场景补充武器轮廓的具体形态要求。
