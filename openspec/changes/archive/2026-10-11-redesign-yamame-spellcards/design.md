## Context

黑谷山女是 T1 野生 BOSS，现有符卡表保留了原作四个名称，但当前实现把四张卡做成了「玩家周围收拢环 / 随机激光网 / 身后压墙 / 脚下光柱」的持续型组合。主要轨道以 `AROUND_TARGET`、`LATTICE`、`PILLAR_UP` 和 `FAN` 为中心，且分别以 16、20、22、30、38、44、46、50 tick 的周期异步重复。

这套实现有两个结构性问题：

1. 绝大多数威胁按照玩家当前坐标重新生成，玩家刚找到的站位不会成为下一轮的安全参考；
2. 异步周期没有共同的起承转合，上一批尚未离场时下一批已生成，视觉上是随机噪声而不是一个可学习的图案。

大妖精符卡已经证明，本项目的 `Beat.tick`、独立循环长度、寿命、编队参考点和显式多拍时间线足以表达「一段戏」，而不是只能表达「每隔 N tick 放一次」。本设计沿用该写法：所有具体参数先作为设计基准，最终实现参数必须通过实机调试校准，但不得破坏这里规定的结构关系。

## Goals / Non-Goals

**Goals:**

- 保留官方四张符卡名称和「网 / 瘴气」两组核心意象。
- 将第一、三张组织成同一语法的蛛丝编织系列，将第二、四张组织成同一语法的瘴气螺旋系列。
- 让每一轮都有可辨识的预备、展开、压力高潮和收束阶段。
- 为玩家提供可停留、可观察、可复用的安全区；躲避应当是读图案和选站位，而不是持续撤离。
- 让同一张卡的并发轨道围绕一个主图案服务，最多增加一条辅助压力轨道。
- 记录每张卡的玩家解法、失败原因、视觉身份、实现边界和验收指标，供后续实现与调参追溯。
- 保持符卡数量为 4，保持现有语言键和血量阈值顺序。

**Non-Goals:**

- 本变更不实现 Java、资源、配置或测试代码。
- 不把山女改成原作 2 套难度变体的另一套血量结构；游戏内仍使用四张阶段卡。
- 不强行逐帧复刻东方地灵殿的 2D 弹幕；所有图案必须适配 Minecraft 3D 空间与现有 R1/R2/R3 约束。
- 不以增加弹数、提高伤害或缩短玩家反应时间制造难度。
- 不在同一张卡中同时叠加「脚下点名 + 玩家周围收拢 + 压迫墙」三种立即位移要求。

## Decisions

### D1. 四张卡采用两套母题的“同语法升级”

四张卡的结构固定如下：

```text
1 罠符「キャプチャーウェブ」   稀疏蛛丝编织
2 瘴符「フィルドミアズマ」     中央瘴气螺旋
3 蜘蛛「石窟の蜘蛛の巣」       密集蛛丝编织
4 瘴気「原因不明の熱病」       三重瘴气螺旋
```

第一与第三张不再是两种互不相干的「网」攻击；第三张只增加网的层数、交叉和相位压力。第二与第四张也不再分别是「涡旋 + 激光网」和「涡旋 + 激光网 + 毒柱」；第四张增加的是螺旋数量和同步展开，而不是第三种完全不同的强制移动器。

理由：玩家可以从第一张学会“蛛丝网”的基本语法，再在第三张处理同一语法的复杂版本；第二张建立“螺旋会展开并冻结”的预期，第四张把同一预期扩展到左右两个副螺旋。

### D2. 每张卡使用统一的轮次时间轴

每张卡的主循环必须能被描述为：

```text
预备拍       识别 BOSS 动作与生成方向
    ↓
展开段       主图案逐步建立，给玩家选站位时间
    ↓
压迫段       图案达到峰值，但保留至少一条稳定解法
    ↓
收束段       弹幕离场、冻结弹回收或压力停止
    ↓
喘息窗口     玩家重新定位，进入下一轮
```

设计目标不是每张卡都必须有完全相同的 tick 数，而是每张卡必须有明确的阶段边界。推荐初始时间带如下：

| 段落 | 推荐时长 | 设计用途 |
|---|---:|---|
| 预备 | 20~40 tick | 让玩家看见第一批生成点和方向 |
| 展开 | 60~100 tick | 图案从稀疏变成完整构图 |
| 压迫 | 40~80 tick | 给出主要躲避决策 |
| 收束/喘息 | 20~40 tick | 清理旧弹并允许重新站位 |

`repeatEvery` 只用于真正的稳态背景轨。主图案必须优先使用 `repeatEvery(0)` + 显式 `Beat.tick`，并给 `SpellCard` 独立的循环长度。循环长度必须覆盖全部内容跨度；末尾空档若存在，必须是刻意设计的喘息而不是遗漏。

### D3. 目标中心不是默认的空间中心

`AROUND_TARGET`、`LATTICE` 和 `PLAYER_GROUND` 都会按照玩家最新位置刷新威胁。它们可以作为点名或辅助轨，但不得构成山女符卡的连续主图案。

主图案的空间中心优先级如下：

1. BOSS 当前发射位置或以 BOSS 为参考点的确定性编队；
2. 发射时锁定的玩家方向，但生成后不得反复重采样玩家位置；
3. 玩家周围生成的单次点名攻击，仅用于迫使玩家从“站定解”切换到短位移。

同一轮内，实时追踪型威胁最多承担一个明确职责。若主图案已经使用瞄准方向，辅助轨不得再同时使用脚下点名和目标周围随机网。

理由：玩家必须能够从已经出现的弹幕推断下一步，而不是被下一次目标重采样取消刚才的推断。

### D4. 第一张卡：罠符「キャプチャーウェブ」

#### 设计意念

山女不把网直接套在玩家身上，而是从自己手中一根一根拉出蛛丝。网尚未闭合时，玩家可以站在已知缝隙中；网逐渐补齐后，玩家需要沿着仍在移动的缺口横向或竖直换位。

```text
稀疏辐条 → 交叉补线 → 网面成形 → 网线离场
```

#### 推荐轨道

主轨「织丝」：

- 使用 `FAN` 发射引线弹，每颗引线弹挂 `Trail` 行为沿路留下静止网点（见 D11）。
- 每轮分 4~6 个生成批次，不一次铺满。
- 每批方向围绕 BOSS→玩家方向有明确的角度偏移，奇偶批次使用相反偏移。
- 批次间应保持可数的缺口，缺口相位缓慢移动，不随机跳跃。
- 每批弹速、尺寸和颜色一致，使玩家把它们读作同一张网。

辅助轨「追丝」：

- 只在织网中后段出现少量瞄准弹，数量低于主轨。
- 它承担“山女发现玩家站位”的点名，不承担持续封锁。
- 追丝出现后必须留下可绕开的横向或竖向空间。

#### 推荐时间线

```text
0~20      山女转身，第一组 4 条蛛丝出现
20~60     第二、三组蛛丝补入，形成宽缺口
60~100    第四、五组蛛丝交叉，缺口开始横移
100~140   少量追丝点名，玩家从缺口横移到下一格
140~180   旧网线继续飞出并离场，不再生成新网
180~220   喘息，开始下一轮
```

循环长度建议先按 220 tick 作为设计基准，实际寿命必须保证上一轮大部分弹在下一轮前离场。

#### 玩家解法

玩家应能做到：

- 第一轮站在宽缺口中观察；
- 根据下一批蛛丝的角度，向相邻缺口移动；
- 追丝出现时只需短位移，不需要连续绕场；
- 网线飞过后可以回到 BOSS 正面附近输出。

#### 禁止事项

- 不使用每 16~20 tick 一次的 `AROUND_TARGET` 作为主轨。
- 不让主轨每一批重新随机采样玩家周围的生成点。
- 不在本卡同时加入脚下光柱或闭合激光网。
- 不让所有蛛丝都直接瞄准玩家当前位置；网的美感来自交叉结构，瞄准只由辅助轨承担。

### D5. 第二张卡：瘴符「フィルドミアズマ」

#### 设计意念

瘴气不是一批随机激光，而是从山女身边长出的一团有中心、有旋向、有膨胀过程的螺旋。螺旋膨胀后，部分瘴气凝结成静止危险点，另一部分继续向外流走，形成“满场但不封死”的层次。

```text
中心螺旋 → 向外膨胀 → 奇数批凝结 → 偶数批穿出 → 中心重新生成
```

#### 推荐轨道

主轨「瘴涡」：

- 以 BOSS 发射位置为编队中心，不以玩家当前位置为中心。
- 使用确定性旋转编队，螺旋的平面朝向玩家但生成后保持该批快照。
- 通过呼吸缩放或沿法线推进表现膨胀，不通过随机改变每枚弹的方向表现。
- 奇数批与偶数批有明确颜色区分，例如红与紫。

冻结轨「凝瘴」：

- 与「瘴涡」构成「走 / 停」两批，而不是把一批拆成两半（裁决见 D13）。
- 「停」批在飞行中减速并定住，保持命中判定。
- 冻结位置必须分布在螺旋展开路径上，形成可预测的弧线或间隙。
- 冻结弹必须有寿命上限，在本轮结束前回收，不能积累成永久墙。

「停 / 走」两批分别用「减速定住」与「膨胀外扩」两套运动表达，不使用批内分组（裁决见 D13）。不得退回到“用一组随机激光代替冻结螺旋”。

#### 推荐时间线

```text
0~30      中央螺旋成形，弹速低，玩家看见旋向
30~90     螺旋缓慢膨胀，外缘出现可穿越的扇形缝
90~130    红色分组减速并凝结，紫色分组继续外扩
130~180   凝结弹构成静态弧线，玩家沿弧线间隙移动
180~220   紫色弹离场，红色凝结弹逐批消失
220~260   喘息并重置旋向
```

循环长度建议先按 260 tick 作为设计基准。

#### 玩家解法

玩家应当观察旋向和凝结位置，选择：

- 留在尚未被凝结弧线覆盖的内侧缺口；
- 在紫色弹外扩时穿过相邻弧线；
- 不需要因为螺旋生成就立即远离玩家当前位置。

#### 禁止事项

- 不用每 16 tick 刷新的 `AROUND_TARGET` 作为螺旋替代物。
- 不把 `LATTICE` 作为与螺旋无关的第二个随机主图案。
- 不让冻结弹没有寿命或冻结在玩家脚下。
- 不让冻结轨与移动轨互相覆盖到没有安全弧段。

### D6. 第三张卡：蜘蛛「石窟の蜘蛛の巣」

#### 设计意念

第三张是第一张“织网”的石窟版本，不是全新的三种攻击叠加。石窟让蛛丝从上、下和侧面形成具有纵深的网幕，但所有网幕仍然遵循同一轮次和同一缺口逻辑。

```text
第一张：平面蛛丝网
第三张：平面网 + 纵深网幕 + 缺口移动加快
```

#### 推荐轨道

主轨「石窟织网」：

- 以 6~10 条蛛丝为一轮，分批生成。
- 采用两个相互错开的竖直编织平面，平面之间必须有可辨识间距。
- 两个平面不同时闭合；一个平面成形时，另一个平面必须保留可穿越方向。

辅助轨「压网」：

- 可使用 `DISC_RING` + `RECLAIM` 表现一面先悬停、再缓慢压来的网幕。
- 网幕必须有明显预警期，且只在主轨的一轮收束后出现。
- 压网是空间压力，不得与脚下光柱和目标周围收拢同时运行。

#### 推荐时间线

```text
0~30      后方/侧方网幕显形但不启动
30~90     第一面石窟蛛网逐批织成
90~130    第一面缓慢压近，第二面开始从另一侧织入
130~180   两面错位交叉，保留一个可识别的斜向通道
180~220   第一面离场，第二面短暂保持
220~260   全部收束，喘息
```

循环长度建议先按 260 tick 作为设计基准。

#### 玩家解法

玩家应当沿斜向通道穿过两面网幕，必要时利用 Minecraft 3D 的上下移动绕过竖直网面。玩家不应需要持续后撤到攻击范围之外；攻击范围本身应当是可穿越的空间结构。

#### 禁止事项

- 不同时运行 `DISC_RING`、`PILLAR_UP`、`AROUND_TARGET` 三个独立压力源。
- 不让两面网幕在同一 tick 完全闭合。
- 不让压网追踪玩家当前位置改变其生成面；生成后网幕方向必须稳定。
- 不用随机激光填充网幕空隙；空隙是玩家解法的一部分。

### D7. 第四张卡：瘴気「原因不明の熱病」

#### 设计意念

热病不是“更快的第二张卡 + 毒柱”，而是第二张中央瘴气螺旋的高热版本：中央大螺旋和左右两个小螺旋同步展开，三者共享奇偶冻结规则。中央螺旋负责主构图，左右螺旋改变安全区的宽度。

```text
          左侧小螺旋       右侧小螺旋
                    ╲     ╱
                    中央大螺旋
```

#### 推荐轨道

主轨「热病中心」：

- 中央大螺旋，速度和展开频率高于第二张，但必须保留内侧或外侧安全弧。
- 奇数批凝结为红色高热点，偶数批紫色继续外扩。

辅助轨「热病双侧」：

- 左右两个小螺旋应作为同一轨的两个固定生成实例，或作为两条共享时间线的视觉子组。
- 两侧生成点相对 BOSS 的位置在发射时确定，不跟随玩家最新坐标。
- 小螺旋成形更快，但与中央螺旋在同一时间开始外扩。

可选低频轨「病热点名」：

- 只有在实机确认三螺旋本身不足以形成站位决策时才能加入。
- 每轮最多一次，使用少量 `AIMED_SINGLE` 或窄 `FAN`。
- 不得加入持续 `PILLAR_UP` 毒雨；毒雨会把三重螺旋的空间构图变成脚下逃跑题。

#### 推荐时间线

```text
0~30      中央螺旋预备，左右两侧出现小型预兆
30~70     中央螺旋成形，左右小螺旋快速补齐
70~120    三个螺旋同步外扩，内外安全区交替出现
120~170   第一批红色瘴气凝结，紫色瘴气继续穿场
170~220   左右小螺旋先收束，中央螺旋保留最后一圈
220~260   中央螺旋消散，短暂喘息
```

循环长度建议先按 260 tick 作为设计基准。第四张的难度优先来自安全区变化速度和三组图案的空间关系，而不是无限提高弹数。

#### 玩家解法

玩家可以选择三种稳定策略之一：

- 留在中央螺旋的内侧缝隙，观察两侧小螺旋外扩；
- 向一侧移动，利用小螺旋先收束的时间窗口穿过边缘；
- 在中央红色凝结弧形成前换到另一条安全弧。

玩家不应必须持续远离 BOSS，也不应被脚下攻击强迫离开所有螺旋安全区。

### D8. 默认攻击是低负担底噪

当前山女默认攻击每 40 tick 发 5 发蛛丝扇，与第一张符卡的追丝轨视觉重复。重做后默认攻击必须满足：

- 继续独立于 `BossCards`，不计入符卡轨道数；
- 频率和数量从 config 读取；
- 符卡中不得与主图案争夺视觉中心；
- 不得成为玩家需要持续处理的第二套符卡。

推荐初始定位：符卡期间降低为低频、少量、固定颜色的 2~3 发宽间隔瞄准弹；若实机仍造成视觉噪声，则符卡期间暂停默认攻击。这个选择属于实现调参项，但“默认攻击不得改变符卡主解法”是硬约束。

### D9. 现有原语与新能力边界

可直接复用的能力：

- `FAN`：少量蛛丝辐条与低频点名；
- `DISC_RING` + `RECLAIM`：有预警的压网；
- `Formation.spin` / `withBreathing`：确定性螺旋展开；
- `SPEED_PROFILE`：减速、停留和外扩速度；
- 显式 `Beat.tick` + `cycleTicks`：阶段时间线。

可能需要独立实现的能力：

- 一批蛛丝在多个固定平面之间编织且保持相位关系；
- 同一螺旋按分组让一半冻结、另一半继续推进；
- 冻结弹保持 AABB 命中判定并按批次寿命回收；
- 多个螺旋共享一套启动、膨胀、冻结、收束时钟。

实现阶段不得用无关随机轨道掩盖这些能力缺口。若能力确实缺失，应先开独立设计/实现任务，并把能力边界写回对应弹幕 spec。

> 上面两类能力现已逐条裁决：蛛丝 = `Trail` 引线弹 + 静止尾珠（D11）、螺旋 = 新 `SPIRAL` 形状（D12）、冻结 = 两批走/停（D13）、跨批次中心一致性 = 织网/展开期 `movementLocked()` 锁位（D14）。形状 / 行为 / 字段的完整映射与「现有 / 需新增」状态见 **D15 映射表**。

### D10. 设计验收标准

实机或预览验证每张卡时，必须回答以下问题：

1. 玩家能否在第一轮停下来观察至少一个完整生成动作？
2. 玩家能否指出当前主图案的中心、旋向或织网方向？
3. 玩家是否能找到一个持续至少 20 tick 的安全区或安全通道？
4. 主图案是否在生成后保持连续，而不是每批重新随机换形？
5. 玩家是否因为图案本身移动，而不是因为脚下/玩家中心重采样，被迫改变位置？
6. 一轮结束前旧弹是否按预期收束，下一轮是否不会与上一轮无限叠加？
7. 默认攻击是否仍然能被识别为底噪，而不是第二张符卡？
8. 关闭或降低默认攻击后，符卡主图案是否仍然成立？若不成立，说明主图案本身不足。

只有在这些问题大体成立后，才允许通过 `TrackLint`、实体容量和伤害数值测试进入平衡调试。

### D11. 蛛丝的落地定义：引线弹 + 静止尾珠（Trail）

裁决「一条蛛丝是点还是线」的空白。**蛛丝只用于第 1、3 张（网系）**；第 2、4 张（瘴系）不使用。

一条蛛丝由两部分组成：

```text
引线弹（spinner）  从 BOSS 手中沿固定方向射出，可见、可命中，继续飞行
     │  每 trailEvery tick 在【当前所在位置】丢一颗
     ▼
尾珠弹（node）     零速静止、保持命中判定、有独立寿命 —— 它就是玩家读到的「网线」
```

- 一批蛛丝 = 一个 `FAN` 内的 N 颗引线弹同时射出，各自沿自己的方向拉线。
- 引线弹飞完自身寿命后消失；尾珠按 `webLifetime` 分批回收。

**行为边界（与 `Split` 的关系）**

- `Trail` 属**行为轴**：它不改变命中语义，只是周期性生成同类静止弹，与 `Split` 并列。
- `Trail` 与 `Split` MUST NOT 同时挂载（lint 拒绝）：二者都“生成子代”，同时开会语义打架。
- 尾珠 MUST 走静止 AABB 接触判伤（`AbstractDanmakuProjectile#checkStationaryEntityHit`，已存在；这是坑 6 的兑现）。
- 尾珠 MUST 由服务端生成并计入 `DanmakuBudget`（与 `Split` 同一路径，`DanmakuBudget.recordSplit` 是既有先例）。

**密度约束（当前 lint 看不到，MUST 补）**

- 尾珠不由任何 `beat.params().count()` 声明，故 `TrackLint.steadyStateEstimate` **完全看不到它们** —— 这是一个静态盲区。
- 一张网的尾珠总量 ≈ 引线弹数 ×（引线寿命 ÷ `trailEvery`）。
- 建议初值（待实测）：引线弹 4~6 颗、寿命 60 tick、`trailEvery = 2` ⇒ 每根丝 30 颗尾珠、一张网约 120~180 颗。
- 每张网系卡 MUST 声明**尾珠预算**，`trailEvery` 与引线寿命受其约束。**`trailEvery = 2` 是观感目标，不是可以无限叠加的免费参数。**

### D12. 新 Shape：SPIRAL（螺旋排布）

用于第 2、4 张（瘴系）。在「面向目标」的竖直平面内，按阿基米德螺线
`r(θ) = r_in + (r_out − r_in)·θ / θ_max` 排布 `count` 颗弹。

- 每颗弹的初速方向 = **平面法线（`forward`）**，与 `ROSETTE` 一致：平面内形状由编队帧负责，行进沿法线（对齐 skill「行进方向 MUST 是平面法线」）。
- 参数复用（沿用项目「同字段在不同形状各有含义」的既定做法）：
  - `count` = 弹数
  - `radius` = 外半径 `r_out`
  - `radialAmp` = 内半径 `r_in`（`0` 则从中心起）
  - `petals` = 圈数（≥1；**符号决定旋向**，与「负幅度只换朝向」的既有约定一致，越界由 `Geometry` 夹取）
- 膨胀由 `Formation.withBreathing` 对出生偏移 `u₀` 等比缩放给出，MUST NOT 用随机方向伪造。

### D13. 半批冻结的裁决：两批（走 / 停）

裁决原 D5 里「奇数批凝结」与「选中的一半弹」两种写法的矛盾。**采用两批读法**：

- 一次撒出的瘴气分成「停」与「走」两组，**每组都是一个完整螺旋**。
- 「停」批：`SPEED_PROFILE.decelerateAndHold` + 不挂会持续缩放的编队 ⇒ 到龄凝固定住，构成静止弧。
- 「走」批：编队呼吸（膨胀）+ 沿法线推进 ⇒ 持续外扩并离场。
- 两批错开生成（交替 tick 或两条轨），于是读作「一批停住时另一批在走」。
- **取消“同一批内各冻一半”的写法**：现有原语不支持批内分组，且它会让尾珠 / 密度不可控。

### D14. 跨批次中心一致性与织网移动锁

- **网系（1、3）**：织网阶段 MUST 锁 BOSS 移动，使多批引线弹共享同一中心，尾珠才能连成一整张网。复用既有 `movementLocked()`（`AbstractTouhouBoss:599`；大妖精环卡按卡下标 + `cycleTick` 已用此机制），在 `YamameEntity` 里按山女卡下标 + 织网结束 tick 覆写。
- **瘴系（2、4）**：以 BOSS 眼位为编队中心快照；展开段同样建议锁位，使「停」批的静止弧与「走」批的膨胀螺旋共享同一中心。
- 明确：`movementLocked()` 是**既有能力**，不是新增。
- 不锁位的后果：每批圆心随 BOSS 游走而偏移，网 / 螺旋在批次之间错开 —— 这正是大妖精环卡必须单拍或锁位的原因（`BossCards` 环卡注释记过这一现象）。

## Risks / Trade-offs

- [确定性图案比随机网更容易被熟练玩家背板] → 用相位推进、缺口移动、奇偶旋向和 BOSS 移动制造变化；变化必须来自可读参数，不来自无提示随机重采样。
- [减少目标追踪后，多人场景可能出现玩家站位过于安全] → 保留每轮最多一个低频点名轨，并按 `AIMED` 的多目标语义复制；不把整张卡改回每人一套随机中心弹幕。
- [三维蛛丝网难以表达] → 优先使用竖直面、斜向通道和上下绕行解；若必须新增几何，保持局部基向量表达和离线可测，不为单个地形写特判。
- [冻结弹容易永久占用实体或失去命中判定] → 使用已有绝对寿命和静止 AABB 判定约束；冻结轨必须声明寿命，实机验证离场与回收。
- [显式时间线参数较多，后人调参可能破坏节奏] → 每张卡独立命名循环常量，保留本设计中的阶段表、禁用组合和验收问题；不得只改一个 `repeatEvery` 解决观感问题。
- [默认攻击与符卡默认叠加导致意外增压] → 默认攻击的低频/暂停策略写入山女能力 spec，并将其作为独立验收项。
- [尾珠是行为生成的静态弹，`TrackLint` 稳态估值看不到] → 每张网系卡声明尾珠预算并运行时计入 `DanmakuBudget`；`trailEvery` 与引线寿命受预算约束，不得只靠「视觉刚好」定值。
- [`SPIRAL` 与左右横向偏移是新增几何，落地成本未知] → 先在预览命令里用最小参数验证螺旋排布与膨胀，再决定 `offsetRight` 还是同心内外圈；不通过则回退到同心读法，不为单张卡写地形特判。

## 修订（2026-10-11 反馈后）

实机观感反馈：蛛丝太短太稀且共面、瘴气只在 BOSS 身边无威胁、衍生弹不散、第四张可被绕圈规避。已按下述调整：

1. **蛛丝改为半球随机散射**：网系（1、3）主轨由平面 `FAN` 改为 `CONE_RANDOM`（`spread=180` 即朝玩家的半球），每轮 3 子拍 × 6~7 根 = **18~21 根**；单拍 <8 发故不触发 R2。引线弹寿命 60、尾珠寿命 **100（约 5 秒）**、生成间隔 4。
2. **尾珠会飘散**：`Trail.drifting(every, lifetime, hold, drift)`——尾珠静止 `hold=40`（约 2 秒）后，各自沿**随机方向**以 `drift=0.06` 缓慢漂移。实现走「速率曲线 0 速段（静止判伤）→ 段后沿出生随机轴漂移」，不新增运动种类。
3. **瘴气加威胁**：卡 2 与卡 4 各新增 `瘴散` 轨——`CONE_RANDOM`（半球）慢速向外（`speed≈0.14`）；卡 4 更稀疏（count 5，周期 80），使玩家无法只靠绕圈规避。
4. 卡 4 轨道数 3 → 4（`MAX_TRACKS=5` 之内）。

新增/扩展的引擎能力（`extend-danmaku-track-primitives` 未覆盖的部分，在本变更内实现）：

- `Behaviour.Trail` 增加 `holdTicks` / `driftSpeed` 与 `Trail.drifting(...)`；
- `AbstractDanmakuProjectile` 增加 `DATA_TRAIL_HOLD` / `DATA_TRAIL_DRIFT` 同步与 NBT；
- `SphereDanmaku.spawnTrailChild` 支持「先静止后随机漂移」的尾珠。

> 注：尾珠的随机漂移方向是**出生时定死的**（沿出生随机轴），不是每 tick 乱窜——这正是 `alongAxis` 在零速后回落到持久化方向轴的用法。

## 修订 2（2026-10-11 反馈：丝线仍太短）

实测反馈：丝线仍然很短、衍生弹消失快，质疑「是不是有别的地方给干掉了」。

**查明的真因**：`DanmakuHitScan.sweep` 对每发弹都做一次方块 clip（`level.clip(COLLIDER)`）。引线弹朝玩家半球发散，而 BOSS 悬在玩家上方，**大量丝线直接扎进地面，几格就销毁**；尾珠也因同样的地形/玩家接触提前回收。不是生命周期、不是预算，是方块碰撞。

**修法**：

1. 新增弹种 `Projectile.piercingSphere()`（穿透方块）：`DanmakuHitScan.sweep` 增加 `clipBlocks` 开关，`AbstractDanmakuProjectile` 增 `DATA_PIERCE_BLOCKS`；网系引线弹与瘴气/瘴散全部改用穿透球弹，从而飞完自身寿命、拉出完整长线。
2. **头弹更大、颜色区分**：引线弹尺寸 0.5 → **0.75**；尾珠尺寸 = 头弹 × 0.55、颜色向白混 0.5（`SphereDanmaku#lighter`），与头弹明显区分。
3. **尾珠更耐久**：寿命 100 → **120 tick（约 6 秒）**。
4. 瘴气/瘴散补上 `YAMAME_MIASMA_LIFETIME = 120` 的寿命，避免低速弹无限累积。

引擎侧新增（`extend-danmaku-track-primitives` 的两张 delta spec 已补）：
- `Trail` 的 `holdTicks` / `driftSpeed`（先静后漂，方向出生定死）；
- `Projectile` 的「穿透方块球弹」变体（改的是命中判定 → 属弹种而非行为）。
