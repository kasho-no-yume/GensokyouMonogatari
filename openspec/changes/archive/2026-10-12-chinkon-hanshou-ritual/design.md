## Context

现有 BOSS 专属产物有两条来源：击杀主题 BOSS 保底掉落的**主题信物**（`#gensokyou:boss_signature`：fairy_nectar / earth_spider_silk / nightfall_core / sukima_fragment）与 `1~2` 个**碎符卡星**。二者是符卡合成（源初造化）与百鬼夜行召唤配方的关键料，但只能靠重复讨伐获得。

既有的「众生余录」（`shujou_yoroku_circle`）建立了「典籍 → 原版死亡战利品」的转化范式：读取**满 20** 的众生典籍（不消耗）、按 species 掷原版掉落表。但它**明确排除 BOSS**——`CodexOfBeingsItem.canCapture` 命中 `#gensokyou:bosses` 即拒收，因此 BOSS 永远进不了典籍。

本变更为 BOSS 产物提供一条**灵力换产物**的回收路径，并在既有典籍体系上开一个「以信物为凭依、让典籍记下它记不下的存在」的分支。

结构 pattern 已先行落盘：`src/main/resources/data/gensokyou/rituals/chinkon_hanshou_circle.json`（1~5 阶，v5 增量，`toggleable:false`，`tiers:[1,2,3,4,5]`），离线校验 0 ERROR / 0 WARN，测试包已重建。

## Goals / Non-Goals

**Goals:**
- 提供「击败 BOSS 一次 → 可反复获得其专属产物」的灵力消耗路径，消除重复讨伐。
- 复用既有仪式框架（`RitualBehavior` / activation 语义 / 灵力四件套 / 空投 / 光柱 / GUI / config / 探针），不新造横切架构。
- 与「众生余录」形成姊妹叙事，且两者输入物**互不串味**（残魂典籍不得被众生余录识别）。
- 阶级门槛与既有 `bossTier()` 严格挂钩。

**Non-Goals:**
- 不做周期自动化的「Boss 产物农场」（本仪式为激活型一次性，非启停周期型）。
- 不改动主题信物在源初造化/召唤配方里的既有用途。
- 不为无信物的 BOSS（当前：傩面 T2、芙兰 T5）造信物。
- 不解决「高阶 BOSS 尚未落地」的内容缺口（2~5 阶预付）。

## Decisions

### D1 触发形态：激活型一次性（而非启停周期）

「消耗供品 + 一次性镇魂演出」在语义上是一次性仪式；周期运转会把它读成"自动农场"，冲击经济设计（见 Risks）。

- **选择**：激活型——pattern `toggleable:false`；摆齐供品后走自定义 UI 按钮；供品在启动当刻吞掉；灵力在可执行时全有全无地扣除；产物以聚合空投落于核心半径 3 圆盘内。
- **备选**：启停周期型（像众生余录）——被拒，因「消耗典籍」与「持续结算」语义冲突，且产出会变成无人值守的资源泵。
- **复用**：`SunakoBrewing`（一次性批次 + 原位消耗 + 空投）与 `hyakki-yagyo-summon`（自定义按钮 + activation 校验）。

### D2 阶级门槛：结构层号 ≥ BOSS 自身品阶

用 `TouhouBoss.bossTier()`（编译期常数、与数值平衡解耦）作门槛，取 `RitualMatch.level()`（结构层号，**不用** `minTier`）比较。

- **选择**：`结构层号 >= bossTier` 放行，`<` 拒绝（低阶结构不得产出高阶 BOSS 产物）。高阶结构自动向下兼容低阶 BOSS（与既有「高阶结构可满足低阶配方」语义一致）。
- **备选**：一一对应（N 阶只处理 `bossTier==N`）——被拒，使 2~5 阶当前全空转且无兼容性。

### D3 残魂典籍 = 独立注册物品（而非众生典籍的数据组件变体）

- **选择**：新物品 `gensokyou:boss_residual_codex`（独立 `Item` 类），携带数据组件编码 `{boss: ResourceLocation, tier: int}`。
- **理由**：众生余录的识别判据是 `stack.getItem() instanceof CodexOfBeingsItem && isFull`；独立物品类**天然**被排除，无需给众生余录加特判（避免污染其契约）。同时残魂典籍不需要"收容"语义，套用典籍的组件语义反而累赘。
- **备选**：给众生典籍加「已寄宿」组件——被拒，因会强制众生余录新增排除分支，违反"输入物互不串味"的目标。

### D4 合成路径：两条原版工作台配方（含数据组件输出）

- **选择**：
  1. **残魂典籍**：`空的众生典籍 + 该 BOSS 的主题信物` → `boss_residual_codex`（每只带信物的 BOSS 一条配方；结果写入 `{boss, tier}` 组件）。配方结果 MUST 使用数据组件指定 BOSS 身份——同一泛用物品、N 条配方区分。
  2. **清空典籍**：`任意众生典籍（含满 20）` → `空的众生典籍`；单物品无序配方。
- **理由**：两条合成均无灵力/仪式语义，且需要随时随地可用（不是"基建"），走原版工作台最直接；清空配方与残魂配方同构，便于玩家理解。NeoForge 1.21 配方结果支持 `components`，足以表达 BOSS 身份。
- **备选**：走「源初造化之仪」配方——被拒，因造化是会话型仪式、要耗灵且要摆台，把"准备原料"这一步也仪式化会让整条链过于笨重；且清空典籍是纯整理性操作，不该有仪式门槛。

### D5 产出映射与随机口径

- **碎符卡星**：`0~1`（独立掷骰，主产物之外的"顺便"产出）。
- **主题信物**：`1~2` 件，取该 BOSS 的 `signatureItem()`；BOSS 无信物时该项为空。
- **设计意图**：主角是信物，碎星是添头。玩家投入 1 件信物 → 期望回吐约 1 件信物 + 少量碎星，净产出靠"灵力"而非"物品重复"。
- **可调**：碎星上/下界、信物上/下界一律进 `GensokyouConfig`。

### D6 灵力成本与容量：全有全无的批次扣费

- **选择**：单次成本 = `base × mult^(BOSS 品阶-1)`（**随所镇 BOSS 的品阶放大，不随结构阶级**；与 `shujou` 的指数口径同构，默认量级对齐"大型仪式需电容/路由"）；缓存容量按结构阶级 = `capBase × capMult^(结构层号-1)`，保证能覆盖该阶级可处理的最高 BOSS 品阶成本。扣费走既有三段式（槽内灵力核心 → 核心缓存 → 半径 3 内其他核心）；**全有全无**——灵力不足时拒绝执行、不吞供品、不产出（与众生余录同构）。
- **理由**：一次性仪式用"瞬时足额校验"比 hyakki 的"会话充能"简单得多，且不引入会话相位状态机。
- **可调**：成本基值、每阶倍率、受灵速率进 config。

### D7 产出表现：冷色光柱 + 聚合空投

- 仅在产出那一刻触发一次巨大光柱，服务端不逐 tick 广播粒子（走客户端 BER，同步最小渲染态）；配色**冷色（青白）**，与众生余录的**紫色**光柱形成一眼可辨的对照。
- 产物同位复用「核心为圆心、水平半径 3 圆盘内随机落点」。

### D8 结构 pattern 与供品台

- pattern 已落盘（1~5 阶）。功能上仅需 1 件供品（残魂典籍），但四方对称结构自然生成 4 个祭品台——**1 台实用，其余留白**（未来可扩为多件供品）。
- 已保留程序侧空位：核心四向 `(0,1)@y0`、核心正上方 `(0,1,0)`、电容槽 `(2,2)@y1`。

### D9 满态可清空（BREAKING，修订 codex-of-beings）

- 用户决定：清空合成对**满 20** 的典籍同样有效。这取消 `codex-of-beings` 的「满态不可逆终态」不变量。
- **理由**：若满态不可清空，玩家填错的典籍只能丢弃，而残魂合成要求"空典籍"，会造成大量浪费。
- **代价**：满态不再有"不可逆的仪式感"。**缓解**：清空配方可考虑加象征性代价（见 Open Questions）。

## Risks / Trade-offs

- **[经济循环失控]** 信物与碎星变为灵力可再生资源，可能比打 BOSS 更划算，架空百鬼夜行与击杀循环 → 碎星压到 `0~1`、信物回吐期望 ≤ 投入、成本随阶指数放大；数值经 `docs/balance-test-harness.md` 调平。
- **[满态清空取消不可逆]** 降低满态成就感的终局性 → 可给清空配方加代价或保留成就；待定（Open Questions）。
- **[高阶空转]** 2~5 阶当前无带信物的高阶 BOSS → 明确标注为预付结构件，随高阶 BOSS 落地自动启用。
- **[与众生余录串味]** 若残魂典籍用众生典籍的数据组件实现，会被众生余录误识别 → 以独立物品类规避（D3）。
- **[pattern 劫持/匹配]** 已由离线校验器拦截（0 ERROR / 0 WARN）。

## Migration Plan

- 纯新增内容，无需数据迁移；已存在的满态/未满典籍存档不受影响（仅新增一条可选的清空配方）。
- 回滚：移除 behavior 注册、物品、配方与 pattern 文件即可，无残留状态（产物是普通物品）。

## Open Questions

- 残魂合成与清空合成最终走**原版工作台**（D4 选择）还是改由「源初造化之仪」承载？
- 「清空典籍」是否需要象征性代价（灵力/材料）以保留满态的分量？
- 碎星/信物的具体期望值与单次灵力成本数值（待平衡测试台定稿）。
- 无信物的 BOSS（傩面/芙兰）将来补信物后是否一并纳入本仪式？
