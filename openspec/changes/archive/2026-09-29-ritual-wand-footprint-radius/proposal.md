## Why

两条**摆放规划**信息都缺失，且缺失方式不同：占地的缺失让升级被静默拒绝（硬阻断），而高度的缺失让玩家一开始就挖错坑位（升级时才发现）。

**一、占地：升级被静默拒绝。** `RitualBuilderPlacement.classify()` 把「非空气且不满足谓词」的格位丢进 `conflicts`，而 `build()` 在 `conflicts` 非空时直接返回 `blocked = true` 拒绝整次搭建。关键在于 `ritual_stones` 标签**只含 `ritual_stone_0..5`、不含 `ritual_core`**——所以邻居仪式的核心落在你的占地范围内时会被判为冲突，升级被静默拒绝，界面上只画一个红框，不解释原因。

**二、离地高度：挖坑时机太晚。** 仪式结构**向上、向下都会长**，而向下那部分是随阶级**递增加深**的（累积切片语义）。核心坐标一旦放下就固定不变，所以放置时若不预留净空，升级到高阶时新出现的地下格位会落在实心里：

```
zaohua     L0 最低 -2  →  L5 最低 -7     每升一级多挖一层
haniyasu   L0 最低 -3  →  L2 最低 -5
hyakki_yagyo L1 最低 -1 →  L3 最低 -3
zaohua 的 L4 整座结构都在核心之下（该级最高格位 = -1）
```

而挖坑是**硬阻断**（同上一条：被占格位 → conflicts → 拒绝搭建）。玩家只能看到画在地下、看不见的红框，猜要挖多深。

**膨胀倍率很高，且极难预判**（23 个图案实测，Chebyshev 半径 = `max(|x|,|z|)`，取各图案**最高阶**）：

```
                        逐阶累计占地半径（正方形半宽）
  前期小结构   saI_energy L0:1     wujinzang L0:3    kukunochi L0:3
               kagutsuchi L0:4    zaohua L0:4        hannyasu L0:3
  ───────────────────────────────────────────────────────────────────
  会长大的     wujinzang   L0:3  → L5:18   (6.0×)   ← 膨胀最剧烈
              zaohua      L0:4  → L5:20   (5.0×)
              seii        L1:6  → L5:22   (3.7×)
              bafang_gu.  L2:8  → L5:19   (2.4×)
  ───────────────────────────────────────────────────────────────────
  顶级占地     seii 22 · zaohua 20 · bafang_guiyuan 19 · wujinzang 18
```

一个玩家按 L0 的 `wujinzang` 半径 3 摆位（核心间距 7 格），到 L5 时每座结构宽 37 格——**必须整体拆迁**。

## What Changes

仪式构建器界面在选中图案时，显示两个**摆放规划**数值（均取该图案**最高可建阶级**的累积切片，故为稳定常量——摆放一次即可长期参考）：

### 1. 建议离地高度 = `|minY|`

**语义：把核心放在离地 `H` 格，最高阶最深的格位正好落在地面高度上，全程零开挖。**

```
   建议离地高度  H = |minY(最高阶)|
   （LevelSlice 是累积切片，天然覆盖所有低阶）

   示意图（结构有 6 层在核心下、100 层在核心上）

        ↑ 上方 100 层，不构成任何约束，本值不关心
   ─────┼────────────────────────────────────
        ●  ← 核心，置于离地 H=6 处
   ─────┼────────────────────────────────────
        ▓▓  下方 6 层，正好落在地面以上
   ══════════════════════════════════════════ 地面
```

**只取 `minY`、不取 `maxY`/`maxY` 与结构总高无关。** 上方有多少层不产生摆放约束——核心往上放不冲突。

### 2. 最大占地半径 = `max(|x|, |z|)`

`maxChebRadius`，Chebyshev 半径。已核验 23 个图案的 XZ 包围盒**全部接近正方形**（长宽比 ≥ 0.87），故用半径不会低估或误导。

**核心间距约束是不对称的**：一个已达 L5（半径 20）的 `zaohua` 旁边，即便对方只是个 L0（半径 3）的 `sair_energy`，中心距也需 23 格。

> **两核心中心距 ≥ 本仪式半径 + 对方仪式半径**

杖子只知道自己这一侧的图案，给不出对方的值，所以 tooltip 必须显式讲清这条加法规则。

**实现载体**：`RitualBuilderScreen` 左列图案列表下方的空白条（`LIST_Y=24` + `LIST_ROWS 7×ROW_H 20` ⇒ 列表止于 y=164；面板高 196 ⇒ y 164~196 空闲；材料区在 x≥132 的右列，横向不冲突；该处也在列表滚轮命中区 24~164 之外，不干扰滚动）。已确认该屏**没有** `InfoLine` 通道（全手绘 `drawString`），故按现有风格加两行普通文本，不为此另开并行机制。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `ritual-builder-menu`: **新增**摆放规划数值展示要求——建议离地高度（`|minY|`）与最大占地半径（`|minX|`/`|Z|` 推导的 Chebyshev 半径），均取最高可建阶；tooltip 说明"零开挖"语义与"中心距 = 两半径之和"的不对称规则

## Impact

- `RitualPattern.LevelSlice` — 新增 `minY()` 与 `maxChebRadius()`（前者镜像既有 `maxY()`，后者与之同族）
- `RitualBuilderPlacement` — 复用既有 `sliceFor(pattern, tier)` 取最高阶切片
- `RitualBuilderScreen` — 左列列表下方新增两行 + tooltip 命中区
- lang 键新增 4 个（`zh_cn` / `en_us`）
- **纯客户端展示**：全部数据已在客户端（`RitualBuilderScreen` 直接读 `RitualPatternLoader.all()`），**不需要新网络包、不需要 `RitualBehavior` 钩子**
- 顺带收益：`LevelSlice` 上原本零调用的 `maxY()` 与新增的 `minY()`/`maxChebRadius()` 构成同一族几何查询，未来任何"结构尺寸"类需求可直接复用
- 不改任何放置/匹配/构建逻辑，**不改 `ritual-builder-placement` 的冲突判定**——本变更只做信息暴露，不做自动检测
