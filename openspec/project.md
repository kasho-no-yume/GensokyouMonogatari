# 幻想乡物语 (Gensokyou) — 项目需求总纲

> 本文档是项目的需求基准（requirement baseline）。所有变更提案（proposal）SHALL 引用本文档作为需求来源；
> 需求变更时先改本文档，再开对应变更。
> 平台基线：Minecraft 1.21.1 · NeoForge · Java 21。

## 1. 定位

东方 Project 题材的**科技魔法兼顾 RPG mod**。核心卖点为 **RPG 式 BOSS 战**；
仪式（多方块机器）系统承担科技侧基建（发电、储能、加工、自动化），
符卡系统承担魔法侧战斗表达。整体体验画像：

- 玩家在原版生存中逐步接触灵力与妖精，获得引导书入门
- 通过炼体提升永久素质，学习符卡装入技能槽，以灵力驱动战斗技能
- 召唤或探索挑战角色 BOSS（低阶野外召唤 / 高阶幻想乡寝宫），获取招牌武器、符卡、材料与货币
- 建设仪式机器改善生存体验（产灵力、矿物增产、道具生产）
- 引爆结界进入幻想乡维度（永久开关），挑战高阶内容

## 2. 核心循环

```
        ┌──────────── 反哺 ────────────┐
        ▼                              │
  提升强度 ──► 挑战更强 BOSS ──► 高级奖励 ─┘
     │                              │
     │ 炼体(素质↑)       招牌武器/符卡道具/材料/円
     │                              ▼
     ├─ 符卡道具：即拾即用（一次性消耗品）
     └─ 已学符卡 ◄── 仅可通过幻想乡任务习得

  支线循环（经济）：发电机仪式 ──灵力──► 淬炼仪式 ──素质↑──► 更多灵力上限
```

## 3. 系统需求

### 3.1 灵力经济

- 玩家 SHALL 自身产生灵力，产量与储量受自身体质限制
- 外部储能容器（**电容**类方块/多方块）为必做件：大型仪式所需灵力远超玩家自持量
- 电容中灵力 SHALL 可喂给仪式，也可喂给玩家
- 远距离传输灵力 SHALL 依赖专门的传输仪式/设施（不做免费无线传输）
- 死亡惩罚：当前灵力清零；最大灵力等永久属性不变
- 心智模型参照 Botania mana

### 3.2 成长（炼体）

- 炼体提升**永久属性**：最大灵力值、恢复速度等
- 实现形态：**淬炼仪式**——进入多方块结构，消耗大量灵力 **+ 稀有道具** 后提升上限
  （不是纯灌灵力；稀有材料是主要门槛）
- 炼体等级同时是学习/使用高阶符卡的素质门槛
- **正式实现＝八百万神恩之仪**（`kami_no_megumi_circle`，1~5 阶，change `add-yaoyorozu-grace`）：
  玩家阶级 0~5 由 `temperLevel` 承载；凡人（0 阶）零灵力、零符卡槽、无飞行——
  弹幕武器/符卡施放/结界引爆全部 gate 在首次进阶之后；每阶属性按指数表 +
  全键随机 roll（可洗练回洗，预览制当场采纳）；进阶成功永久解锁创造飞行
  （当前不耗灵——实测按阶级扣灵会使 BOSS 战几乎无法正常走位与还手，故成本已砍掉；惯性可关）
- ⚠️ 命名区分：八百万神恩＝玩家自身炼体进阶；**降神变身**（phase-d
  `kamigakari-transformation`，"八百万神明内容矩阵"）＝借神明力量的临时变身道具，
  两套系统互不隶属，文档与 spec 不得混用

### 3.3 符卡与技能槽

两条获取路径，定位互补：

| | 道具符卡 | 已学符卡 |
|---|---|---|
| 形态 | 一次性消耗品 | 装入技能槽的常驻技能 |
| 使用门槛 | 无（与素质无关） | 需炼体达标 |
| 消耗 | 卡片本身 | 灵力 |
| 定位 | 低练度提前体验 / 应急爆发 | 可持续的核心战斗手段 |

- **学习途径唯一**：已学符卡仅能通过幻想乡内的任务（委托）习得；
  掉落的符卡道具不可转化为已学状态。技能槽系统因此是进入幻想乡之后的内容
- 技能槽位 **0~5 个＝超人类阶级数**（抽象槽：任一已学卡可配装；
  已学数量上限同样＝阶级，实现见 change `add-yaoyorozu-grace`）
- 战斗释放依赖 **HUD + 键位系统**（客户端 UI，本项目新增能力域）
- 仅做**预设符卡**；玩家自定义符卡明确后置（耦合低）
- 符卡命名沿用东方格式（如「水符○○」）

### 3.4 仪式系统（科技侧）

- 全部为**多方块结构**，法阵元素参与
- 单人参与为前提（无多人协作仪式），但所有状态 MUST 在 dedicated server 下正确工作
- 仪式类型清单：
  - **产灵力仪式**（发电机）
  - **电容**（储能容器）
  - **传输仪式**
  - **分解 / 聚合仪式**（功能性：矿物增产、材料加工、强力道具生产）
  - **淬炼仪式**（炼体）
  - **召唤仪式**（召唤低阶 BOSS）
  - **降神仪式**：将神灵的部分力量封入容器，产出**一次性变身道具**；
    使用后 T 秒内临时改写玩家大部分属性（生命/移速/攻击/灵力恢复）并**临时替换技能槽**为该神明 kit
  - **结界引爆大仪式**：一次性、全局永久的幻想乡入口开关

### 3.5 BOSS 与寝宫

- 分层设计：

| | 低阶 BOSS | 高阶 BOSS |
|---|---|---|
| 出现方式 | 召唤仪式（主世界即可） | 幻想乡寝宫内 |
| 场地 | 野外即战场，无寝宫 | 专属寝宫（结构内部可先占位） |
| AI 形态 | 野外战斗 AI | 寝宫战斗 AI（场地机制可用） |

- 野外生态：主世界随机刷新**小妖精**（普通敌对怪）；**大妖精**为百鬼夜行召唤的低阶 BOSS，不自然刷新
- mob 设计全局规则见 `docs/mob-design-guidelines.md`（东方怪非弹幕抗性 90%、弹幕为核心的战斗心智模型等）
- 掉落物体系：招牌武器（如拉维坦剑）、符卡（道具形态）、合成材料（ppoint/bpoint 等，是材料不是货币）、円（货币）
- 已确认角色：芙兰朵露（旧版数值基线：500 血 / 60 攻 / 护甲 20，最终数值以**代码常量**为准）
- README 中"黑幕 BOSS"设想保留观察，定位待定

### 3.6 世界：幻想乡与商人

- 幻想乡维度由**结界引爆大仪式**解锁，全局永久开关
- 地形生成基本沿用主世界风格；寝宫结构本体先做占位外壳，内部细节留空
- 主线剧情内容暂缓
- 商业系统：
  - 主世界：自定义商人实体（行为参照流浪商人）
  - 幻想乡内：随处可与可交易角色交易
- **委托任务（简化版）为必做项**：它是已学符卡的唯一习得载体；
  完整主线剧情脚本仍后置
- 货币：**円**

### 3.7 入口体验

- 不开局赠送引导书
- 引导链：击败小妖精收集 **9 张记忆残页** → 合成**引导书** → 进入本 mod 内容
  （大妖精作为第一位召唤 BOSS，不再是野外随机遭遇/引导书掉落源）
- 首批可玩点必须低门槛：当前以弹幕武器/仪式为第一小时入口；
  道具符卡「无素质要求」的低门槛入口待符卡系统完善后兑现（该系统当前为半成品，暂缓）

## 4. 全局规则

- 死亡：当前灵力归零；永久属性保留（防跑尸式惩罚）
- 多人：无协作仪式；一切玩家绑定状态（灵力、已学卡、炼体等级、变身态）按 per-player 存储并在服务器重启/存档重载后保持
- 平衡哲学：道具卡=付费跳级，学会卡=正途
- **配置面三分法（`config-surface`，详见 `docs/config-guidelines.md`）**：数值按「把该键翻倍是否改变同一场战斗的结果」归三类——
  **战力数值**（伤害/血量/属性/怪物预算/弹幕武器与符卡强度与消耗/掉落概率）SHALL 为**代码常量**，MUST NOT 配置化；
  **非战力经济与世界节奏**（仪式产能/缓存/受灵/消耗/产出、仓储、工具成本、刷新倍率）SHALL 走 **SERVER 配置**；
  **表现偏好**（画质/HUD/镜头）SHALL 走 **CLIENT 配置**。
  **新增可调项 MUST 先经用户确认或由用户主动提出**，实现者 MUST NOT 自行往配置里加数值（不设键数上限）
- 素材规则：mod 素材 MUST 为原版生存不可获得之物（不另立与原版重复的物品）；**凡材可自由作配方配料**，
  入口层（0 阶仪式石/核心）允许以凡材为主、仅含少量 mod 钥匙；mod 独有品与阶级物品 MUST 含 mod 料
- 幻想乡独有资源（矿产/土产/木材/海产/植物）SHALL 由对应资源仪式经信物带（指导书/隙间碎片）产出，
  产量随结构阶 `×4^阶` 放大，即「前期锁死、后期洪流」
- 数值设计规范：怪物见 `docs/mob-design-guidelines.md`；弹幕武器/核/词条见 `docs/weapon-design-guidelines.md`
- 数值测试台（开发设施，命令权限 2）：`docs/balance-test-harness.md`（`/gs_test`）
- 语言：中文优先（zh_cn 为第一语言文件），en_us 同步维护

## 5. 资产规范（占位期）

项目当前**没有任何自制美术资源**。在正式美术到位前，全部视觉资产 SHALL 使用原版资源占位，
且占位方案 MUST 保证未来替换时不修改任何代码与引用。

### 5.1 占位来源映射

| 资产类型 | 占位来源 | 适用范围 |
|---|---|---|
| 物品图标（通用） | 海洋之心（heart_of_the_sea）贴图 | 默认物品 |
| 武器类图标 | 三叉戟（trident）贴图 | 一切武器物品 |
| 盔甲类图标 | 下界合金胸甲（netherite_chestplate）贴图 | 一切盔甲物品 |
| 符卡类图标 | 旗帜图案（flower_banner_pattern）贴图 | 一切符卡道具 |
| 实体模型 | 史蒂夫人形模型（humanoid） | 一切生物/Boss |
| 实体皮肤 | 艾利克斯（Alex）皮肤；弹幕/阴阳玉用旧仓库 lightorb.png | 一切生物/Boss 的皮肤层与弹幕视觉 |
| 方块模型 | 标准立方体（含带方块实体的方块） | 一切方块 |
| 方块贴图 | 钻石块（diamond_block）贴图 | 方块全部面 |

### 5.2 替换零成本原则

- **禁止直接引用 `minecraft:` 命名空间的贴图**：所有模型 JSON 与渲染器只准指向
  `gensokyou:` 命名空间下的自有路径
- 自有路径自第一天起即按**最终命名**创建（如 `textures/item/lightorb.png`），
  文件内容暂存原版像素拷贝；正式美术到位后仅覆盖文件内容，零引用改动
- 实体皮肤路径 SHALL 收敛为单一常量/注册点（每实体一个 `TEXTURE_LOCATION`），
  不允许路径字符串散落在渲染逻辑中
- 方块一律走自有 blockstate + model JSON（含多方块仪式组件），不得以
  `parent: minecraft:block/...` 方式借用原版模型间接引用原版贴图
- 语言键（lang key）同步按最终命名建立，占位期文案可写"[占位] 名称"以便游戏内肉眼识别未完成项

### 5.3 命名与分类

- 目录按资产类型分类：`textures/{item,block,entity}/`、`models/{item,block}/`、`blockstates/`
- 文件名与 registry name 一一对应；**禁止** `_temp`/`_placeholder` 之类的临时后缀——
  占位体现在文件内容，不体现在名字
- 维护**占位资产清单**（阶段 A 建立，如 `docs/asset-placeholder-list.md`）：
  记录每个占位文件的来源与其替换状态，正式资产替换一项销项一项；
  清单清零即代表占位期结束

### 5.4 品阶配色环（全模组强制）

所有**品阶化资产**（弹幕核、武器等级核、仪式核/基座变体及后续同类资产）的主体色 SHALL
遵循统一品阶配色环，每档提供 主色/高光/暗部 三阶供像素分层：

| 品阶 | 色名 | 主色 | 高光 | 暗部 |
|---|---|---|---|---|
| 0 | 灰 | #9E9E9E | #CFCFCF | #616161 |
| 1 | 绿 | #4CAF50 | #A5D6A7 | #2E7D32 |
| 2 | 蓝 | #2196F3 | #90CAF9 | #1565C0 |
| 3 | 金 | #FFC107 | #FFE082 | #B8860B |
| 4 | 红 | #F44336 | #FFAB91 | #B71C1C |
| 5 | 紫 | #9C27B0 | #CE93D8 | #6A1B9A |

- **弹幕核图标约定**：弹幕核（BulletCoreItem）物品图标在左下角带约 3×3 像素的
  弹幕类型微图标；**每种弹幕类型一种微图标**（玉/散珠/刀/符/短管/长管/锥）；
  同类型核跨品阶外形一致仅配色不同，不同类型核外形差异明显。
- **动态色彩与品阶色环共存**：带动态着色的资产（如球形核心）SHALL 以 `TierPalette` 的品阶色
  为基准，动态化 ONLY 允许在该色的**窄区间（±30°）**内摆动，MUST NOT 做全色相循环——
  一旦颜色不再是品阶色，阶 1/2/3 就无法辨认，品阶配色环即失效。
  色相的**唯一**来源仍是 `TierPalette`，动态化 MUST NOT 另写一份色值。
- **未装配形态例外（千机核心）**：**未装配形态（弹核槽为空的千机核心本体）没有品阶归属**
  ——品阶随装入的核而来，核心自身无阶可循。故该形态 SHALL NOT 受品阶配色环约束，
  MUST 呈现**全光谱流光**（沉睡态）；一旦装入弹核，MUST **立即**回到该核品阶色的
  窄区间（±30°）。此例外 ONLY 适用于**无品阶归属**的形态，MUST NOT 被援引到任何
  **已装核**的资产上（那些仍 MUST 走品阶色，否则阶位不可辨）。
- **动态着色的资产 MUST 做"加法预算"**：多层加法混合叠同一饱和色时，主通道必然截顶 →
  色相漂移 + 饱和度塌陷（读作"发白"）。加法层贡献之和 MUST 留出余量，使
  **本体峰值 + 加法总和 < 255**，从结构上排除截顶。色相与亮度的调制 MUST 在 **HSV 空间**做，
  MUST NOT 用 RGB 乘法后逐通道截顶。详见 `weapon-gui-visual` 的「色彩合成的溢出与色相约束」。
- **品阶方块族命名约定**（仪式石）：每品阶独立注册方块，
  注册名与贴图统一 `<registry_name>_0` … `<registry_name>_5`（含分面 `_top/_bottom_N`），
  无无后缀基础方块/基础贴图；方块物品名以品阶色染色（0 级不染）。
- **单方块品阶变色**（仪式核心、祭品台）：保持单一注册方块，`tier`（0-5）BlockState 属性
  随仪式等级（结构内仪式石最高品阶）切换 `_0.._5` 变体模型（祭品台保留六套分面变体贴图
  `_top_N/_bottom_N/_N`）；基础贴图（无后缀）保留且与 `_0` 灰版同图；
  方块物品名不染品阶色（放置恒 0 阶灰，成型后由核心重扫统一写色）。
- **程序化滤镜染色**：需按品阶/主题变色的物品（增幅核、符卡）采用
  「灰度底图 + 运行期 tint」——assets 只保留未染色底图（染层高光近白、阴影近黑），
  染/不染区域以模型图层拆分表达（层号即 tintindex），染色结果不落盘为贴图。
- **品阶色单一色源**：`TierPalette`（Java）为名字染色 / 物品 tint / UI 强调色的唯一取色处，
  色值即本表主色列。
- **已消除**：弹幕核贴图曾按 config 默认 `requiredTier` 定色、运行期改 config 不跟色。三分法落地后 `requiredTier` 为**代码常量**，该局限不再存在。

### 5.5 咒符条血条贴图规格（`gui/boss_bar/`）

咒符条 = **一圈悬空的细符纸边框**，中间是一条开放的**血槽窗**。
纸只出现在窗口四周（上沿 2 + 内唇 2 + 槽 8 + 内唇 2 + 下沿 2 = 16 逻辑行），
上下各留 2 行透明缝，读作「纸框」，不是「实心纸卡片」。

边框贴图是 **728 × 144 texel** —— 逻辑尺寸 **182 × 36**（血条本体 24 + 上方 12 行装饰带），
按 1920×1080 / guiScale=4 下的**物理像素**产出（每逻辑像素 4×4 texel）。美术由扩散模型绘制，
结构由 `tools/boss_bar_art.py` 收口时钉死。九宫格仍然保留，但**只在玩家改 config 宽度时
才起作用**：182 逻辑宽时 `728 − 2×240 = 248 texel`，恰好是 62 逻辑像素的 4 倍，
**全图 1 texel = 1 物理像素，零缩放**。

> **为什么破例不用 1 texel = 1 逻辑像素**：182×24 只有 4368 texel，端头装饰柱仅 22×20
> 逻辑像素，扩散模型画不出可读细节。血条是 HUD 上最大的单件美术，
> 按物理像素产出才体现模型优势；代价是 guiScale < 4 时会被降采样（1080p 默认即 4）。
> 这是 `gui-art-system` 分辨率宪法里**唯一**的例外。

#### 资源位置与尺寸

| 资源 | 路径（相对 `assets/gensokyou/`） | 尺寸（texel） | 说明 |
|---|---|---|---|
| 边框 × 5 | `textures/gui/boss_bar/frame_1.png` … `frame_5.png` | **728 × 144** | 五阶五套装饰主题（竹/水纹/金箔/彼岸花/境界裂痕），AI 出图 + 程序收口 |

#### 纵向分区（36 逻辑行 / 144 texel）

```
 逻辑     texel    内容
 0..13    0..55    上方装饰带（AI 自由创作）
14..15   56..63    透明缝（纸框悬空，不与装饰带粘连）
16..17   64..71    符纸上沿（细边 2 行）
18..19   72..79    内框上唇（AI 画，收口不重绘）
20..27   80..111   血槽 = 血条条身区        ← ★ 5 阶共用同一行范围
28..29  112..119   内框下唇（AI 画，收口不重绘）
30..31  120..127   符纸下沿（细边 2 行）
32..35  128..143   透明（留白）
```

#### 横向分区（182 逻辑列 / 728 texel）

```
 逻辑      texel      内容
 0..21     0..87      左端装饰（藤蔓 / 花簇，AI 画）
20..21    80..87      血槽左竖边（结构层）
22..159   88..639     血槽 = 条身填色区（= 182 − 2×22）
160..161 640..647     血槽右竖边
160..181 640..727     右端装饰（AI 画）
```

| 约束 | 原因 |
|---|---|
| **血槽行范围（逻辑 20..27 / texel 80..111）5 阶 MUST 完全一致** | 条身高度若随阶变化，就成了阶的函数，于是多血条堆叠预算、`screenHeight/3` 截断判定全要跟着分叉。 |
| **血槽内缩（22 逻辑）5 阶 MUST 完全一致** | 内缩若随阶变，同一血量的填充长度会随阶变化 —— 那是读数错误，不是装饰。 |
| 符纸 MUST 是**细边框**，MUST NOT 是实心纸卡片 | 实心纸面即使挖了槽，屏上仍读作「卡片上贴了一根色条」；细框 + 悬空缝才读作镂空。 |
| 血槽条身区 MUST **全透明** | 血条自己填色；AI 画的纸面若盖住这里，读数就没了。 |
| **边框颜色不参与运行期染色** | 五阶是五套独立主题，颜色画死在像素里；色相来源仍是 `TierPalette`，改色时图与色板一起改。 |
| 边框在条身**之后**绘制 | 纸框与藤蔓悬在条身外面，压在上面才不会被填充盖掉。 |
| **收口不重绘血槽边线** | 用户要求先看 AI 原画；只把框线一圈 alpha 钉成不透明、按坐标挖槽。 |
| 窗口位置有比例偏差时 MUST **3×3 网格重映射** | 横向「左端/窗口/右端」+ 纵向「上框/窗口/下框」；只做纵向会让填充条比纸框窗口短一截。 |
| 装饰层 MUST **全白抠除**（含花缝里不连通的白） | 只抠边缘连通的白会留下白色底板，读作「花贴在白卡上」。 |
| 纸框 MUST **固定矩形**（窗口以外补纸色） | AI 每阶画的框高不一致，实机读作「有的阶短一截」；游戏 sprite 要稳定外框。 |
| 凹轨色 MUST = 深墨 + ~25% 阶色 | 纯黑铺满空槽是实机反馈的「血条底像一块黑」。 |
| 目标尺寸用逻辑像素、源区域用 texel | 两者差 4 倍；混用不报错，只会裁切错位。 |
| 贴图尺寸不符 MUST 视同缺失 | 文件在但尺寸不对不会报错、只会画成一团；`framePresent()` 读 PNG 尺寸后回落降级画法。 |

#### 五阶差异 = 装饰主题 + 密度递进

每一阶是一套**独立的装饰意象**，主题色与 `TierPalette` 同色相（不再是统一朱红）：

| 阶 | 主题色 | 装饰意象（AI 按草稿自由发挥） |
|---|---|---|
| 1 | 绿 `#4CAF50` | 竹节 / 草叶 / 风痕，稀疏 |
| 2 | 蓝 `#2196F3` | 水纹 / 雨脚 / 流动水线 |
| 3 | 金 `#FFC107` | 金箔碎光 / 金色流光 / 细雷纹，**不要铜钱** |
| 4 | 红 `#F44336` | 彼岸花（红花石蒜）+ 赤色花丝（保留） |
| 5 | 紫 `#9C27B0` | 境界裂痕 / 蝶影 / 星点，最繁密 |

**整条纸框 + 上方装饰带都属于设计区**，MUST NOT 只装饰左右两端。
装饰密度 MUST 随阶递增（1 阶最素、5 阶最满）。`tools/boss_bar_art.py` 的 `CANOPY` /
`_end_vine` 是草稿的递进骨架，但扩散模型**不会精确执行「几枝/几朵」**——
验收标准是「主题对、越阶越满、肉眼可分辨」，MUST NOT 按枝数点验。

#### 产线（一次生成五条）

```
tools/boss_bar_art.py --draft --all          # 竖排五条线稿 1456×1632（每条 182×36 的 8 倍）
tools/genpic_client.py --send ...            # Qwen-Image-2.1（Runpod 端点；本地 ComfyUI 可选）
tools/boss_bar_art.py --compose --all --ai build/bossbar/raw_all.png
                                             # 行投影切五条 → 找边线 → 分段纵向映射 → 挖血槽
tools/preview_boss_bar.py                    # 五阶 + 多宽度本地目检（按 1080p 物理像素 1:1）
```

草稿每条 1456×288 = 最终 texel 的 **2 倍超采样**，条间留 48px 纯白；
AI 出图后按**行投影**切成 5 条（白间隔是天然切缝）。

收口脚本做四件事：以**血槽空窗为锚**定位窗口；做 **3×3 网格重映射**
（横向左端/窗口/右端、纵向上框/窗口/下框），把窗口精确拉到 88..639 × 80..111；
上方装饰带单独**全白抠除**（含花缝里的白）；把血槽挖透明。
**不重绘边线**（保留 AI 原画），只把框线一圈 alpha 钉成不透明。
纸框窗口以外补纸色、alpha 固定为矩形（五阶框高一致）；装饰层的白全部抠透明。

**手动扣槽**：`--compose` 会把自动检测到的 `window`/`frame`（原图绝对像素）写进
`build/bossbar/windows_auto.json`；每阶框长/框高不一致时，改该 JSON 后用
`--windows-file` 复用。`--debug-window` 输出标注图（红=窗口、蓝=纸框）。
无论原图窗口多宽，3×3 映射都会把它贴到固定的 88..639 × 80..111，屏幕上的血条长度不随 AI 构图变化。
切不出 5 条时按内容总高度均分兜底并告警（构图仍需人工目检）。

> **注**：阶 3（金）与阶 4（红）当前**没有任何 BOSS 使用**——现存 6 只东方 BOSS 里
> 4 只是百鬼夜行召唤的低阶杂兵，1 只召不出来。见 `boss-tier` capability 的
> 「阶级分配表当前为占位」。美术按上表出全套即可，不必等阶级表定稿。

#### 条身：凹轨 / 残影 / 灵力 / 前缘（v4）

血量条本体 MUST 读作「凹槽里的灵力」，MUST NOT 是纯色进度条。

- `segment.png`（64×32 灰度）是**三层共用**的纵向剖面：上缘内阴影 → 上三分之一亮芯 →
  中段平 → 下缘压暗。运行期分别乘轨道色 / 残影色 / 品阶色。
- 凹轨色 = `blend(#2A1A1C, TierPalette.rgb(tier), 0.25)`：绿阶暗橄榄、蓝阶暗蓝灰、
  金阶暗金褐、红阶暗红、紫阶暗紫。MUST NOT 直接用纯黑铺空槽。
- 条身贴图最大亮度 MUST < 1.0（当前 0.86）——乘法染色只能压暗，留出的一档给前缘。
- `segment_edge.png`（8×32，近白 + alpha 月牙）贴在填充右端，乘**提亮 1.25x 的阶色**，
  读作液面收口。前缘宽度 MUST ≤ 当前填充宽度。
- 绘制尺寸：源 64×32 texel 铺到「当前血量宽度 × 8 逻辑行」。纵向 32 texel 对 32
  物理像素（guiScale=4）**1:1**；横向 MUST 均匀（每行同色）。
- 落盘的灰度值 MUST NOT 预乘任何色相——一旦烘焙了颜色，tint 就会把它染脏。

#### 结构色（不进贴图）

暗轨底与掉血残影是**结构色**而非阶色，继续用**代码常量**色，**不在贴图规格内**：
`TALISMAN_BAR_COLOR_TRACK`（`#2A1A1C` 暗轨底）、`TALISMAN_BAR_COLOR_GHOST`（`#F5EFE0` 米白残影）。
燕尾撕边与右下朱印只在**降级画法**（贴图缺失）保留，同样不在贴图规格内。

#### 替换流程

1. 按本节覆盖 7 个 PNG。**MUST NOT 改动** Java 侧常量：`TEXEL_SCALE`(4)、
   `FRAME_TEX_W/H`(728/144)、`FRAME_CAP_TEX`(240)、`FRAME_MID_TEX`(248)、
   `FRAME_CAP`(60 逻辑)、`TOP_BAND`(12)、`WIN_ROW_TOP/BOTTOM_TEX`(80/111)、
   `SEG_TEX_W/H`(64/32)、`EDGE_TEX_W/H`(8/32)。
2. 可**逐张**替换：加载期 `TouhouBossBarRenderer#framePresent` 探测某阶 `frame_N.png`
   是否在 classpath 上，缺哪张那一阶就回落到纯 `fill()` 老画法（不崩、不空、不重叠），
   其余阶照常用新图。
3. 颜色若要改，走**代码常量**或 `TierPalette`，MUST NOT 在贴图里硬编码色相。

#### 已知待改进

1. 前缘高光是「提亮色 × 近白贴图」，受乘法染色上限所限，无法做到真正的加法发光
2. 符卡行用品阶色（`TierPalette`），与边框主题同源；同色相时靠暗轨底保持对比
3. 撕边齿数固定 11 铺满 `talismanBarWidth`，宽度大时看着像虚线——齿数该与宽度挂钩
4. 上方装饰带使单条血条的总行高从 30 增到 46 逻辑像素，能同时显示的 BOSS 条数变少
5. guiScale < 4 时 728 texel 会被降采样（分辨率宪法对该件的例外代价，已知接受）
6. AI 单次出五条时，五套主题色可能互相串色；若有偏差，改为逐阶单独请求

### 5.6 樱符 GUI 美术系统（`gui-art-system`）

**GUI 美术的唯一规格在 capability `gui-art-system`**（`openspec/specs/gui-art-system/spec.md`；
变更提案已归档于 `openspec/changes/archive/2026-10-23-sakura-gui-art-system/`）。
本节只列与本仓库全局约定直接相关的三条。

#### 分辨率宪法

所有 GUI 贴图 MUST 按 **1 texel = 1 逻辑像素** 产出并 1:1 绘制。
MUST NOT 产出 2×/4× 落盘后降尺寸 blit 的贴图 —— MC 的 GUI 纹理是 NEAREST 过滤，
2:1 最近邻降采样会丢一半像素并糊掉边缘。

> **唯一例外：BOSS 咒符条血条**（见 §5.5）。它按 1080p 物理像素产出（728×144 = 182×36 ×4），
> 因为 182×24 的 texel 量不够扩散模型画细节；默认 1080p / guiScale=4 下仍是零缩放。

> 1080p 下 MC 的 auto GUI scale = 4。182 逻辑像素宽的血条在屏上占 728 物理像素，
> 1:1 绘制时每 texel 是干净的 4×4 物理像素块。**贴图的 texel 数 = 设计信息量。**

#### 三层分工

| 层 | 内容 | 产出手段 |
|---|---|---|
| 材质装饰层 | 纸纹、花瓣、枝、印、光晕 | AI 扩散生图（只出大形与明暗层级） |
| 结构层 | 卡框、分隔线、槽格、电池槽框、外框 | 程序 / ASCII（坐标锁死） |
| 文字 | — | Java |

AI 出图的**调用方法**（端点、模型、三类调用形态、参数、prompt 纪律、收口流程、成本模型）
与**适用场景判定表** MUST 以 capability `gui-art-system` 为准，MUST NOT 靠口头约定。

#### 底图复用方案

多个面板共用视觉时，MUST **各自烘焙一张整图**，一致性靠「共用材质件 + 共用 prompt
纪律 + 共用收口脚本 + 共用调色板常量」保证。

底图 MUST NOT 用九宫格，也 MUST NOT 用「把烘焙整图拆成零件再平铺/复用」——
两轮零成本装配实验已证明：九宫格要求边条可拉伸（烘焙边框含枝/印，破坏该前提）、
中心平铺必然重复露缝、装饰件从烘焙图抠必然带原纸底残留、「半结构半装饰」的成分
（卡片柔和底色 / 金角括号）拆开后无处可归。

#### 调色板单一色源

樱符调色 MUST 只有一处定义：**Java 侧 `SakuraPalette`**（与烘焙侧
`tools/textures/gui_sakura.py` 的 `PAL` 逐值一致，由 `SakuraPaletteTest` 断言）。
GUI 代码 MUST NOT 在别处硬编码樱粉/金/米白等主题色。

品阶色另走一套：`TierPalette`（见 §5.4），MUST NOT 与装饰色混用。

#### 控件层（本仓库自绘的樱符控件）

| 控件 | 位置 | 要点 |
|---|---|---|
| `SakuraButton` | `client/widget/` | 九宫格贴图 + 居中文字 + 三态 |
| `SakuraSlider` | `client/widget/` | 标签独占一行 + 轨槽带（轨槽 MUST 比字形高） |
| `SakuraSearchField` | `client/widget/` | 继承原版 `EditBox`，外观自绘（凹槽是结构层，归程序） |
| `SakuraSpiritBar` | `client/widget/` | HUD 竖排灵力条，只显示比例，填充用品阶色 |
| `SakuraSkillSlot` | `client/widget/` | HUD 符印格，键位标签在槽外 |

字形实占高度是 **8 行**（unifont `pixelHeight=16 / oversample=2`），
MUST NOT 用 `Font.lineHeight`（=9，行高不是字形高）。

## 8a. Gradle 调用约定（自动化会话）

- **禁止以前台管道直连方式运行 gradlew**（`gradlew ... | Select-String`、`2>&1 | tail` 等一律禁止，会卡死自动化会话管道）。正确姿势固定为"重定向到文件再读取"：
  `cmd /c "gradlew.bat <task> --console=plain > build_out.txt 2>&1"` 完成后 `Get-Content build_out.txt`
- 长任务（`build`/`test`/`runServer`）建议 `Start-Process -NoNewWindow -Wait -PassThru` 包一层同样重定向，或放后台会话轮询输出文件；无论哪种，**不得让 gradle 的 stdout 流入工具调用管道**
- 攒批编译：写完一批代码再构建一次，构建后必须继续后续步骤不得中断
